**场地**：PYNQ-Z2 板子（网线接笔记本、耳机麦插板子上的 3.5mm 口）、笔记本（开 Jupyter 看文件列表）

> 1. 旧版说"440Hz 保留、880Hz 被滤除" —— 那是 9/25 那个 65 抽头单段演示，

>    麦克风 → 核 → 耳机「边录边放」的真·实时已经跑通（`board/scripts/fir_live.py`）：

## 分镜 2 ｜ 算法在做什么（0:20–0:50）

**画面**：`data/figures/multiband_comparison.png`（频谱对照图），
或者设计报告里那张段划分示意图。

**旁白**：
"算法把声音按频率切成四段，分界点是 500 Hz、1000 Hz、2000 Hz。
每段单独做动态范围压缩 —— 也就是小声的地方放大、大声的地方压下来，
最后再合回去。四段之和严格等于原信号延迟 96 个采样，
重建误差是浮点精度级别，所以切分本身不会改变音色。"

**这段不用展示代码**，观众不需要看 C 代码。

## 分镜 4 ｜ 数据（1:50–2:20）

**画面**：`data/results/accel_cpu_vs_fpga.md` 里那张表，或者直接把下面三行做成图。

| | 单采样耗时 | 相对 48 kHz 实时预算（20.83 µs） |
|---|---|---|
| PL 里的加速核（100 MHz，Q1.15 定点） | 理论 0.280 µs；板上实测（每块 8000 点）0.317 µs | 理论 74.4 倍；板上 65.7 倍 |
| 板上的 ARM（float64 + scipy） | 6.199 µs | 3.36 倍 |
| **同芯片加速比** | **19.5 倍**（6.199 / 0.317） | |

**旁白**：
"核跑在 100 MHz 上，每个采样的理论时间是 0.280 微秒，板上实测是 0.317 微秒 ——
48 kHz 的实时预算是 20.83 微秒，所以核有六十几倍的实时余量，
三秒的声音，核实际计算的时间只有 0.057 秒。
Zynq 里那颗 ARM 跑纯软件的对比也在板上量了：同一套算法、同样的乘法次数，
ARM 每采样 6.199 微秒，核 0.317 微秒 —— 同一颗芯片上，**19.5 倍**。"

**这段必须带上的几条**（剪辑的时候打成小字放屏幕上，或者旁白里说）：

- 两边精度不同：CPU 是 float64 双精度，核是 Q1.15 定点 16 位。核做的是更粗的活。
- CPU 那边用的是 scipy 的 C 实现，属于优化过的软件，不是随便写的。
- 核**没有**靠滤波器对称性少算乘法：折叠开关 `FIR_FOLD` 是关着的，
  核和 CPU 两边都是 579 次有效乘法（旧版"核只算 291 次、少做一半"的说法已作废）。
- 核的 0.317 µs 里含每块约 297 µs 的 Python 开销（写寄存器 + cache 维护 + 轮询 DONE），
  占 8000 点长块实测的 12%。纯硬件那一段是 0.280 µs。
- 反过来说也要讲：CPU 那边不是极限，手写 NEON 还能更快，
  所以这 19.5 倍是"相对 scipy 参考实现"，**不能说成"FPGA 比 CPU 快 19.5 倍"**。

**别拿桌面电脑的数字来比**。桌面上是 0.140 µs/采样，和板载 100 MHz 的核（0.28 µs 理论）不是一回事 ——
一个 3 GHz 的 x86 扛 SIMD，一个 100 MHz 的 FPGA，放一起相除没有意义。

**如果时间还够，可以再加一句**（这条其实比数字本身更有信息量）：

"这个核现在每采样只要 28 个时钟周期。它原来要 450 个周期，其中 398 个（88%）
纯粹花在把延迟线整体挪一格这种搬运上，真正算乘法只占 11 个周期。
后来我们只是换了个编译开关（`-DFIR_SHIFT_CHAIN=1`，把值串在标量临时变量上、展成寄存器链），
算法一个字没改，拍数就从 450 掉到 28 —— 改的是一个开关，不是电路。"
