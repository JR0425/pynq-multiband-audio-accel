> 改成"看峰值包络",起振 / 释放时间运行时可改,两个都填 0 时**与 v20 逐位相同**
> ——csim 1000/1000 点相同,上板 90 秒逐位自检 960000/960000。
> 代价是每采样 35 → **49 拍**,整机 WNS 从 +1.283 掉到 **+0.251 ns**(仍收敛、0 失败端点)。

【模型回答】

**第一步:先把"关掉新特性 = 老版本"做成可回归的判据。**
核里新参数排在最末尾(`drc_attack` @0x58、`drc_release` @0x60),
老地址 0x00–0x57 一个不动;两个都写 0 时走原来的 `drc()`。
这样"新 bit 关掉 WDRC"和"老 bit"必须**逐字节相同** —— 这条先过,
后面所有对拍才有一个不会错的基准。

**第二步:包络的定点规则先写死,再写代码。**
包络用 `drc_t`(Q2.22),平滑步进 `step` 用 Q1.15,驱动负责把毫秒换成步进:

    step = round((1 - exp(-1 / (tau * fs))) * 32768)

`diff = |x| - env`,`env += diff * (diff > 0 ? attack : release)`,
衰减量 `gr = max(env - thr, 0) * (1 - ratio)`,再从幅度里减掉。
**不是**把 `|x|` 换成 `env` 代进原式 —— 那样等于把波形乘一个缓变包络,
波形会被压平,听感是失真而不是压缩。

**第三步:写一份独立的整数参考模型,两条路都要过。**
`tools/ref_model_wdrc.py`,纯整数,和核一对一:

| 模式 | 对拍对象 | 结果 |
|---|---|---|
| `legacy`(起停 0/0) | v20 的 csim 输出 | 1000 / 1000 相同,0 处不同 |
| `wdrc`(5 ms / 100 ms) | v21 的 csim 输出 | 1000 / 1000 相同,0 处不同 |

legacy 那条同时证明模型本身的 FIR / 相减 / 增益部分没写错 —— 它和上一版逐字节相同。

**第四步:综合与布局布线。**
每段多一条包络支路,csynth 里 DRC 那个循环 II 从 1 变成 4,每采样 **+14 拍 = 49**。
OOC 布局布线 **+1.270 ns**、0 失败端点;重出 overlay 之后整机 **+0.251 ns**、0 失败端点。
DSP 205/220(93.18%),LUT 6624(12.45%)。

**第五步:上板 A/B 之前先把条件凑对。**
设计成同一趟里只改起停时间,门限 −36 dBFS、压缩比 4:1 全程不动:
0–20 s 0/0 → 20–50 s 5/100 ms → 50–90 s 0/0。
判据是两行 `[调参] 起振`(改动被接住)+ 逐位自检仍然 960000/960000。
实测进核峰值 29639、门限约 519 —— **压缩确实在工作**,不会出现"没压住所以听不出"的假阴性。

**第六步:第二天补界面。**
在 `w5_tuning_ui.ipynb` 里加门限、压缩比、起振、释放四条滑杆和一排起停预设。
压缩比在界面上是 `R:1`,写进核里换算成 `1 - 1/R`;毫秒由驱动换成步进。
四个代码格在板上逐格执行过(`ALL_CELLS_OK`),旋钮文件确认写出了全部键。

【哪里错了】

· **AI 的问题:把"参数能调"当成"用户能调"就交付了。**
前一晚出完 v21、跑完 B/A,我认为这个特性完成了。但那条 A/B 是我写的 shell 脚本,
用户要换一个门限、换一个压缩比,得自己改脚本里的 JSON。**用户第二天问
"现在还不能像 v20 一样落在 jupyter 里面是吗"**,才把这个缺口暴露出来。
判据应该从一开始就是"**用户自己能不能改这个参数**",不是"我能不能改"。

· **AI 的问题:参考模型第一版取整方向错,而且错得很像结构问题。**
`ap_fixed` 的 `AP_TRN` 是向负无穷取整。第一版把"取绝对值 → 压缩 → 还原符号"
写成先 floor 正数再取反,1000 个点里差 3 个,**全部是负值**。正数全对、
负数成片差 1 个 LSB,看现象会往"结构接错了"上想。修法是:
对"取完符号之后"的那个数做 floor(见 `skill/pitfalls/hls_fixed_point_types.md` 第 5 条)。

· **AI 的问题:拍数硬编码,改了一处、漏了六处。**
`board/scripts/fir_chunk_sweep.py` 里写死了 `35`、`0.350 µs` 和"59 倍",
`audio_duplex_probe.py` / `fir_audio_loop.py` / `compare_cpu_fpga.py` 里也有。
核改成 49 拍之后这些数字**全部变成错的,而且不会报错**。
是当天一路手工改过去的。跟着代码走的数字不该抄成常量。

· **AI 的问题:门限 −36 dBFS 是"猜一个能压住的",没有先量进核电平。**
当天赌对了(峰值 29639,门限约 519),但如果麦克风电平低一档,
压缩根本没启动,用户会听到"没有区别",而结论会被写成"WDRC 听不出来"。
**听感实验的前提也要先量**,不能只量实验本身。

· **环境的坑:板上几个脚本是 root 所有。**
`compare_cpu_fpga.py`、`audio_duplex_probe.py`、`fir_audio_loop.py` 属 root,
传上去报 `Permission denied`。要先用 `sudo chown xilinx:xilinx` 改回来,
再传一遍并核对哈希 —— 只传不看哈希,会以为已经更新了。

· **环境的坑:板上 `py_compile` 因为 `__pycache__` 属 root 而失败。**
这不是语法错误,是写缓存目录失败。改用 `ast.parse` 做纯语法检查。

· **环境的坑:板上 `nbconvert` 的模板 `conf.json` 属 root,跑不了。**
最后自己写了一个把 notebook JSON 读进来、逐格 `exec` 的临时 harness,
在板上把 6 个代码格跑完,确认写出的旋钮文件包含全部键。验完即删。

· **环境的坑:`nohup` 启动后台脚本时 SSH 通道读超时。**
脚本其实已经起来了,是后台进程一直占着通道的 stdout。**不能按"命令失败"重跑**,
要用 `pgrep` 确认 —— 重跑会起来第二条 `fir_live.py`,两条抢 MMIO。

【怎么修正】

1. 核里加 `wdrc()`:峰值包络 + `attack`/`release` 两个 Q1.15 步进;
   `atk == rel == 0` 时走原来的 `drc()`,回归判据是"与 v20 csim 输出逐字节相同"。
2. 新寄存器排在签名末尾(`0x58` / `0x60`),老地址不动;驱动 `fir_core.py` 加
   `ms_to_coef()`(毫秒 → 步进,并夹到 `[1, 32767]`,长到 1 秒也不会静默变成 0)。
3. 新增 `tools/ref_model_wdrc.py`:legacy / wdrc 两种模式都对拍 1000 点全同。
4. 重综合、OOC 布局布线、重出 `fir.bit`(md5 `5989720f…`)、上板,
   保留 v20 的 bit 作退路。
5. `w5_tuning_ui.ipynb` 加四条滑杆 + 五档预设,压缩比在界面写 `R:1`、
   驱动里换算成 `1 - 1/R`。
6. 全仓库把"当前出货 35 拍"改成三代口径:**31(v19)/ 35(v20)/ 49(v21)**,
   脚本里的硬编码换成 `CYCLES` 常量。
7. 门限默认值按用户听后的意见改成 **−10 dBFS**(暂定,不是测量结论)。

【沉淀】

1. **"能改"和"用户能改"是两个交付等级。** 新参数只有作者能改,等于没交付
   —— 用户没法自己 A/B,也就没法替这个特性做判断。
2. **回归判据要选"必须逐字节相同"的那条。** "关掉新特性 = 老输出"比任何
   SNR、频谱、听感都硬,而且它先证明了新代码没有碰到老路径。
3. **听感实验的前提要单独量。** 门限是否低于信号峰值、压缩器是否真的在动,
   这两条不成立时,实验得到的"没区别"是假阴性。
4. **逐位对拍先对齐取整方向。** `AP_TRN` 是向负无穷;`int()` / `round()` 在负半轴
   差 1 个 LSB,现象像结构错。
5. **跟着代码变的数字不能硬编码。** 拍数、理论耗时、实时倍率都该从一处常量
   或报告里取,否则改核之后它们静默变错。
6. **后台启动失败和"看起来像失败"要分开。** SSH 读超时 ≠ 脚本没起来;
   用 `pgrep` 确认,别重跑出第二条抢资源的进程。

## 验证边界

- **对拍是 1000 个采样**,不是长时间音频。legacy 和 wdrc 两条都是 1000/1000 全同。
- **上板那趟 90 秒**:8926 块 / 89.26 秒音频 / 90.05 秒墙钟 = **0.99×**,丢 **78 块**。
  丢块是音频 IP 没有 DMA 的已知结构限制,与起停时间无关。
  实时倍率不是 1.00×,报告里不能按 1.00× 写。
- **耳听只有两个切换点、一个人、一次**,用户口头报告"明显有区别"。
  没有做重复实验,也没有第二个人盲听。报告只能写"可闻",不能写灵敏度的具体数值。
- **界面那四条滑杆只做了代码格执行验证**(板上 headless 跑完 6 格、旋钮文件写出全键)。
  **浏览器里的拖动没有验过** —— 手感、回显、跟手程度都还没量。
- **ARM 对照没有重跑**。19.5 倍是 v19(31 拍)那次的实测;v21 的 49 拍按拍数折算
  约 12~13 倍,**是折算不是实测**,引用时必须带这句。
- **整机 WNS 只有 +0.251 ns**(v19 时 +1.283)。时序收敛、0 失败端点,
  但余量已经很薄,后面往 PL 里加任何东西都要重新量。
- **门限默认 −10 dBFS 是用户听后的主观选择**,不是测量结论;
  它意味着只压最响的峰值,几乎不改变说话的整体响度。
