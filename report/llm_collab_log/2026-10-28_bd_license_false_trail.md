# 2026-10-28 BD 卡点结案：把 license 的随机失败当成「换目录就过」

> 结论先写：`create_bd_design` 那 12 轮「随机读不到自己的 tcl」，
> 真因是 **FlexNet license/feature 随机加载失败**，而且它在 **stderr** 里，
> 我这边只 grep 了 stdout 的 `ERROR`，一整天都被吞掉了。
> 「换一个全新 build 目录就过」只是运气，当时还把它写成了结论。
> 另一半是我们自己的重试壳：`taskkill` 在沙箱里被静默拦掉，
> 前一轮的 vivado 没死，后面每轮都在并发，于是失败率被自己放大了。

【任务】

手上要编的是一颗带 `fir_pl_regs` 的位流：四段增益、门限、比值、起放时间
全部改成运行期寄存器可调，替换掉之前编译期写死的那版。
判据很简单：管子上的 `fir_pl.bit` 能读回 `ID=0x504C0002`、写进去的增益能读回、
斜坡 100 ms 内落零，然后上耳朵听。

【提示词】

「`fir_pl_regs` 这版得编出来：四段增益、门限、比值、起放时间全改成运行期可写，替掉编译期写死那版。
可现在 `create_bd_design` 一直报 `couldn't read file .../rsb/bd.tcl`，连挂十几轮了。
是不是杀软或者 Windows 过滤驱动挡着？要不要重装 Vivado？」

【模型回答】

先给了一串对照实验：报错的那个 rsb 文件在不在（`wc -c` 510 字节，在）、
Vivado 进程自己能不能读（`_tmp/fio_diag.tcl` 里 `open` 五次，5/5 成功）、
空 `create_bd_design` 在全新目录能不能过（能）、完整构建脚本在全新目录能不能过（能）、
同一支脚本在老目录（连挂 12 轮）。
结论写成：**「换目录就过」**，并建议以后看到
`[BD 41-69] couldn't read file .../rsb/...` 第一件事就是换目录名重跑，
不要重装、不要关杀软、不要查驱动。

**这个结论是错的。** 同一天下午做第二次复盘时才发现：真正随机的是 license。

【哪里错了】

**AI 的问题：只 grep stdout，把 license 报错整段吞掉。**
构建壳里是 `... | grep '^ERROR'`，而
`ERROR: [Common 17-217] Failed to load feature 'ipintegrator'`
这一类是写到 stderr 的。所以日志里永远只看到后面那串
`couldn't read file ".../bd.tcl": No error` —— 一个**结果**，
永远看不到**原因**。把 stderr 合流（`2>&1`）之后，第一次挂就能看到 license。

**AI 的问题：把一次巧合当成结论，还写进了文档。**
「换目录过」确实是真的，但它是「重试一次刚好撞上 license 成功」的另一种说法。
我没有做**反向验证**（同一个新目录再连跑五次，看是不是也随机挂），
直接把「别查环境」写成了操作纪律。这在方向上把人带偏：真正的随机源没定位，
下次换个场景还是会挂。

**AI 的问题：先怀疑内核过滤驱动，浪费了半个白天。**
看到「读不到文件」就往杀软 / 过滤驱动上想，列了 `MessageTransfer`（完美世界）、
`gameflt`、`XunYouFilter`、`nnndisfilter` 四个 Running 的驱动，还建议重启 Windows。
可手上已经有反证了：同一个进程手动读那个文件 200 次 0 失败。
报错里出现的是工具内部文件名，不是自己的文件，按这条走就不该往自己的磁盘上怀疑。

**环境的坑：沙箱里 `taskkill` 被静默拦截。**
重试壳每轮先 `taskkill /F /IM vivado.exe` 再 `sleep 3` 再 `rm -rf` 工程目录。
`taskkill` 返回码正常、没有输出，但进程没死。于是第二轮起来时，
第一轮的 vivado 还占着 `build/vivado/audio_pl`，两三个 vivado 同时读写同一个工程目录 ——
「随机」就是这么被放大的。16:30–16:46 连挂 6 轮，全是这个。

**环境的坑：Windows 上被杀进程的文件句柄不会立刻释放。**
就算杀成功了，句柄也要几秒才放。`rm -rf` 碰到忙文件**跳过而且不报错**，
下一轮拿到一个半删的工程：`.cache/project.wpc` 还在、`.xpr` 没了。

【怎么修正】

1. 构建壳改成 stderr 合流，失败时把这一轮所有 `ERROR` / `CRITICAL` 全打出来，
   不再只认 `^ERROR` 一个前缀。
2. `kill_stray` 杀完要**验尸**：`tasklist` 查 `vivado.exe`，还活着就 FATAL 退出，
   绝不进下一轮。
3. 每轮用带轮次和时间戳的全新工程目录（`FIR_PL_BUILD_DIR=.../pl_${i}_${TS}`），
   不跟上一轮的残留抢。
4. 赶时间时走**复用路**：`reuse_project_build.tcl`，`open_project` → `reset synth_1`
   → `launch` → 拷 bit。完全绕开 `create_bd_design`，12 分钟确定性出位流。
5. 文档里把「换目录就过」标成**已作废**，保留排查路径但写清结论被推翻。

【沉淀】

1. **只在 stdout 里 grep ERROR，等于自带一个盲区。** 构建脚本一律 `2>&1`，
   并且失败时打印全部错误行，不要挑前缀。
2. **报错里出现工具内部的文件名（`rsb/.../bd.tcl`、`utils_timing.tcl`），
   先查工具自己，别查自己的磁盘。**
3. **杀进程要验尸。** 返回码为 0 不代表死了；没死就并发，并发就出「随机」。
4. **一个结论如果是「重试就好了」，那它不是结论，是重试。**
   要么找到随机的源头，要么把它变成确定性绕行（复用工程），
   别写成操作纪律。

## 验证边界

- 这一天的数字全部来自 `build/vivado/pl_*_MMDD_HHMMSS/` 里各自的 `run.log`，
  失败轮次已经清掉，只留成功那轮。
