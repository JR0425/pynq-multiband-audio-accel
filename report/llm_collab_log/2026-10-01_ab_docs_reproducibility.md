# A/B 工作包：复现说明、性能口径和报告文档

【任务】
检查项目文档是否还按当前相减式多频段方案描述，并补齐队友复现基线所需的步骤。审查性能数字的来源和测试条件，避免软件、HLS 和板测结果混成同一口径。

【提示词】
「我看 README 还有 65 抽头和每段独立带通的说法，跟现在方案不一样。报告和板卡说明里还有哪些旧描述需要一起找？」
「新队友拿到仓库后要从哪里开始跑 Python 基线？README 里是不是缺依赖安装和输出文件说明？」
「性能表里 Python、HLS 和板上延迟能直接放一起比吗？各自的测试条件怎么写才不会让人误解？」

【模型回答】
AI 协助搜索旧架构描述、检查复现入口和性能数字来源，并按检查结果更新 README、性能记录、报告草稿及提交清单。

【哪里错了】
部分材料仍写 65 抽头、各段独立带通或过期 RTL 计划；快速开始没有完整环境和运行步骤。桌面 Python、HLS 核级和参考 overlay 板测条件不同，缺少平台、格式或测量对象说明时会形成误导性横向比较。

【怎么修正】
补充 Python 依赖和运行说明，更新 README、性能表、报告草稿及提交清单；拆开说明软件、HLS 与板测的测量对象和证据状态。文档编辑由 AI 按排查结果协助完成；性能数据与最终提交版本需项目负责人及队友复核。

【沉淀】
发现架构变更后，沿 README、源代码注释、报告、板卡文档逐层搜索旧术语；复现指南说明依赖、命令和预期输出；性能数据同时标记平台、数据格式、实现和来源。
