# 2026-10-29 值错地方、发错东西：两个「看着对」的 bug

> 结论先写：这一天修的两处都不是算法错，是**量的地方不对**和**发的内容不全**。
> `MPO_PEAK` 量在限幅前、而且只有左耳，所以「限幅计数在涨、峰值纹丝不动」；
> 网页拖一下增益，会把门限 / 比值 / 起放时间 / MPO 全部刷回默认，
> 因为三处入口只发了 `{gain_db}`，后端按 body 整份重建。
> 两处都逃过了自检，因为自检脚本自己也在用同样错误的口径。

【任务】

这一批四个任务：`PEAK_IN` 电平表、抓取缓冲、板上 WAV 音源、网页第三档。
验收要求是「不看耳朵也能判」：读数能对上、参数能读回、限幅确实在动作。

【提示词】

「这一批四件事：`PEAK_IN` 电平表、抓取缓冲、板上 WAV 音源、网页第三档。
验收想做到不看耳朵也能判——读数能对上、参数能读回、限幅确实在动。
另外 `MPO_PEAK`(0x054) 我盯着看了半天：限幅计数一直在涨，它一动不动，是不是限幅器压根没生效？
还有个怪事，网页上拖一下增益，门限、比值那些像被重新上电刷回默认了。」

【模型回答】

按顺序做下来，`PEAK_IN` 加了、`MPO_PEAK` 改了、网页三处入口统一改成整份提交、
模拟 PGA 提到 +35.25 dB 再做数字侧补偿。板上的读数当时是「全绿」。

【哪里错了】

**AI 的问题：`MPO_PEAK` 量在限幅前，而且只取左耳。**
寄存器表 0x054 写的是「限幅后输出峰值」。RTL 里接的是 `aq_l` ——
限幅**前**、而且**只有左耳**的那一路绝对值的最大值。
表现很典型：**限幅计数一直在涨，峰值寄存器却一动不动**（因为计数是在限幅命中时加的，
峰值取的是限幅前的信号，两者根本不在同一点上）。
当时的第一反应是「限幅器没生效」，去查阈值和比值，方向就偏了。
改成取 `pr_l/pr_r`（真正写进输出 FIFO 的那两个采样）取大，并垫一级寄存器拆时序。
取负号那一刻还踩了一次：`{1'b0, pr_l}` 是零扩展，`-8000` 会被当成 `+24768`，
必须先符号扩展到 17 位再取负。

**AI 的问题：加了新表，却让旧的自检继续用旧口径。**
`pl_mpo_tone_probe.py` 一开始往 `fir_pl_regs + 0x04` 写 CTRL ——
`fir_pl_regs` 里根本没有 CTRL，那是个死地址，写进去不报错也不生效。
CTRL 在 `gpio_ctrl @ 0x43C00000` 的 bit0..bit8。
死地址写不进去不会有任何提示，探针会一直「什么也没发生」。

**AI 的问题：网页三处入口只发了增益。**
后端的 `sanitize_tune` 是**按 body 整份重建** tune 的：
`{gain_db: [...]}` 进去，门限 / 比值 / 起放 / MPO 全部变成默认值。
`sendGain()`、`hearApply()`、双耳开关三处都只发了 `{gain_db}`。
表现是「拖一下增益，压缩器像重新上电了一样」。三处统一改成发完整的 `compBody()`。
自检补了 `--contract`：让无头浏览器真的拖一次滑杆，
检查发出去的 tune 是不是整份（会临时改板上的调音，跑完写回原值）。
这条以前没有，所以「接口对」是嘴上说的。

**AI 的问题：把 PGA 的作用范围说大了。**
`0x400E/0x400F` 从 `0xB3`（+21 dB）提到 `0xFF`（+35.25 dB），数字侧 −14.25 dB 补偿，
响度不变。但这一招**只对 ADC 量化噪声有效**：
如果嘶声来自话筒自噪声或室内噪声，它会被模拟增益和数字增益一起放大，
最后听到的底噪一模一样，信噪比不变。这条必须写在前面，
否则会变成「改了没用，是不是没生效」的循环。

**环境的坑：健康卡的字被裁掉。**
「负载 1/5/15」在板上被裁字（`0.41 / 0.20 / 0.15` 超宽）。字号降到 11px、
分隔符从 ` / ` 改成空格才放下。

【怎么修正】

1. `MPO_PEAK` 取 `pr_l/pr_r` 取大，符号扩展先做，再垫一级寄存器。
2. 探针的 CTRL 一律走 `gpio_ctrl @ 0x43C00000`，在探针里写死并把注释留在旁边。
3. 网页三处入口统一发 `compBody()`；
   `webui_accept.py --contract` 加进验收脚本，以后每次改页面都跑。
4. PGA 那条在文档里写明适用边界（只对量化噪声）。
5. `MPO_REL`(0x4C) 只存不生效（限幅是瞬时的），寄存器表标注为预留，
   不再假装它有作用。

【沉淀】

1. **「计数在涨、峰值不动」先怀疑两个量不在同一个点上**，不要先怀疑阈值。
2. **改了一个量的定义，要把所有读它的脚本一起改。** 否则自检会用旧口径给你绿灯。
3. **后端按整份 body 重建参数时，前端任何一个入口发半份都是 bug。**
   验收要么让浏览器真的点一次，要么不发。
4. **往一个不存在的偏移写值不会有任何提示。** 探针的寄存器地址要对着寄存器表写，
   写完读回一次。

## 验证边界

- 限幅读数只对 PL 直连这条链成立，`fir.bit`（HLS 版）走的是另一套寄存器。
- `--contract` 会临时改板上的调音，跑完写回原值；它不是只读检查。
- PGA 提到 +35.25 dB 之后，数字侧补偿是 −14.25 dB，两边不是精确抵消，
  差的那部分在响度上听不出来，但电平表的读数会整体低 14 dB 左右。
