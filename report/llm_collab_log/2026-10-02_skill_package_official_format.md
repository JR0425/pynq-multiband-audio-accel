【任务】

把 `skill/` 从一个**纯 markdown 笔记堆**改成**按官方 Agent Skill 写法组织的包**。

起因不是"想做得好看"：这批笔记已经攒了十几篇，覆盖板子串口、overlay、定点类型、
HLS 仿真、GitHub 网络这些互相独立的方向。攒到十几篇之后出现两个实际问题：

- **不知道该翻哪一篇。** 文件名是按"当初卡在哪"起的，后来遇到的是症状，
  症状和文件名对不上就得一篇篇点开。
- **笔记里的数会过期。** 抽头数、门限、代码页这些值改过好几轮，
  但笔记里没有任何地方记着"这个数是哪天的"。

【提示词】

「技能包按官方 skill 的写法重写一下，看看别人的规范长什么样。」
「顺手查一下这些笔记里有没有推荐了不该推荐的工具。」
「那些数别在每篇里各写一份。」

【模型回答】

AI 的第一版是"每篇加个 YAML 头"就交差。方向对，但漏掉了两件事：
**适用范围**和**修订记录**——而这两件恰好对应上面那两个实际问题。

看官方的 `SKILL.md` 之后（AMD 发布的 `Xilinx/ross-ai-assistant` 包），
发现里面有两样东西**这个仓库不该抄**，也说明为什么。

【哪里错了】

· **AI 的问题：第一版只加了 frontmatter，没写「什么时候别用」。**

  加 frontmatter 是为了让 agent 能按 `description` 匹配到这篇笔记。
  可是笔记类内容和工具类内容不一样：**工具告诉你怎么做，笔记告诉你在什么条件下成立**。

  举个现成的例子：`pynq_direct_ethernet_windows.md` 讲的是"板子和笔记本网线直连、
  没有路由器"的场景。如果哪天环境里有路由器，这一篇的**每一条都不适用**——
  固定 IP、掩码、网关全得反过来配。光写"什么时候用"挡不住这个误用。

  所以每篇都要有**成对的**两块：什么时候用 / 什么时候别用。
  `description` 里也要写症状和说法（"串口输出是 ??????"、"No Devices Found"），
  不能只写主题词——**匹配是靠症状匹配的，不是靠标题匹配的**。

· **AI 的问题：想照抄官方的 `Step 0 … Step N` 工作流骨架。**

  官方的 skill 是**驱动工具产出东西**的，套上步骤是合理的：第几步跑什么命令、
  第几步检查什么产物。

  这个仓库的笔记多数是**记录型**的——记的是"当年为什么错、怎么发现的、量出来是多少"。
  给这种东西套步骤，只会加一层壳，不加任何信息，还掩盖了"这不是一个流程，
  是一个判据"。

  **抄格式要抄它解决的问题，不是抄它的样子。**

· **AI 的问题：想按官方那样"一个 skill 一个目录"。**

  官方的包是一篇一个目录，因为每篇是独立可安装的单元。这里的笔记被
  **有日期的协作日志**和仓库里的脚本交叉引用着（日志里写"见
  `pitfalls/pynq_audio_playback.md`"），一搬目录全部断链，换不来任何东西。

· **AI 的问题：笔记里推荐了一个自己没在这台机器上验证过的工具。**

  `github_network_issues.md` 的"解决方案"里原来有一条：

  > **使用稳定网络**：手机开热点给电脑连接，或使用 Watt Toolkit 开启 GitHub 加速。

  前半句没问题。后半句是错的，而且错在两层：

  1. **这台机器上它根本用不了。** 点开加速页就卡死，进程以管理员权限跑着杀不掉。
  2. **就算不卡，方向也不对。** 它靠改 hosts 工作，而这里封的是 **IP 不是解析**
     —— 改 hosts 改的是域名到地址的映射，地址本身不通的话改映射没有任何用。

  这条被删掉，并在文件末尾加了「不要用的」一段写清原因。
  **一条工具建议写进技能包之前，要问自己在这台机器上真跑通没有。**

· **AI 的问题：把会变的数字在每篇笔记里各写一份。**

  `audio_algorithm_prompt.md` 里原来直接写了抽头数和频段边界。
  这些值改过（从 65 抽头 / 600 Hz 那版改成现在的 193 抽头 / 500、1000、2000 Hz），
  抄在这些提示词里的旧值**会生成和硬件对不上的系数**，而且不报错。

  改法是让提示词里明确写一句"**上面那行的数别照抄**"，并指到唯一定义处
  `src/python/band_design.py`。**会变的值只在唯一定义处写死，别处只写"从哪取"。**

· **环境的坑：官方那套东西，能用的是半套。**

  官方发布的东西分成两半：一半是**写法约定**（`SKILL.md` 的字段和结构），
  另一半是**要装起来的东西**（配套的 server）。这次真正能落地的只有前半套
  —— 写法约定就是纯文本，抄过来就行；后半套在这台机器上装不上。

  这个区分决定了对外的说法：**"按官方格式写"成立，"用了官方的工具链"不成立。**
  两句混着说会让别人以为这里跑过官方的 server。

· **环境的坑：官方包在 GitHub 上，而这台机器的国际带宽约 112 KB/s。**

  整包 clone 会卡很久，而且大部分内容用不上。只取需要的那几篇就够了
  —— 这次要的是写法约定，不是包里的内容。

· **环境的坑：`github.com` 和 `api.github.com` 是两个域名，要分别测。**

  笔记里原来笼统写"GitHub 访问不了"。实测下来经常是一个能通、一个不能通，
  而走 Git Data API 推送用的正是后者。写"不能通"之前先把两个分开测。

【怎么修正】

改动了 **17 个文件，+727 / −53**：`README.md` + `pitfalls/` 下 14 篇 +
`prompts/audio_algorithm_prompt.md` + `templates/hls_testbench_template.md`。

每篇补齐同一套结构：

- **YAML frontmatter**：`name`（连字符短语）、`description`（含触发症状和说法）、
  `license: MIT`、部分加 `compatibility`（写清 PYNQ 版本和系统）、
  `metadata.version` / `updated`
- **`## 什么时候用` / `## 什么时候别用`** 成对出现
- **`## 修订记录`** 表，新增行统一写成
  `| 1.0.1 | 2026-10-02 | 按官方 Agent Skill 的 SKILL.md 写法补 frontmatter 和适用范围 |`

  `github_network_issues.md` 因为内容本身也改了（删 Watt Toolkit、补直连和 API 推送），
  从 1.0.0 跳到 **1.1.0**。

`frontmatter` 里的 `updated` **保持这篇笔记内容最后一次被验证的日期**，
不跟着格式改动走——格式变了不等于内容重新量过。14 篇统一这样，
不是漏改，是有意的。

`README.md` 新增：

- **Format 段**：写清按哪套约定、以及**故意没抄的两样**（工作流骨架、一篇一目录）和理由
- **Index 表**：16 行，`Skill name | Note | Scope`。表和 frontmatter 里的 `name`
  逐条核对过，16 条全部一致。

`audio_algorithm_prompt.md` 除上面那条"数别照抄"之外，还补了 DRC 的真实取值口径：

| 参数 | 真实人声上的压缩量 |
|---|---|
| 出厂默认 0.100 / 0.70 | −1.0 dB |
| **本项目采用 0.030 / 0.50** | **−4.1 dB**（干湿比 1.60 倍） |

并写明阈值和压缩比是**运行期寄存器**（`DRC_THR = 0x30` / `DRC_RATIO = 0x38`），
**改它不用重新综合**。

`hls_testbench_template.md` 只补了 frontmatter、适用范围和修订记录，
**模板骨架本身没动**——模板没问题，缺的是"什么时候别用它"（要改本项目现有测试台时，
真实接口在 `src/hls/fir_tb.cpp`）。

**顺手修掉一个自己的疏漏。** 补完适用范围之后，`pynq_serial_console.md` 里
出现了**两个 `## 什么时候用` 标题**（新的一个 + 旧的没删）。全文扫了一遍，
14 篇里只有这一篇有重复标题，删掉旧的那个。

几条能搬去别的项目的：

- **笔记类内容要写「什么时候别用」。** 只写"什么时候用"，就等于默认它到处都成立。
  适用条件被违反时，内容多半不是"效果差一点"，而是**全是反的**。
- **匹配靠症状，不靠标题。** `description` 里要出现人真正会去搜的那些词
  （报错原文、界面上的英文单词、看到的怪现象）。
- **抄格式要抄它解决的问题。** 官方 skeleton 和一篇一目录都是解他们自己的问题的，
  搬过来只会加壳。
- **会变的值只在唯一定义处写死。** 别处一律写"从哪取"，旧数字抄过去不报错，
  只是悄悄地错。
- **写进技能包的工具建议，要真在这台机器上跑过。** 查得到 ≠ 能用。
- **分清"按官方格式写"和"用了官方工具链"。** 前者只要抄约定，
  后者要求对方的东西能装、能跑、能连。两句混着说，别人会高估这里的复现条件。
