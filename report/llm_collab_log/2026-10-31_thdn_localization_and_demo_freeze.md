# 2026-10-31 失真定位到减法式压缩的零交叉死区 + 演示参数冻结

> 结论先写：压缩失真不是定点量化、也不是包络纹波，是 `src/rtl/fir_drc4.v` 的
> `y = sign(a)·max(0, |a| − gr)` 在零交叉处挖出宽约 2G 的死区 —— 板上 1 kHz 单音
> 六组对照：不压 0.07%（= 输入本底）、演示默认 9.13%、深压 37.69%，谐波结构用
> A/G 死区模型复现到 0.1 dB。播放循环里的"台阶"定位在**增益块之前**，
> 抓取脚本自己还造过一批假台阶。演示默认参数当天冻结
> （22 dB / −20 dBFS / ratio 0.7 / 5 ms / 100 ms），T9 直连 600 秒长跑 PASS
> （`data/results/soak_pl_600_20261029_1031.md`）。

【任务】

1. 压缩一重，耳机里就能听出毛刺。定位失真来源：Q1.15 定点量化、包络纹波，
   还是压缩算法本身？要定位到代码行，并给一个能对上实测的模型。
2. 循环播放 250 Hz 时，抓取缓冲的波形偶尔中间有一道台阶，位置随机，一起查。
3. 演示默认参数今天冻结；600 秒长跑收尾。

【提示词】

「1.压缩一重，耳机里就能听出毛刺。帮我定位失真来源，是包络纹波，
还是压缩算法本身？或者你有别的见解。要定位到代码行。
2.另外循环播放 250 Hz 时，抓取缓冲读出来的波形偶尔中间有一道台阶，位置随机，
不在循环接缝上，一起查一下。
3.演示默认参数今天要冻结，600 秒长跑收个尾。」

【模型回答】

**失真：六组对照定位机制**（`data/results/thdn_localization_20261031.md`，
位流 628b75b3…，`tone1001_lo.wav` 1 kHz、1024 点 FFT）：

| # | 压缩器 | 限幅器 | THD+N |
|---|---|---|---|
| 1 | 关 | 不动作 | 0.07% |
| 2 | 关（THR 抬到 0 dBFS） | 动作 | 7.72% |
| 3 | +30 dB / −10 dBFS / k 0.5 | 动作 | 9.05% |
| 4 | +30 dB / −20 dBFS / k 0.7 | 动作 | 16.29% |
| 5 | +24 dB / −40 dBFS / k 0.5 | 不动作 | 37.69% |
| 6 | 同 5，atk 50 / rel 300 ms | 不动作 | 33.94% |

机制：`fir_drc4.v` 的 `y = sign(a)·max(0, |a| − gr)` 在零交叉处留下宽约 2G 的死区，
折点产生奇次谐波。离线复算 A=15849、G=6352 得 33.9% / 三次 −12.4 dBc，
与第 6 组实测同量级；演示默认（A=12589、G=1492）把 3/5/7/9 次谐波
−24.7/−29.5/−33.0/−35.8 dBc 逐项复现到 0.1 dB。
另做了一个"门限当开关"的实验：段增益降到 14 dB 让包络正好压在门限上，
一压就出谐波、退到门限下就回到 −90 dBc。

**台阶：在增益块之前**（`data/results/pop_steps_20261031.md`）：
同一窗口里 `in`（`fe_din_q`）和 `out`（`mpo_l`）同位置出现台阶；
四段增益压 −20 dB 后 `out` 的台阶 7055 → 717（1/9.84，正好增益比），`in` 不动；
峰值寄存器全程 8000，台阶前后样点都没出正弦包络 —— 是同一段正弦被挪了相位再接起来，
不是叠加的咔哒，也不是算术溢出。干净窗口最大一阶差 262，对理论 257（含量化）。

**长跑：T9**（`data/results/soak_pl_600_20261029_1031.md`）600 秒逐秒采寄存器，
overrun 54944 → 54944 零增长、underrun 全 0、RX FIFO 水位稳定。

【哪里错了】

**我的：说"1024 点抓取窗口无法分辨 1 kHz 的谐波"。**
错。1024 点 @48.828 kHz 的频率分辨率约 47.7 Hz，1 kHz 的 2~10 次谐波间隔远大于此，
完全可分辨——事实上六组对照就是用这个窗口做的。
真问题是窗口时长只有约 21 ms，**不适合做稳态失真统计**；把窗口做到 4096 点（84 ms）
才能在板上直接做实时失真测量。两种说法的结论不同：前者改分辨率（改不动），
后者加窗长（可行）。

**我的：用"冻-读-解冻"连抓台阶，台阶是自己造的。**
`scope_snap=1` 只停写不停播，恢复后中间那段样点根本没进缓冲，
每个周期都在缓冲里留一道相位跳变——连抓 4 s 后每隔约 86 个字一道、
位置固定在缓冲地址上，全是观测动作自己造成的。
`pop_rec.py` 改成不冻结、只取两次读相同的最长连续段。

**AI 的：第一版把谐波主项往偶次上引。**
减法式死区是奇对称折叠，应预期**奇次**为主；实测偶次全部低于 −80 dBc、
奇次从 −10.7 dBc 起才对上模型。引错方向不影响结论但会带偏定位顺序。

**我的：曾想把台阶归因于环形接缝。**
台阶位置在窗口内随机、不落在写指针或接缝上，假设被自己的读数否掉。

【怎么修正】

1. 失真定性为**算法结构特性**：报告只给完整曲线、不报单点 dB 数值；
   结论句固定为"减法式增益在零交叉处挖出死区，属结构特性而非实现缺陷"。
2. 窗口说法改为"窗口太短不适合稳态失真统计"，扩展方向 4096 点。
3. `pop_rec.py` 改为不冻结、两次读相同的最长连续段；"不要用冻结连抓"写进留档。
4. 演示默认冻结 22 / −20 / 0.7 / 5 ms / 100 ms，`/api/tune` 会重置未带字段的
   行为与恢复流程写进 `thdn_localization_20261031.md` 尾部。
5. T9 结束写 `SOAK` 后把播放置 `off`。

【沉淀】

1. **排除要按层来**：先"不压 = 本底"排除定点前端，再"attack/release 放慢 10 倍几乎不变"
   排除包络纹波，剩下的才轮到算法——顺序反了会先去改定点格式，白费一轮综合。
2. **定性判断可以升级成定量模型**：死区宽度 2G 是可算的，A、G 从寄存器参数推出来，
   谐波结构就能逐项对上——"机制清楚"和"模型能复现"是两个可信度等级。
3. **观测工具会污染观测**：冻结式抓取对"连续性"类观测天然有损。
   动手前先问一句：这个动作会不会改变被测的流？
4. **"分辨不了"和"不适合"是两种病**：前者是分辨率不够，后者是时长不够。
   开口下结论前先把数算出来。

## 验证边界

- THD+N 全部为板上实测（位流 628b75b3…，`board/probes/thdn.py`）；
  37.69% 是极端工况、9.13% 是演示默认，两个数不可互换，也不能只引用其一。
- `wdrc_characteristic.md` §C 那张 700 Hz、0.041–45% 的表是**模型域**数据，
  与板上数不同源，不能混挂在同一个频点下。
- 台阶定位到"增益块之前"为止，未进一步落到具体 RTL 节点；
  "起播后 8 s 内占比 69%"的现象未解释。
- T9 是 PL 直连线 600 秒单趟；块模式线的 600 秒回归是另一条线
  （`soak600_20261023.md`），两条线分别记账、不互相归属。
- 演示参数"冻结"指软件默认值收口；`tune_baseline.json` 在板上、不在仓库，
  具体数值依赖板上备份（见根 README 的私有文件对照表）。
