# A/B 工作包：Python 基线结果和数值对照

【任务】
核对 A/B 软件侧当前 Python 基线是否能重新生成结果，并检查仓库已有 HLS 输出与 Python 参考数据之间是否存在偏移或数值差异。记录比较结果来源，避免把旧的硬件输出说成本次重新运行。

【提示词】
「我重新跑 Python 基线时，Windows 控制台报 `UnicodeEncodeError`，是不是输出单位里的特殊字符导致的？怎么改比较稳妥？」
「仓库里已经有 HLS 输出了，我拿它跟新生成的 Python golden 对比时，应该怎么查延迟偏移和误差？这次没有重新跑 HLS，报告里要怎么说清楚？」

【模型回答】
AI 协助排查 GBK 控制台编码问题、运行 Python 基线产物，并使用已有 HLS 输出做数值对照和图表整理。

【哪里错了】
单位中的 `µ` 在 Windows 默认 GBK 控制台无法编码，导致脚本在输出阶段报错。比较结果还有证据边界：本次重跑 Python 基线/比较脚本，不代表重新执行了 Vitis HLS。

【怎么修正】
将终端单位改为 ASCII `us` 后生成基线 WAV、频谱图及黄金数据，并生成瀑布图和 Python/HLS 对比图。已有 HLS 输出的比较记录为：1,000 点 SNR 75.4 dB、最佳位移 0；旁路输出延迟 96 点、0 个错配。AI 协助运行脚本并更新产物；最终提交前仍需负责人确认输入和结果文件。

【沉淀】
数值对比需分别说明输入、延迟对齐方式和误差指标；写报告时分清“本次实际运行”和“使用仓库既有结果进行比较”。
