# 2026-10-28 位流上板：连抓三个真 bug，全是「静默」的那种

> 结论先写：`fir_pl_regs` 这颗位流当天傍晚真的上板了，
> 寄存器读写、+18 dB 生效、斜坡挂起-落零、60 秒零丢字全部实测通过，
> 嘴到耳 **≈2.54 ms**（16.2 ms 版的 1/6）。
> 但这一天真正值钱的是三个 bug：**地址漏分配、斜坡时序 −3.5 ns、自检脚本读错地址**，
> 加上前一批留下的**四段增益只有两段是活的**。四个 bug 没有一个会报错，
> 全靠「写进去再读回来」和「逐位对拍」才暴露。

【任务】

`fir_pl_regs` 这颗位流要接的判据是：

1. `ID = 0x504C0002`、默认 `GAIN = 256`；
2. 四段增益能写能读回；
3. `ramp_busy` 100 ms 内自己落零；
4. 四段各自落到自己的槽位（不是四段写同一个值看着都对）；
5. 上板连跑 60 秒不丢字。

【提示词】

- 「读 PL直连_PROGRESS.md 继续项目，告诉我接下来要做什么，尽量先做需要我协作的事情，等会我去睡觉了需要你独自往后做」
- 「只剩这六个任务了吗」

【模型回答】

先把 `fir_pl_regs` 的参数字段从 128 位整包改成按下游用法裁好
（增益 4×16 = 64 位，thr/ratio/atk/rel 4×24 = 96 位），BD 里对接；
然后综合、实现、上板、跑 `pl_regs_check.py` / `pl_gain.py` / `pl_demo_check.py`。

**结果：位流编出来了，但四个 bug 埋在中间。**

【哪里错了】

**AI 的问题：BD 里接了线没分配地址，validate 不阻断。**
`fir_pl_regs_0` 的 `connect_bd_intf_net` 写了，`assign_bd_address` 漏了。
Vivado 只给 CRITICAL WARNING、位流照样出。上板之后 PS 读 0x43C40000 必然是总线错，
而这时候人只会怀疑「RTL 没写进去」。修法是补地址 +
在 BD 脚本里加一条断言：五个从机缺一个就 `error`。

**AI 的问题：把「bank 内相对偏移」当成绝对地址。**
寄存器表写的是 `+0x70 / +0x74`（RAMPDIV / RAMPBUSY），**相对于 bank0 = +0x100**，
真实地址是 `0x170 / 0x174`。自检脚本读的是 `0x070`，恒 0。
当时的判断是「RTL 没写进去」，于是去改 RTL 的 initial 值 —— **改成了 6**，
而表里约定的默认值是 0，等于用一个错误去盖另一个错误。我自己对着表核了一遍才撤回。

**AI 的问题：斜坡模块时序 WNS −3.5 ns，改完才算完。**
`fir_gain_ramp` 一拍里串完「减法 → 桶形移位 → 补 1 LSB → 加法 → 钳位」，
19 级逻辑，WNS −3.5 ns（上一版还是 +0.222）。改成两级流水：
第一拍算 step，第二拍做加法和钳位。复编后 **WNS +0.253**。
前提条件是 tick 间隔 ≥ 2 拍，由前端 3 拍/采样保证，TB 的节奏也同步改了。

**AI 的问题（前一批留下的）：四段增益只有两段是活的。**
`fir_pl_regs` 的参数包是 128 位（四段各 32 位），BD 里用 `xlslice` 取 `[63:0]`
再当四个 16 位用。实际喂给 `fir_pl_direct` 的是
`{seg0 高16, seg0 低16, seg1 高16, seg1 低16}` ——
**b1/b3 段增益恒 0，b2 段吃的是 b1 的值**。
演示时四段都写同一个 +30 dB，所以只听得出「整体变响」，一直没暴露。
修法：输出位宽按下游用法裁好，`xlslice` 和原计划新增的四个全都不需要；
单测补了 8 条「四段各自落到自己槽位」的断言，旧接法必挂。

**环境的坑：BD 里的静默错误，validate 和出声都拦不住。**
这几天的教训是同一个形状：地址漏分配、位宽被截、口没接线，
Vivado 全都只 CRITICAL WARNING 或者干脆不说话，位流照出、灯照亮。
唯一能暴露它们的是**写已知值再读回**。

【怎么修正】

1. BD 脚本加断言：五个 AXI 从机地址缺一即 `error`，写在 validate 之前。
2. 自检脚本的偏移一律按「基址 + bank + 偏移」三级算，
   `0x170/0x174` 这种绝对地址也打印出来，方便肉眼核。
3. RTL 的 initial 恢复成表里约定的 0，撤回那次「改成 6」。
4. `fir_gain_ramp` 两级流水，TB 节奏同步。
5. `fir_pl_regs` 输出位宽按下游用法裁，单测按「四段各自落槽」写。
6. 判据里加第 4 条：四段写不同值，逐段读回必须不同。

【沉淀】

1. **BD 里「接线」和「分配地址」是两件事**，漏了不报错。
   凡是有 AXI 从口，脚本里就写一条「缺一即 error」。
2. **寄存器表的「+偏移」先问清楚相对于谁。** 这次相对于 bank，不是相对于基址；
   读出来恒 0 的时候，第一反应应该是「地址算错了」，不是「RTL 没写」。
3. **一个 bug 用另一个改动去盖，会变成两个 bug。** 这次差点把 initial 从 0 改成 6。
   改之前先回表核对约定值。
4. **参数打包的位宽要按下游用法裁。** 「128 位整包随便切」看着灵活，
   切错一位就整段错位，而且在「四段写同一个值」的演示里完全看不出来 ——
   验收必须写不同的值。

## 验证边界

- 2.54 ms 是这一版的嘴到耳（当时的算法：采集 FIFO 积压 + 各级缓冲 + 数模），
  批 3 之后口径更新为 2.2 ms，见 `PL直连_PROGRESS.md` §11。
- 60 秒零丢字是 `pl_demo_check.py` 的读数，长跑（600 秒）是另一条线。
- 三个 bug 的修复各自有对拍：斜坡与改动前的 RTL 副本逐位 0 失配；
  四段增益 8 条断言；地址断言在故意删掉一条 `assign_bd_address` 时确实报错。
