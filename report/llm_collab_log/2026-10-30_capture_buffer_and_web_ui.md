# 2026-10-30 抓取缓冲 + 网页波形频谱：三个 bug 里有俩是我自己的测试写错

> 结论先写：这颗位流把 4096 点抓取缓冲接进了 BD（84 ms，0x43C60000，
> 低 16 位进核、高 16 位出核），时序 **WNS +0.107 ns**、DSP **213/220**；
> 网页加了时域波形和 4096 点频谱两栏；录音回放改成循环播放固定素材，
> 拖哪一段的增益，频谱上那根峰就跟着上下走。
> 这一天错得最多的不是 RTL，是**画图**和**读数**：
> 频谱被画成一条贴顶的平线、抓取缓冲的旋转差一个字、
> 播放线程第一块写进了正在读的槽。还有一个是我自己的离线测试先写错了，
> 差一点据此得出「旋转了两次」的错误结论。

2. 网页上要能看到波形和频谱；
3. 录音回放改成循环播放一段固定音频，方便演示拖增益的效果；

录音回放改为循环播放固定音频，方便展示调整增益的现象」

【模型回答】

拍数是 **2083 拍/采样**（100 MHz 时钟、48.8 kHz 采样，三倍的 2083 就是总线上的间隔），
嘴到耳 **2.2 ms**（`lat_ms` 的算法：`(st1>>16)/48.828 + (st1&0xFFFF)/97.656 + 2.2`）。

抓取缓冲 `cap_bram` 4096×32 挂在 0x43C60000，低 16 位写 `fe_din`（进核）、
高 16 位写 `mpo_l`（出核左耳），84 ms 历史。BD 的 AXI 从口从 6 个加到 7 个。

网页加两栏：波形做 4096 点按像素的 min/max 包络（固定 ±32768 满刻度，
横轴 0/42/84 ms）；频谱做 Hann 窗 + 4096 点基 2 FFT，
对数横轴 20 Hz–20 kHz、纵轴 0…−90 dBFS。
后端 `/api/scope` 1 Hz 刷 `/dev/shm/fir_scope.json`，`read_scope` 在 PL 里
冻结 → 读 4096 字 → 解冻，再按写指针旋转成「最旧在前」。

【哪里错了】

**AI 的问题：频谱画成一条贴顶的平线。**
映射写成 `Y = padT + Math.min(0, -d) / 90 * ih`。
`-d` 是「0 dB 在顶、−90 dB 在底」的坐标，本来就 ≤ 0 或 ≥ 0 混着用，
`Math.min(0, -d)` 把所有**正的** dB 值全压成 0，于是所有点都贴在顶部一条线上。
看起来像「频谱没数据」，其实数据是对的。改成先把 `-d` 钳进 `[0, 90]` 再乘高度。
判据：四根演示峰 250/750/1500/4000 Hz 的高度和 dB 读数都要对得上。

**AI 的问题：布局用了 `flex: 1 1 auto`，新加的两栏被挤没了。**
1600×900 下 FR 卡片吃掉全部高度，波形和频谱只剩一条缝。
改成 `flex: 2 1 0` + `min-height: 110px`，用无头 Edge 截图核对。

**AI 的问题：抓取缓冲的旋转差一个字。**
`rot = (ptr + 1) % 4096`。`cap_wr` 是**下一个要写的地址**，
也就是最旧的那个还没被覆盖的槽，旋转就该从它开始。加了 1 之后整段波形左移一个采样，
在低频上几乎看不出来，在 4 kHz 上刚好差一点相位。
改成 `rot = ptr % 4096`。

**AI 的问题：播放线程第一块和读头抢同一个槽。**
循环播放原来是「先写一块，睡一块的时间」。
`pos` 从 0 开始时，读头正好在 0 附近，第一块写下去就把**正在播的那几个字**改了 ——
听感是循环点附近偶尔一记咔哒。改成**先睡后写**：
起点故意落后读头 4 块（约 85 ms），写头永远跑在正在播的字前面；
时标用 `time.monotonic()` 绝对推进，不靠逐次累加。

**我自己的测试先写错了。**
为了不碰板子就验旋转，我写了一个离线假缓冲：按写入顺序把 4096 个点追加到 `i`，
再按旋转读。跑出来「旋转了两次」，我差点据此去改 RTL。
停下来核对才发现假缓冲的写地址应该是**槽位 `a = i % 4096`**，
不是下标 `i`。假缓冲改成按槽位写之后，RTL 的行为和 `rot = ptr` 完全一致。
**注意：错的是我的假缓冲，不是 RTL。** 这类「先错在验证工具上」的情况，
判断依据应该是「两边都改到一致才算数」，而不是「谁先跑出结果信谁」。

**环境的坑：观察量那一行数字被裁、相邻两栏叠在一起。**
字号降到 9.5px、分隔符从 ` / ` 改成 `/` 才放得下。
`/api/status` 的字段一多，这一行就是第一个被挤爆的地方。

【怎么修正】

1. 频谱的 Y 映射先钳位再缩放，四根已知峰的频率和 dB 写进自检。
2. 布局改成 `flex: 2 1 0` + 最小高度，1600×900 用无头浏览器截图验。
3. `read_scope` 的旋转改成 `ptr % 4096`，注释写明「cap_wr 是下一个要写的地址」。
4. `Player.run()` 改成先到点再写、领先 4 块、`time.monotonic()` 绝对时标。
5. 离线假缓冲按槽位写，验证脚本和 RTL 用同一套地址语义。
6. 观察量行字号 9.5px、分隔符改 `/`。

【沉淀】

1. **图画成一条平线，先看映射，不要先怀疑数据。** 把纵轴的钳位区间打印出来最快。
2. **环形缓冲的指针有两种语义：下一个要写 / 最后写的。**
   旋转差一个采样在低频看不出来，找一个高频点放进去当判据。
3. **写头不能和读头抢同一个槽。** 先到点再写、故意落后一段，比加锁简单可靠。
4. **离线验证工具本身也会错。** 两边一致才算数；
   第一版假模型跑出「RTL 错了」的时候，先怀疑假模型。
5. **新增一栏前先算高度预算**，`flex: 1 1 auto` 在固定视口里等于「谁先写谁吃满」。
