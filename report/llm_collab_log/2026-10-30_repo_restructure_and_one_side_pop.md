# 2026-10-30 拆掉 tools/ 之后路径全断；顺便把「一边突然响一下」的范围砍掉一半

> 结论先写：仓库根目录清到只剩 `src / sim / build / board / data / report / skill`。
> 拆 `tools/` 时踩的坑全是同一个：**「往上两级找仓库根」这种写法，目录动一层就全断**，
> 而且断得不报错 —— 脚本照样 import 成功，只是路径指到了 `board/`。
> 另一半是「一边突然响一下」：静止 240 秒的读数说明，
> **两耳在写进输出 FIFO 之前是同一路信号乘两套完全相同的参数**，
> 所以「只有一边」只可能出在 FIFO 之后。

【任务】

1. 先暂停波形/频谱的活，回去查偶发「一边突然响一下」，新线索是**静止的时候更容易触发**；
2. 把产出更新到本地；
3. 根目录里的 `.Xil`、`-p` 要清掉；`tools`、`xsim.dir` 不要单独挂在根上，并进别的目录；
   `docs/` 不能留在仓库。

【提示词】

「先暂停，回头去查查偶发"一边突然响一下"，我发现静止的时候更容易触发，
同时更新产出到本地。仓库中的 ".Xil" "-p" 是干嘛的，可以删掉吗。
tools、xsim.dir 两个文件并入其他文件中，docs 这个文件直接删掉，怎么可以留在仓库」

【模型回答】

**仓库这边**：`.Xil` 和 `-p` 是 Vivado 和一次 `mkdir -p` 手滑留下的目录，删掉；
`xsim.dir` 是 xsim 编库产物，可重建，删掉。
`docs/` 十个内部笔记整体移到桌面（不是硬删）。
`tools/` 拆成两半：78 个板级探针 + `ab_*.py` + `webui_*.py` → `board/probes/`；
参考模型、系数生成、质量指标、素材生成 → `sim/model/`。
`tools/_tmp` 和 `tools/board_debug/_tmp`（59 MB 原始实验日志）→ `build/tmp/`。
死掉的实验 overlay 挪到桌面。

**「一边响」这边**：板上跑 240 秒，每 10 ms 采一次
`PEAK_IN` / `PEAK_OUT` / ovf / und / oovf / 限幅计数，出事就冻结抓取缓冲存 84 ms 波形。
读数：`PEAK_IN` 全程 ≤ 128（等于数字零），`PEAK_OUT` 最大 2070、
10 ms 窗里 31 个 ≥ 1000、**没有一个 ≥ 3000**，ovf 卡在陈旧值 45496 不涨，
und / oovf / 限幅计数全是 0，**一次事件都没触发**。
两耳寄存器读回来完全一致（增益 +20/+25.5/+25.5/+20 dB、门限、比值都一样）。

【哪里错了】

**AI 的问题：目录动一层，「往上两级找仓库根」全断，而且不报错。**
脚本里一直是 `D = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))`，
从 `tools/x.py` 挪到 `sim/model/x.py` 之后，同一个写法指到的是 `sim/` 而不是仓库根。
更麻烦的是它**不会抛异常**：`sys.path.insert` 照样成功，
真正用到 `D` 的那一刻才报「找不到文件」，看起来像环境问题。
六个文件要各加一层 `dirname`，两个 `ROOT = os.path.dirname(HERE)` 同理。

**AI 的问题：`git mv` 到一个已经存在的目录，变成了再套一层。**
`git mv tools/board_debug board/probes`，而 `board/probes` 已经建好了，
结果文件全进了 `board/probes/board_debug/`。索引里 84 条全是「重命名后又删除」。
后来用普通 `mv` 把内容挪上来，索引又和实际不符。
正确顺序是先把目标目录建好、再把源目录**里面的内容**一个个 mv 进去。

**AI 的问题：拿 `git grep` 的结果去批量替换，漏掉了刚 mv 的文件。**
替换脚本的文件清单是 `git grep -l "tools/"` 跑出来的，
而刚 `git mv` 过去的文件在索引里的位置还是旧的，不在清单里 ——
于是 `board/probes/*.sh`、`sim/model/*.py` 里的旧路径一条都没改。
靠再跑一遍 `grep -rln`（不带 git）才补齐。

**AI 的问题：替换顺序反了会互相吃掉。**
`tools/board_debug/_tmp` 和 `tools/_tmp` 两条规则，
如果短的先执行，长的永远匹配不上。必须先长后短。

**环境的坑：`build/tmp` 不建目录，PID 锁直接写失败。**
构建壳的锁和日志原来在 `tools/board_debug/_tmp`，那个目录是手工建的；
换到 `build/tmp/probes` 之后，因为它**不入库**，新克隆根本没有这个目录，
`echo $$ > $LOCK` 直接失败。构建脚本开头要自己 `mkdir -p`。

**环境的坑：板子在 10-30 上午连不上。**
`ping 192.168.2.99` 3 发 1 回（网口没断），paramiko 连 10 s 超时。
按之前的判据：网口在、串口静、SSH 不通 ⇒ 板子卡住，不是断电。

【怎么修正】

1. 全部六个脚本的仓库根改成三级 `dirname`，两处 `ROOT` 同理；
   跑一遍 `gen_rtl_coeffs.py --check-rom`（0 处不同）和 `ref_model_wdrc.py`（1000/1000）
   确认路径真的对。
2. 目录搬迁改成「先建目标、再搬内容」，搬完 `git add -A` 让 git 自己识别重命名。
3. 替换清单用 `grep -rln` 而不是 `git grep -l`。
4. 替换规则按「长路径在前」排序。
5. 构建脚本开头 `mkdir -p build/tmp/probes`。
6. 板子：断电 10 秒再上电；上电后先确认位流 md5 再谈别的。

【沉淀】

1. **`dirname(dirname(__file__))` 是一种隐式契约**：目录一改就断，且断得晚、断在别处。
   要挪目录，先搜这个写法。
2. **`git mv` 的目标必须不存在**，否则会套一层。
3. **批量替换的文件清单要用文件系统扫，不要用索引扫**，尤其是刚 mv 过之后。
4. **只比较宽的替换规则必须按长度从长到短排。**
5. **不入库的目录，脚本自己要负责建。**
6. **「只有一边响」不一定是左右声道的问题。** 两耳数学上相同的时候，
   单边现象只能来自分叉点之后 —— 先找分叉点，再谈怀疑对象。

## 验证边界

- 240 秒里用户没有记录「什么时候听到过响」，所以这组读数只能证明
  「静止时左耳出核的数字信号没有大跳变」，不能证明这段时间没响。
- `PEAK_OUT` 只测左耳；抓取缓冲抓的是「进核 / 出核（左耳）」，
  **分不了左右**，因为上游本来只有一路。
- 仓库整理之后删掉的文件都在 git 历史里；桌面那两个移出目录是临时归档，
  确认不要了再删。
