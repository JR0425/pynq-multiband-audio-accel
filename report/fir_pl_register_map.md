# `fir_pl.bit` 寄存器级契约 —— 演示通路的对外接口

日期：2026-11-02 ｜ 适用位流：`board/overlay/fir_pl.bit`（MD5 `628b75b3d7a13015a69125fb8ac2d228`）
数据来源：**`src/rtl/fir_pl_regs.v`（唯一权威）**、`board/overlay/build_audio_pl.tcl`（只读输入的连线）、
`board/scripts/fir_pl_live.py`（后端实际读写的那一组）、`board/probes/pl_regs_check.py`（上板核对）

> **这份文档和 `report/hardware_interface_spec.md` 不是同一颗位流。**
> 那一份描述的是**上一代块模式 HLS 核**（`fir.bit`，16.7× 加速比的量测载体），
> 寄存器是 HLS 自动生成的 `ap_ctrl_hs` 那套（`AP_CTRL` / `in_r` / `out_r` / `length_r`）。
> 本文件的 `fir_pl.bit` 是**手写 RTL**，寄存器由 `fir_pl_regs.v` 手工排布，两套地址**没有任何一处重合**。
> 照上一份写驱动，对着演示位流一个字都读不对。
> 两份都留在仓库里，因为两条通路都还在（§3 的四通路表）。

## 〇、三件定死的事

1. **位流 = `fir_pl.bit` + 同名 `fir_pl.hwh`，必须成对加载**（`fir_pl.hwh` 与 `.bit` 要为同一次构建）。
2. **`s_axi` 基址 `0x43C40000`，地址窗口 64 KiB**（`assign_bd_address -offset 0x43C40000`）。
   本文所有偏移都是**相对 `0x43C40000` 的绝对值**，不再叠加 bank 基址。
3. **本设计只有一个时钟域**：`FCLK_CLK0` = 100 MHz。I2S 的 BCLK / LRCLK 由它分频产生、
   再打一拍输出，不存在跨时钟域握手，也**不需要** CDC 同步器（见设计报告 §2.5）。

## 一、地址分区

| 区间 | 内容 | 归属 |
|---|---|---|
| `0x000–0x0FF` | 控制 / 状态 / 电平 / 限幅 / 音源 / 抓取 | `fir_pl_regs` 直接译码 |
| `0x100–0x17F` | **左耳**参数 bank0 | 同上，`addr[9]=0` |
| `0x200–0x27F` | **右耳**参数 bank1（布局与 bank0 完全相同） | 同上，`addr[9]=1` |
| 另两个窗口 | 波表 BRAM（播放缓冲）、抓取 BRAM | `axi_bram_ctrl`，**不经本文件**，见 §五 |

⚠️ **bank 内的 `+0x00 … +0x74` 是相对偏移，不是绝对地址。**
`GAIN[0]` 在左耳是 `0x100`、右耳是 `0x200`；`RAMP_DIV` 在左耳是 **`0x170`**，不是 `0x070`。
板上真踩过这个坑：写 `0x070` 读到恒 0（那是 `CLR_STAT`，一个单拍脉冲），一度误判成寄存器没实现。
`skill/templates/pynq_overlay_skeleton.py` 里专门为此留了一段注释。

## 二、控制 / 状态区（`0x000–0x0FF`）

### 2.1 控制

| 偏移 | 名字 | R/W | 位定义 | 出厂值 |
|---|---|---|---|---|
| `0x00` | `ID` | RO | 恒 `0x504C_0002`（`PL` + 版本 2） | — |
| `0x04` | `CTRL` | R/W | bit0 `run`：整条链路使能<br>bit1 `drc_en`：压缩器使能<br>bit2 `flush`：两侧 FIFO 清空，**写 1 后 16 拍自清**<br>bit3 `mpo`：MPO 限幅使能<br>bit4 `tone`：片内单音音源<br>bit5 `src`：音源选择（0 = 播放环，1 = 单音）<br>bit8 `clr`：计数器清零（电平，写 0 恢复计数） | `0x0000_0000`（`run=0`、`drc_en=0`，只过前端） |
| `0x70` | `CLR_STAT` | W（单拍） | 写任意值产生一个时钟周期脉冲，清 `ovf` / `und` / `pop` 计数器 | — |

**`flush` 是自清的**：写 `CTRL[2]=1` 后计数器数 16 拍自动落回 0，不需要软件再写一次 0。
这条是给"换阶段 / 重跑前先冲掉残留采样"用的；如果软件手动清零，会有一拍窗口把残留采样放出来。

**`run=0` 时输出静音、且不消耗 FIFO** —— 所以 `run` 也是"暂停但不丢数据"的开关。

### 2.2 状态与计数

| 偏移 | 名字 | R/W | 内容 |
|---|---|---|---|
| `0x08` | `STAT0` | RO | `[15:0]` 采集溢出计数（上一对还没送完又来一对）<br>`[31:16]` 播放欠载计数（LRCLK 边沿到了，手里凑不齐一对） |
| `0x0C` | `STAT1` | RO | `[15:0]` 播放 FIFO 当前水位（字）<br>`[31:16]` 采集 FIFO 当前水位（字） |
| `0x10` | `STAT2` | RO | `[15:0]` 输出 FIFO 溢出次数（正常必须恒 0）<br>`[31:16]` 运行以来见过的最大播放 FIFO 水位 |
| `0x14` | `smp_cnt` | RO | **读回恒 0（未接，见 §2.5）** |
| `0x18` | `frm_cnt` | RO | **读回恒 0（未接）** |
| `0x1C` | `ply_rd` | RO | 播放环**读指针**（`[13:0]`）。2026-10-30 起接真值，此前恒 0 |
| `0x20` | `ply_und` | RO | **读回恒 0（未接）** |
| `0x24` | `PLY_CTL` | R/W | bit0 播放使能、bit1 循环（`{30'd0, w_data[1:0]}`） |
| `0x28` | `PLY_LEN` | R/W | 播放环循环长度（`[13:0]`，写 `{18'd0, w_data[13:0]}`） |
| `0x80` | `POP_CNT` | RO | 相邻采样跳变 > 8192（满量程 1/4）的**次数** |
| `0x84` | `POP_MAX` | RO | 见过的最大单采样跳变量 |

`POP_CNT` / `POP_MAX` 这一对是 2026-10-31 加的**片上判据**，原因是 `0x78/0x7C` 那个读窗口
读 1024 点要 41 ms，比 21 ms 的可读窗口还长 —— 当测量仪器不成立。
判据三档：安静 60 s 不涨 = 链路干净；涨而 `POP_MAX` 只有几百 = 噪声；`POP_MAX` 上万 = 真的丢样点 / 重样点。

### 2.3 电平、限幅与音源

| 偏移 | 名字 | R/W | 内容 |
|---|---|---|---|
| `0x2C` / `0x30` | `lvl_in_lo` / `lvl_in_hi` | RO | **读回恒 0（未接）** |
| `0x34` / `0x38` | `lvl_out_lo` / `lvl_out_hi` | RO | **读回恒 0（未接）**；实际电平看 `0x40`/`0x44` 的窗口峰值 |
| `0x3C` | `WIN_LEN` | R/W | 峰值窗口长度，默认 `1024`。`peak_in`/`peak_out` 每窗末锁存 |
| `0x40` | `peak_in` | RO | 最近一窗入核 `\|max\|`（16 位，满量程 32767） |
| `0x44` | `peak_out` | RO | 最近一窗出核 `\|max\|` |
| `0x48` | `MPO_TH` | R/W | 限幅阈值，默认 `32767`（= 满量程 = 不动作，**故意**） |
| `0x4C` | `MPO_REL` | R/W | 限幅释放步长，默认 `896`（100 ms @48 kHz） |
| `0x50` | `mpo_cnt` | RO | 被限幅的采样数 |
| `0x54` | `mpo_peak` | RO | 见过的限幅前峰值（饱和到 `0x7FFF`） |
| `0x58` | `tone_sel` | R/W | 片内单音频率档（`[1:0]`） |
| `0x5C` | `tone_amp` | R/W | 单音幅度（`[15:0]`） |

### 2.4 耳别、示波与抓取窗口

| 偏移 | 名字 | R/W | 内容 |
|---|---|---|---|
| `0x60` | `EAR_CTL` | R/W | bit0 `indep`：双耳独立（0 = 两耳吃同一套参数）<br>bit2:1 `out_mode`：输出模式 |
| `0x64` | `SCOPE_CTL` | R/W | bit0 `arm`：抓取单次触发<br>bit1 `auto`：连续抓取 |
| `0x68` | `scope_seq` | RO | **读回恒 0（未接）** |
| `0x6C` | `scope_wr` | RO | 抓取缓冲当前写指针（`[12:0]`） |
| `0x78` | `CAP_IDX` | R/W | 抓取缓冲**读下标**（写）+ 回读当前下标（读） |
| `0x7C` | `CAP_DATA` | RO | 返回 `CAP_IDX` 指向的那个字 |

**抓取缓冲必须走 `0x78`/`0x7C` 这个逐字窗口，不能直接读 `axi_bram_ctrl`。**
后者在本设计里读回恒 `0x8`，根因是 `SINGLE_PORT_BRAM` 填 0 导致读口走了没人接的 B 口
（生成的 wrapper 里能读到 `.bram_rddata_b(...1'b1,1'b0,1'b0,1'b0)` = `32'h00000008`，
与板上读回一字不差）。完整经过见 `data/results/rtl_vs_hls.md` §9.4。

**这个窗口读 4096 点约 41 ms 量级**（40 µs/字），比 21 ms 的波形刷新窗口还长 ——
所以慢变量判据（跳变次数）已经下放到 PL 的 `0x80`/`0x84`，不要用读窗口去当测量仪器。

### 2.5 读回恒 0 的寄存器（明确列出来，不要当成"写坏了"）

BD 里这 8 个只读输入统一接到 `xlconstant`（`z32`，`CONST_VAL=0`）：

`smp_cnt`(0x14)、`frm_cnt`(0x18)、`ply_und`(0x20)、`lvl_in_lo`(0x2C)、`lvl_in_hi`(0x30)、
`lvl_out_lo`(0x34)、`lvl_out_hi`(0x38)、`scope_seq`(0x68)

它们是**接口位保留、数据源未接** —— 位流里有这个地址、读不报总线错、但值恒 0。
用途已经由别的寄存器覆盖：采样计数看 `0x1C` 的 `ply_rd`，欠载看 `0x08[31:16]`，电平看 `0x40`/`0x44`。
自检脚本 `pl_regs_check.py` 对这 8 个地址**只验"读得到、不报错"，不验值**。

## 三、参数 bank（`0x100` 左耳 / `0x200` 右耳）

组内偏移固定，两耳布局相同。

| 组内偏移 | 绝对地址（左 / 右） | 名字 | R/W | 格式 | 出厂值 |
|---|---|---|---|---|---|
| `+0x00` | `0x100` / `0x200` | `GAIN[0]` | R/W | Q7.8（1.0 = 256） | `256`（0 dB） |
| `+0x04` | `0x104` / `0x204` | `GAIN[1]` | R/W | 同上 | `256` |
| `+0x08` | `0x108` / `0x208` | `GAIN[2]` | R/W | 同上 | `256` |
| `+0x0C` | `0x10C` / `0x20C` | `GAIN[3]` | R/W | 同上 | `256` |
| `+0x10…+0x1C` | `0x110…0x11C` | `THR[0..3]` | R/W | Q1.15 **左移 7 位**（低 7 位为 0，等价 Q2.22） | `419456` = `3277<<7` = **−20 dBFS** |
| `+0x20…+0x2C` | `0x120…0x12C` | `RATIO[0..3]` | R/W | Q1.15 **左移 7 位**（等价 Q2.22） | `2936064` = `22938<<7` = **0.7** |
| `+0x30…+0x3C` | `0x130…0x13C` | `ATK[0..3]` | R/W | Q1.15 **左移 7 位**（0 = 无记忆压缩） | `17408` = `136<<7` = **5 ms** |
| `+0x40…+0x4C` | `0x140…0x14C` | `REL[0..3]` | R/W | 同上 | `896` = `7<<7` = **100 ms** |
| `+0x50…+0x5C` | `0x150…0x15C` | `ENV[0..3]` | **RO** | Q2.22，取每段包络的高 24 位后右移 | — |
| `+0x60…+0x6C` | `0x160…0x16C` | `GR[0..3]` | **RO** | 当前增益衰减量（Q7.8 量纲） | — |
| `+0x70` | **`0x170`** / `0x270` | `RAMP_DIV` | R/W | 增益斜坡分频，`0` = 每采样走 1 LSB | `0` |
| `+0x74` | `0x174` / `0x274` | `RAMP_BUSY` | **RO** | bit0 = 斜坡未落定 | — |

段号 = `addr[3:2]`，bank 号 = `addr[9]`。

**关于出厂 `THR` 与实际演示门限的差别（必须一起读）：**

- RTL 出厂值是 `−20 dBFS`（`419456`）。这是照 v25 出货核的参数抄下来的，目的是"位流一上电听感就和批 2 一致"。
- **但演示时软件会立刻覆盖它**：`fir_pl_webui.py` 的 `PRESETS["demo"]` 写的是
  `+22 dB / −10 dBFS / 0.7`，上电后由 `fir_pl_live.py` 的 100 Hz 控制环写进寄存器。
- 所以"默认门限是 −10 dBFS"指的是**演示状态**，"出厂 419456 = −20 dBFS"指的是**不跑软件时**。
  §5.1 那张 THD 表里 `−20 dBFS` 一档对应的是 RTL 出厂门限，`−10 dBFS` 一档对应 `demo` 预设 —— 两者不是同一件事。

**为什么阈值/比值/起停是"左移 7 位"存放：** 三者进核前统一 `<<7`，
寄存器里就是这么摆的（`136 << 7 = 17408`）。软件写的时候必须已经移好，
写成 `136` 会得到一个比 5 ms 快 128 倍的 attack —— 听起来像"没压缩"，很难查。

## 四、读写语义（四条，都是有代价换来的）

1. **只支持整字写（`WSTRB = 4'hF`）。**
   字节使能不实现，非 `4'hF` 的写**静默丢弃**（不报 SLVERR）。
   要改一个字节就先读-改-写。省掉 40 条按字节的赋值，代价是这条约定必须遵守。

2. **参数类寄存器用 `initial` 给初值，不跟 `rst_n` 走。**
   Xilinx 器件上电按 `initial` 装载，所以 FPGA 配置完就是出厂值；
   **只有控制位与握手状态走 `rst_n`**。这意味着对 PL 做局部复位**不会**恢复参数默认值。

3. **`bank` 由 `addr[9]` 选，不是 `addr[11]`。**
   2026-10-29 板上抓到的 bug：原来用 `wa[11]` 选 bank，而 `0x100`/`0x200` 的 bit11 都是 0 ——
   于是**所有写给右耳的参数都落到左耳上**（读 `0x2xx` 也读到左耳）。
   现象是"双耳两套处方怎么调都一起变"，看着像参数没接进通路。现在已改为 `addr[9]`。

4. **参数按"高位在前"打包，位宽已按下游用法裁好**：增益每段 16 位、其余每段 24 位。
   2026-10-28 的教训：原来是每段 32 位、共 128 位，BD 里用 `xlslice` 取 `[63:0]` 当四个 16 位用，
   结果 `b1`/`b3` 段增益恒 0、`b2` 拿到 `b1` 的值。**四段写同一增益时只听得出"变响了"**，
   所以第一批位流就这样跑过去了。

**写寄存器的顺序没有约束**（不像上一代 HLS 核要"全写完再 `ap_start`"）：
`fir_pl_regs` 是纯寄存器文件，写进去立刻生效，下一采样就吃到新参数。
验配页面靠的正是这一点 —— 拖滑杆就能实时听到变化。

## 五、不在这个窗口里的两个缓冲

| 资源 | 地址 | 大小 | 用途 |
|---|---|---|---|
| 播放环 BRAM | `0x43C50000` | 16384 字（64 KiB） | 板载 WAV 循环播放，字格式 `[31:16]` 为样本、低 16 位补 LD 位 |
| 抓取 BRAM | `0x43C60000` | 4096 字 | 波形 + rFFT 频谱数据源 |

播放环的字格式：`ply_sample = ply_rdata[31:16]`（高 16 位是样本，低 16 位是 I2S 的 LD 补位）。
读指针看 `0x1C`，循环长度写 `0x28`（`PLY_LEN`，`[13:0]`），启动写 `0x24`（`PLY_CTL`，bit0 使能、bit1 循环）。

**抓取 BRAM 不要直接读**（读回恒 `0x8`，见 §2.4），走 `0x78`/`0x7C`。

## 六、量出来的配套参数（不是寄存器，但驱动要一致）

| 量 | 值 | 说明 |
|---|---|---|
| `FCLK_CLK0` | 100 MHz | PL 主时钟，也是寄存器总线时钟 |
| BCLK | 3.125 MHz | `clk_cntr[4]`，100 MHz / 32 |
| LRCLK | 48.828 kHz | `clk_cntr[10]`，100 MHz / 2048 —— **不是 48.000 kHz** |
| codec MCLK | 10.000 MHz | `clk_wiz_10MHz` 单独出，走 `audio_clk_10MHz` 端口 |
| 每采样拍数 | 3 | 前端 3 拍（`3000 cycles / 1000 samples`），48.828 kHz 下预算 20.48 µs |
| 群延迟 | 96 采样 = 1.966 ms | `(N−1)/2`，2026-11-02 互相关实测 94—96、中位 96 |

⚠️ **48.828 kHz 与 48.000 kHz 差 1.7%**，写时长/采样数换算时要用前者，
用 48 kHz 算 600 秒会差出 10 秒的量。这是 `i2s_duplex` 分频比的直接结果，
不是误差 —— 改分频比会让 I2S 与 codec 失配。

## 七、最小可用驱动（照这份表就能写出来）

```python
from pynq import Overlay, MMIO

BASE = 0x43C40000

class FirPl:
    def __init__(self, mmio=None):
        self.mm = mmio or MMIO(BASE, 0x10000)

    # 左耳 bank0；右耳把 bank 参数换成 1（内部 +0x100）
    def _a(self, off, bank):
        return off + (0x100 if bank == 0 else 0x200)

    def gain(self, bank, seg, db):
        q = int(round((10 ** (db / 20)) * 256)) & 0xFFFF      # Q7.8，1.0 = 256
        self.mm.write(self._a(0x00 + 4 * seg, bank), q)

    def thr_dbfs(self, bank, seg, dbfs):
        q = int(round((10 ** (dbfs / 20)) * 32768)) << 7       # Q1.15 再 <<7
        self.mm.write(self._a(0x10 + 4 * seg, bank), q)

    def run(self, on=True, drc=True):
        v = (1 if on else 0) | (2 if drc else 0)
        self.mm.write(0x04, v)

    def status(self):
        return dict(ovf=self.mm.read(0x08) & 0xFFFF,
                    und=self.mm.read(0x08) >> 16,
                    tx_lvl=self.mm.read(0x0C) & 0xFFFF,
                    rx_lvl=self.mm.read(0x0C) >> 16,
                    peak_in=self.mm.read(0x40) & 0xFFFF,
                    peak_out=self.mm.read(0x44) & 0xFFFF)
```

现成的完整实现见 `board/scripts/fir_pl_live.py`（100 Hz 控制环）、
`board/scripts/fir_pl_webui.py`（网页验配）、`board/probes/pl_regs_check.py`（上板核对，逐条打 PASS 行）。
生成器见 `skill/templates/register_map_stub.py`。
