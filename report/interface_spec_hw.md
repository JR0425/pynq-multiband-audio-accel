## 〇、先说三件已经定死的事

1. **数据格式 = int16 / Q1.15**,外部采样率 **48 kHz**。真实输入是 I2S 送来的 int16,
   和 Q1.15 是同一串比特,**不需要任何转换逻辑** —— 这也是上板版选定点的原因之一。
2. **频段结构 = 相减式**,4 段,边界 **500 / 1000 / 2000 Hz**(倍频程)。
3. **抽头数 = 193**,已实测定下来(比 65 抽头多花 2.23 倍运算量,换来的是四段真的分得开;
   量出来的对照见 §1.5)。它在代码里是编译期参数 `FIR_N_TAPS`,不是寄存器。

## 一、核的契约(这一层现在就定死)

### 1.1 函数签名

```c
void fir_multiband(const int16_t *in, int16_t *out, int length,
                   const int16_t drc_thr[N_BANDS],    /* Q1.15 */
                   const int16_t drc_ratio[N_BANDS],  /* Q1.15 */
                   int reset,
                   int bypass);
```

- `in` / `out`:等长两块内存,采样一对一。
- `length`:本块采样数,须 ≤ 编译期上限 `N_MAX`。
- **抽头延迟线在块之间保持**(不在每次调用时清零)——
  由 `reset` 显式清零。理由见 §1.4。
- `reset`:非 0 = 清空延迟线(对应 CTRL 的 RESET 位)。
- `bypass`:非 0 = 跳过压缩,输出就是各段之和(对应 CTRL 的 BYPASS 位)。
  两个用处:① 上板演示"加压缩 / 不加压缩"的对比听感(验配现场就是这么做的);
  ② **直通检验** —— 各段之和恒等于延迟 D 拍的输入,所以 bypass 时输出必须
  **逐位等于**输入延后 D 拍。实测 N=65:1000 个采样、位移精确等于 D=32、错配 0 个。
  想靠"把阈值设到最大"来绕过压缩是**不行的**:阈值是 Q1.15,最大只能到 32767/32768,
  而相减式下 b_i 是两段之差、幅度能到 ±2,照样会落进压缩支路。

### 1.2 数值格式

| 量 | 类型 | 说明 |
|---|---|---|
| 输入 / 输出 | `int16`,Q1.15 | 量程 [-1, 1) |
| 系数 | `int18`,Q1.17(片内 ROM,烧死) | 实测三个低通的最大系数 0.083,余量充足 |
| 累加器 | 40 位,Q8.32 | 3 个低通各自独立累加;关掉饱和(永远不会溢出) |
| DRC 中间量 | 24 位,Q2.22 | 输入是单段输出,量级在 ±1 附近 |

采样 16 位 × 系数 18 位:C 仿真对黄金参考 **SNR 75.4 dB**(N=193)/ 76.0 dB(N=65),
判据 ≥ 70 dB。另外还有一条比 SNR 硬得多的检查 —— **直通检验**:bypass 模式下输出必须
**逐位等于**输入延后 D 拍(N=193:D=96,1000 个采样错配 0 个;N=65:D=32,错配 0 个)。
这条能把"结构接错了"和"量化误差大了"分开。

### 1.3 内部结构:相减式,只要 3 个滤波器

```
hist[]   共 N 抽头,三个滤波器共用

y1 = FIR(hist, c_LP500)          /* 低通 500  */
y2 = FIR(hist, c_LP1000)         /* 低通 1000 */
y3 = FIR(hist, c_LP2000)         /* 低通 2000 */

b1 = y1                    /* 0    ~ 500  Hz */
b2 = y2 - y1               /* 500  ~ 1000 Hz */
b3 = y3 - y2               /* 1000 ~ 2000 Hz */
b4 = hist[D] - y3          /* 2000 ~ 24k  Hz,  D = (N-1)/2 */

out = Σ DRC(b_i, thr_i, ratio_i)
```

- **`hist[D]` 就是 D 拍前那个输入**(hist[0] 最新,hist[k] 是第 k 拍前),
  它已经在线上了 —— 第 4 段不需要额外的延迟线,白拿。
- 四段延迟**天然一致**(全是 D),不需要额外对齐。
- 不做压缩时 `out` 恒等于输入(延迟 D 拍)。实测重建误差 **−309 dB**,
  而"每段各自设计带通"的旧方案是 **+3.2 dB**(还没压缩,声音就先变了)。
- 滤波器从 4 个降到 **3 个**。

### 1.4 延迟线与块间连续性(这一条和队友那份 spec 不一样)

核**不再每次调用清零延迟线**。理由:分块处理时,每块开头清零会让块边界炸出"咔"声。

| | 做法 | Python 侧怎么对 |
|---|---|---|
| 整段一次处理 | 调用前先写一次 RESET | `lfilter(taps, 1, x)` 零初值 |
| 分块流式 | 只在开始时 RESET 一次 | `lfilter(taps, 1, x, zi=状态)` 跨块带状态 |

两种用法同一份硬件,靠"什么时候发 RESET"区分。

### 1.5 抽头数已定为 193（附：为什么不是 65）

| 抽头数 N | 过渡带 3.3·fs/N | 最差边界残留 | 段 2 在**自己**中心 707 Hz 处 |
|---|---|---|---|
| 65 | 2437 Hz | −6.0 dB | −14.2 dB |
| 129 | 1227 Hz | −14.5 dB | −4.1 dB |
| **193** | **820 Hz** | **−21.4 dB** | **−1.6 dB** |

判据是每条边界两侧都 ≤ −20 dB。65 抽头**不是"串音大了点"，是段 2 连自己该通过的
707 Hz 都压掉了 14 dB** —— 过渡带（2437 Hz）比要分的那几段本身（500 / 500 / 1000 Hz 宽）
还宽，四段根本没分开，压缩比调什么都一样。所以 65 抽头不满足功能要求，不是"省一点"的选项。

### 1.6 群延迟、吞吐、面积、时序（全部实测）

| 抽头数 N | 群延迟 D=(N−1)/2 | 时间 @48 kHz | 拍/采样 | LUT | DSP | WNS |
|---|---|---|---|---|---|---|
| 65 | 32 采样 | 0.67 ms | 173 | 1754 (3.3%) | 70 (31.8%) | **+1.547 ✅** |
| **193** | **96 采样** | **2.00 ms** | **449** | **3962 (7.5%)** | **202 (91.8%)** | **+1.624 ✅** |

- 实时预算：48 kHz 下每采样 **1/f 秒**。100 MHz 时是 2083 拍，193 抽头用 449 拍 →
  **4.6 倍余量**。吞吐从来不是限制条件。
- 上表是 `-mode out_of_context` 综合 + 布局布线的**实测值**，量法见
  `data/results/impl_metrics.md`。

**乘法器不限流**，这是量出来的结论，不是默认值：限流能省 DSP（限到 64 个还剩 86 个），
但复用会把两个 DSP48 串成一条没有寄存器的长链，100 MHz 下直接崩
（限 64 → WNS −0.620、443 条失败路径；限 96 → −0.138、19 条），**而且更费 LUT**
（3962 → 10443）。202 个 DSP 占板上 91.8%，看着吓人，但整个系统里除了这个 FIR
没有任何东西用 DSP48（DMA、I2S、AXI 互联都是 0 个）。

"降频换面积"这条备选路也量过：限流 64 + **80 MHz** 能过，86 个 DSP，但只剩 **+0.386 ns** 余量，
且它的临界路径 11.589 ns 里有 7.018 ns 是纯走线（逻辑只有 4 级）—— 布得散，靠不住。
所以不用它。

## 二、寄存器表(AXI-Lite)

| 偏移 | 名字 | R/W | 内容 |
|---|---|---|---|
| 0x00 | CTRL | W | bit0 START(写 1 启动一块);bit1 RESET(写 1 清延迟线);bit2 BYPASS(写 1 不做压缩) |
| 0x04 | STATUS | R | bit0 DONE;bit1 BUSY |
| 0x08 | N_SAMPLES | W | 本块采样数 |
| 0x0C | ID | R | `(N_BANDS << 16) \| N_TAPS` —— 给 Python 核对固件版本 |
| 0x10/14/18/1C | DRC_THR_1~4 | R/W | 四段的压缩阈值,Q1.15(默认 0.1 → **3277**) |
| 0x20/24/28/2C | DRC_RATIO_1~4 | R/W | 四段的压缩比,Q1.15(默认 0.7 → **22938**) |

### 与队友那份 spec 的差异(逐条)

| 队友 spec | 改成 | 为什么 |
|---|---|---|
| `CTRL`(0x00)同时管 Start 和 Done | 拆成 `CTRL`(只写)/ `STATUS`(只读) | 同一地址读写同一寄存器:写完 Start 再读回来,读到的是自己写的值,不是状态 —— 必然出竞态 |
| `NUM_TAPS`(0x04)做成可写寄存器 | 删掉,改成只读 `ID` | 抽头数在 HLS 里是**编译期常量**,寄存器改不动它,写进去是给自己看的。但 Python 需要知道当前固件是几个抽头 → 只读返回 |
| `FREQ_BAND_1~4`(0x08~0x14) | 删掉,**系数烧死在片内 ROM** | 系数是离线算好的,运算需要的是**系数本身**,不是截止频率。写成频率 = 要求硬件现场算 sin/cos + 窗函数,贵得多且没必要。**为什么不走"软件写系数"**:系数一旦变成运行时可写的数组,HLS 就没法把它当常量处理,很可能撑出一大片逻辑(参考实测过的反例:LUT 炸到 232%);这一条**没试过,列进风险**。 |
| `overlay.write(0x18, 0.1)` | 写整数 **3277** | PYNQ 的 MMIO 只收整数。Q1.15 下 0.1 → 3277、0.7 → 22938 |
| (没有) | 加 `N_SAMPLES` | 核必须知道这一块有多少点 |
| (没有) | 加 `RESET` | 见 §1.4,块间连续要靠它 |

## 三、外层包装(第 ② / ③ 步再定,这里只记约束)

**核本身是"块进块出",和怎么搬数据无关** —— 所以甲(改官方 IP 内部)还是乙(换 `axi_i2s_adi` + DMA)
这个选择**不影响本文件的一、二两节**。外壳怎么包,等第 ③ 步动手前再定。

上板前必须补的两条(实测得到,不是推测):

1. **`ap_done` / `ap_ready` / `out_r` 是组合输出**(端口上没打拍)。
   外层包装必须给它们**各打一拍**,否则会拖出一条十几纳秒的组合路径。
2. **WNS +1.624 是在"裸核"上量的**,而且用的是 `-mode out_of_context`
   (核当成 IP、顶层端口不占管脚)。没套 AXI、没接音频通路、I/O 也没约束 ——
   接进 overlay 之后**必须重新量一遍**;那个数不能当成整机的承诺。

## 四、风险 / 还没定的

- **91.8% 的 DSP 用满了**,只剩 18 个。现在够用(系统里没有别的东西用 DSP48),
  但如果以后要加"每段增益"、"立体声"或者任何要乘法器的模块,就得回到降频那条路
  (限流 64 + 80 MHz,已实测能过,但只剩 +0.386 ns 余量)。
- **BYPASS 位是新加的**,不在原来那份接口约定里。理由写在 §1.1。
- **系数做成 ROM 而不是软件可写**:换频段边界要重新综合。这是刻意的取舍(见 §二),
  但**"运行时可写系数"这条路没试过**,不知道代价多大。真要演示"频段参数化"的话要回头试。
- **段边缘的分离度 −21 dB 够不够** —— 没上板听过,不知道。
- **要加"每段增益"寄存器吗** —— 助听器验配最直观的就是每段增益。
  现在是"阈值 + 压缩比"两档,还没有独立增益,加的话是 4 个寄存器和几个乘法器
  (DSP 只剩 18 个,够,但余量进一步变薄)。
  建议等第一版出声之后再定。
