## 一、核的契约(这一层现在就定死)

### 1.1 函数签名

```c
void fir_multiband(const int16_t *in, int16_t *out, int length,
                   const int16_t drc_thr[N_BANDS],    /* Q1.15 */
                   const int16_t drc_ratio[N_BANDS],  /* Q1.15 */
                   int reset,
                   int bypass);
```

- `in` / `out`:等长两块内存,采样一对一。
- `length`:本块采样数,须 ≤ 编译期上限 `N_MAX`。
- **抽头延迟线在块之间保持**(不在每次调用时清零)——
  由 `reset` 显式清零。理由见 §1.4。
- `reset`:非 0 = 清空延迟线(对应 CTRL 的 RESET 位)。
- `bypass`:非 0 = 跳过压缩,输出就是各段之和(对应 CTRL 的 BYPASS 位)。
  两个用处:① 上板演示"加压缩 / 不加压缩"的对比听感(验配现场就是这么做的);
  ② **直通检验** —— 各段之和恒等于延迟 D 拍的输入,所以 bypass 时输出必须
  **逐位等于**输入延后 D 拍。N=193 上板实测 144000 个采样、位移精确等于 D=96、错配 0 个；C 仿真也验证了 1000 点直通输出。
  想靠"把阈值设到最大"来绕过压缩是**不行的**:阈值是 Q1.15,最大只能到 32767/32768,
  而相减式下 b_i 是两段之差、幅度能到 ±2,照样会落进压缩支路。

### 1.2 数值格式

| 量 | 类型 | 说明 |
|---|---|---|
| 输入 / 输出 | `int16`,Q1.15 | 量程 [-1, 1) |
| 系数 | `int18`,Q1.17(片内 ROM,烧死) | 实测三个低通的最大系数 0.083,余量充足 |
| 累加器 | 40 位,Q8.32 | 3 个低通各自独立累加;关掉饱和(永远不会溢出) |
| DRC 中间量 | 24 位,Q2.22 | 输入是单段输出,量级在 ±1 附近 |

采样 16 位 × 系数 18 位:C 仿真对黄金参考 **SNR 75.4 dB**(N=193)/ 76.0 dB(N=65),
判据 ≥ 70 dB。另外还有一条比 SNR 硬得多的检查 —— **直通检验**:bypass 模式下输出必须
**逐位等于**输入延后 D 拍(N=193:D=96,1000 个采样错配 0 个;N=65:D=32,错配 0 个)。
这条能把"结构接错了"和"量化误差大了"分开。

### 1.3 内部结构:相减式,只要 3 个滤波器

```
hist[]   共 N 抽头,三个滤波器共用

y1 = FIR(hist, c_LP500)          /* 低通 500  */
y2 = FIR(hist, c_LP1000)         /* 低通 1000 */
y3 = FIR(hist, c_LP2000)         /* 低通 2000 */

b1 = y1                    /* 0    ~ 500  Hz */
b2 = y2 - y1               /* 500  ~ 1000 Hz */
b3 = y3 - y2               /* 1000 ~ 2000 Hz */
b4 = hist[D] - y3          /* 2000 ~ 24k  Hz,  D = (N-1)/2 */

out = Σ DRC(b_i, thr_i, ratio_i)
```

- **`hist[D]` 就是 D 拍前那个输入**(hist[0] 最新,hist[k] 是第 k 拍前),
  它已经在线上了 —— 第 4 段不需要额外的延迟线,白拿。
- 四段延迟**天然一致**(全是 D),不需要额外对齐。
- 不做压缩时 `out` 恒等于输入(延迟 D 拍)。实测重建误差 **−309 dB**,
  而"每段各自设计带通"的旧方案是 **+3.2 dB**(还没压缩,声音就先变了)。
- 滤波器从 4 个降到 **3 个**。

### 1.4 延迟线与块间连续性

核**不再每次调用清零延迟线**。理由:分块处理时,每块开头清零会让块边界炸出"咔"声。

| | 做法 | Python 侧怎么对 |
|---|---|---|
| 整段一次处理 | 调用前先写一次 RESET | `lfilter(taps, 1, x)` 零初值 |
| 分块流式 | 只在开始时 RESET 一次 | `lfilter(taps, 1, x, zi=状态)` 跨块带状态 |

两种用法同一份硬件,靠"什么时候发 RESET"区分。

### 1.5 抽头数已定为 193（附：为什么不是 65）

| 抽头数 N | 过渡带 3.3·fs/N | 最差边界残留 | 段 2 在**自己**中心 707 Hz 处 |
|---|---|---|---|
| 65 | 2437 Hz | −6.0 dB | −14.2 dB |
| 129 | 1227 Hz | −14.5 dB | −4.1 dB |
| **193** | **820 Hz** | **−21.4 dB** | **−1.6 dB** |

判据是每条边界两侧都 ≤ −20 dB。65 抽头**不是"串音大了点"，是段 2 连自己该通过的
707 Hz 都压掉了 14 dB** —— 过渡带（2437 Hz）比要分的那几段本身（500 / 500 / 1000 Hz 宽）
还宽，四段根本没分开，压缩比调什么都一样。所以 65 抽头不满足功能要求，不是"省一点"的选项。

### 1.6 群延迟、吞吐、面积、时序（全部实测）

| 抽头数 N | 群延迟 D=(N−1)/2 | 时间 @48 kHz | 拍/采样 | LUT | DSP | WNS |
|---|---|---|---|---|---|---|
| 65 | 32 采样 | 0.67 ms | 173 | 1754 (3.3%) | 70 (31.8%) | **+1.547 ✅** |
| **193** | **96 采样** | **2.00 ms** | **28** | **3670 (6.90%)** | **200 (90.91%)** | **+1.832 ✅** |

- 实时预算：48 kHz 下每采样 **1/f 秒**。100 MHz 时是 2083 拍，193 抽头改开关后只用 28 拍 →
  **55.6 倍余量**（长块那次实测约 **67 倍**）。吞吐从来不是限制条件。
- 上表是 `-mode out_of_context` 综合 + 布局布线的**实测值**，量法见
  `data/results/impl_metrics.md`（65 抽头那一行是早期实测基线，未含后加的 `-DFIR_SHIFT_CHAIN=1` 开关；193 抽头已按该开关重测）。

**乘法器不限流**，这是量出来的结论，不是默认值：限流能省 DSP（限到 64 个还剩 86 个），
但复用会把两个 DSP48 串成一条没有寄存器的长链，100 MHz 下直接崩
（限 64 → WNS −0.620、443 条失败路径；限 96 → −0.138、19 条），**而且更费 LUT**
（3962 → 10443）。200 个 DSP 占板上 90.9%，看着吓人，但整个系统里除了这个 FIR
没有任何东西用 DSP48（DMA、I2S、AXI 互联都是 0 个）。

"降频换面积"这条备选路也量过：限流 64 + **80 MHz** 能过，86 个 DSP，但只剩 **+0.386 ns** 余量，
且它的临界路径 11.589 ns 里有 7.018 ns 是纯走线（逻辑只有 4 级）—— 布得散，靠不住。
所以不用它。

## 二、寄存器表(AXI-Lite)

> **这张表 2026-10-01 重写过。** 原来那一版是**设计意图**（CTRL / STATUS / N_SAMPLES / ID
> 那套手排的寄存器），和 HLS 实际生成的对不上 —— HLS 给 `s_axilite` 口的是一套
> **`ap_ctrl_hs` 协议 + 参数自动分配偏移**的寄存器组，我改不动它的布局。
> 下面这张是**实际生成的那一张**，队友交接记录其出处为 HLS 生成头文件
> `xfir_multiband_hw.h`；仓库中的 `board/scripts/fir_core.py` 与板级 overlay 元数据使用同一寄存器映射。
> 生成头文件本身不在当前仓库快照中。**以生成的 HLS 映射和驱动常量为准。**

| 偏移 | 名字 | R/W | 内容 |
|---|---|---|---|
| 0x00 | `AP_CTRL` | R/W | bit0 `ap_start`(写 1 启动);bit1 `ap_done`(读 1 = 算完,**读后自动清**);bit2 `ap_idle`;bit3 `ap_ready` |
| 0x04 | `GIE` | R/W | 全局中断使能(HLS 固定生成,本设计不用中断) |
| 0x08 | `IER` | R/W | 中断使能位(HLS 固定生成,未用) |
| 0x0c | `ISR` | R/W | 中断状态位(HLS 固定生成,未用) |
| 0x10 / 0x14 | `in_r` | R/W | 输入缓冲区**物理地址**,64 位:低 32 位在 0x10,高 32 位在 0x14 |
| 0x1c / 0x20 | `out_r` | R/W | 输出缓冲区物理地址,64 位:同上 |
| 0x28 | `length_r` | R/W | 本块采样数 |
| 0x30 / 0x34 | `drc_thr` | R/W | 四段的压缩阈值,Q1.15,**每两个挤进一个 32 位字**:0x30 = 段 0/1,0x34 = 段 2/3 |
| 0x38 / 0x3c | `drc_ratio` | R/W | 四段的压缩比,Q1.15,同上排布 |
| 0x40 | `reset` | R/W | 非 0 = 清延迟线(只在整段处理的第一块写 1) |
| 0x48 | `bypass` | R/W | 非 0 = 不做压缩,只输出延迟后的原样(直通检验用) |

**参数必须在写 `AP_CTRL` 之前写完** —— HLS 是在 `ap_start` 那一刻把所有参数口一起锁存的。
写完再改地址或块长,这一块不会有任何变化。

**为什么地址寄存器是这样的**:源码里 `in` / `out` 各写了一条 `-mode m_axi` 指令,
但**光有 m_axi,核去 DDR 用的基地址是写死的(0)** —— 必须再给同一个指针挂一条
`s_axilite` 指令,才会长出 `in_r` / `out_r` 这两个地址寄存器。少了这一步,核根本不知道
该读哪儿。(这正是 2026-10-01 撞出来的坑,`build/hls/directives/v18_axi_shell.tcl` 里有记录。)

**还有个容易想错的地方**:源码里 `in` / `out` 是两条 `m_axi` 指令,但 **HLS 会把同一个
bundle 里的 m_axi 口合并成一个 AXI4-Master**。打包出来的 `component.xml` 里只有一个总线接口
`m_axi_gmem`(顶层 Verilog 里倒还看得见 `m_axi_in_r_*` / `m_axi_out_r_*` 两组线)。
**block design 里认的是 `m_axi_gmem`。**

### 与最初那版设计意图的差异(留着，说明"为什么最后不是那样")

| 原设计意图 | 实际(HLS 生成) | 为什么 |
|---|---|---|
| `CTRL`(0x00)同时管 Start 和 Done | `AP_CTRL` 一个口两者都管,`ap_done` 读后自清 | 原意图里那条"同地址读写会出竞态"的担心**不成立** —— `ap_done` 不是存储位,是读寄存器那一刻算出来的 |
| `N_SAMPLES`(0x08) | `length_r`(0x28) | 位置由 HLS 自动排,改不动 |
| 只读 `ID`(`(N_BANDS<<16)\|N_TAPS`) | **没有这个寄存器** | 抽头数是编译期常量,Python 侧直接写死在 `fir_core.py` 里核对;少一个寄存器不影响功能 |
| 系数烧死在片内 ROM | 同 | 没有变 |
| `BYPASS` 是独立寄存器 | `bypass`(0x48) | 一致 |
| `RESET` 是独立寄存器 | `reset`(0x40) | 一致 |

### Python 侧调用(实际能跑的那段)

模板见 `board/scripts/fir_core.py` —— 那是**唯一**维护寄存器偏移的地方,
别在别的脚本里再抄一份。最小用法:

```python
import numpy as np
from pynq import Overlay, allocate
from fir_core import FirMultiband

ol = Overlay("fir.bit")                 # board/overlay/fir.bit
k  = FirMultiband(ol.fir_multiband_0.mmio)

in_buf  = allocate(shape=(8192,), dtype=np.int16)    # pynq.allocate
out_buf = allocate(shape=(8192,), dtype=np.int16)
np.copyto(in_buf[:n], x)
dt, spins = k.run(in_buf, out_buf, n, reset=True)    # 内部按顺序写完全部寄存器再 ap_start
np.copyto(y, out_buf[:n])
```

整段处理用 `k.process(x, reset=True)` —— 它自动按 8192 点切块,
**只在第一块 reset**(延迟线跨块保持,否则块边界会炸出咔声)。

## 三、外层包装(2026-10-01 已定,见下)

**走的是第三条路,甲和乙都没用。**
核自己当 **AXI4-Master**,经 PS 的 `S_AXI_HP0` 直接读写 DDR;Python 只把缓冲区地址、
块长、参数写进寄存器,然后轮询 `ap_done`。没有 AXI DMA,I2S 那边保持官方的
`audio_codec_ctrl` 不动。

选它的理由:

- **不用改核的数据接口** —— 甲(改官方 IP 内部)要动别人写的 RTL,乙(换 `axi_i2s_adi` + DMA)
  要把核改成流式接口,两条路都会让已经验完的 csim / 拍数 / 时序全部作废。
- **核天然就是"块进块出"** —— 给它两个地址比给它一条流简单得多。
- **HP0 是专门给 PL 的高带宽从口**,接它就是标准做法。

代价与取舍(都写清楚了,免得以后当成"没想过"):

- **边录边放的实时已经跑通**（连续 8/10/24 秒全部 **1.00 倍、一块不丢**），而且**核一个字没改** ——
  没有改成流式接口，`fir.bit` 也没重跑。瓶颈全在 PS 侧 Python：驱动 `play()` 每次调用白花
  3.33 ms 的 8 次 I2C、音频 IP 没有 DMA（收发各空转占一个核）、格式转换写在搬样线程上而那条线程零余量。
- 对「出声 + 拍演示 + 量加速比」这三件事，分块这条路够了。

原来担心的两条,事后都有结论:

| 原来担心的 | 结论 |
|---|---|
| `ap_done` / `ap_ready` / `out_r` 是**组合输出**,外壳里得各打一拍 | **没成立** —— HLS 的 `ap_ctrl_hs` 把这些位放在 AXI-Lite 寄存器里,由读操作算出来,不是裸的组合输出。不需要外壳打拍 |
| 插进 overlay 之后 **WNS 必须重量** | **量了**:整机 WNS **+1.283 ns**、失败端点 0(裸核 OOC 是 **+1.832**)。见 `data/results/impl_metrics.md` |


（原来这里列着"上板前必须补的两条",2026-10-01 两条都有结论了,已并入上面的对照表:
第 1 条不成立、第 2 条量出来了。）

## 四、风险 / 还没定的

- **90.9% 的 DSP 用满了**,只剩 20 个(220 个里用了 200)。现在够用(系统里除了这个 FIR 没有任何东西用 DSP48),
  但如果以后要加"每段增益"、"立体声"或者任何要乘法器的模块,就得回到降频那条路
  (限流 64 + 80 MHz,已实测能过,但只剩 +0.386 ns 余量)。
- **整机时序余量 +1.283 ns**。往 PL 里再加东西(比如给音频通路加 AXI DMA)
  **必须重新量**。加之前先想清楚值不值。
- **BYPASS 位是后加的**,不在原来那份接口约定里。理由写在 §1.1。
- **系数做成 ROM 而不是软件可写**:换频段边界要重新综合。这是刻意的取舍(见 §二),
  但**"运行时可写系数"这条路没试过**,不知道代价多大。真要演示"频段参数化"的话要回头试。
- **段边缘的分离度 −21 dB 够不够** —— 算术上验过(`fir_selftest.py` 直通检验 0 错配),
  **但还没戴耳机听过**。听感这件事只有人能判。
- **边录边放的实时已经跑通** —— `board/scripts/fir_live.py` 连续 8/10/24 秒全部 **1.00 倍、一块不丢**
  (24 秒那档 960000/960000 采样逐位自检通过),**核一个字没改、`fir.bit` 没重跑**。瓶颈全在 PS 侧 Python
  (驱动 `play()` 的 8 次 I2C、音频 IP 无 DMA、搬样线程零余量的格式转换);自编流式音频通路在
  `audio_stream.cpp` + `build_audio_stream.sh`。
- **要加"每段增益"寄存器吗** —— 助听器验配最直观的就是每段增益。
  现在是"阈值 + 压缩比"两档,还没有独立增益,加的话是 4 个寄存器和几个乘法器
  (DSP 只剩 20 个,够,但余量进一步变薄)。
  建议等第一版出声之后(听感过关了)再定。
