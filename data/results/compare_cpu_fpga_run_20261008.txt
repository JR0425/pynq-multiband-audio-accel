========================================================================
同一块板子上：ARM 核跑 vs PL 里的核跑
========================================================================
输入：144000 个采样（3.0 秒 @ 48000 Hz），11 根谱线 100 Hz~4 kHz + 底噪
算法：相减式 4 段 / 193 抽头 / 边界 [500, 1000, 2000] / 阈值 0.1 / 压缩比 0.7

---- A. CPU（Zynq 里的 ARM，float64 + scipy 的 C 实现）----
   跑 3 次取最快：
     3 低通 + 相减（和核同一个算法，**这个才是要用的**）：0.893 秒，单采样 6.199 µs
     4 段各自滤波（旧形状，乘加 4/3 倍，仅作对照）：1.054 秒，单采样 7.317 µs  → 比上面慢 18%
   实时倍率 3.36x（预算 20.8 µs/采样）

---- B. PL 里的核（Q1.15 定点，AXI4-Master 直接读写 DDR）----
   核地址 0x43c10000
   跑 3 次取最快：0.0457 秒（每块 8000 个采样，切了 18 块）
   单采样 0.317 µs   实时倍率 65.69x
   硬件理论上限：28 拍 @ 100 MHz = 0.280 µs/采样
   实测 − 理论  = 0.037 µs/采样，折成每块 **297.1 µs** 的固定开销
      （固定开销 = 写 10 个寄存器 + 2 次 cache flush + 1 次 invalidate + 轮询 DONE）
   → **固定开销占实测的 12%**，它已经不是小数了。
     这一段不是硬件，是 Python 的来回；核变快之后它就成了主项。
     压它只有两条路：块调大（摊薄固定开销），或者改成 PL 连续搬、
     Python 不参与每一块。逐档量法见 fir_chunk_sweep.py。

========================================================================
加速比
========================================================================
   CPU   6.199 µs/采样   (  3.36x 实时)
   核    0.317 µs/采样   ( 65.69x 实时)
   → 核比同一颗芯片上的 ARM 快 **19.5 倍**

   ⚠️ 引用这个数必须带上这四条，否则会虚高：
      1. 两边精度不同 —— CPU 是 float64，核是 Q1.15 定点 16 位。
         核做的是更粗的活，快的一部分是这一条换来的（定点设计的取舍，
         不是 FPGA 白得的便宜）。
      2. CPU 那边是 scipy 的 C 实现，属于「优化过的软件」，不是随便写的。
         也不是极限 —— 手写 NEON float32 的 FIR 还能再快 3~5 倍（估计值，没试过）。
      3. 核的耗时含 Python 写寄存器 + cache 维护 + 轮询，上面已经把这一项
         单独算出来了；块长越小它越重。
      4. 两边工作量对等：都是每采样 579 次有效乘法（核是 3 × 195 = 585，
         尾巴上 6 个是补零）。**这一条以前写错过**，见 data/results/accel_cpu_vs_fpga.md。

   两个都够实时（预算 20.8 µs/采样）。**板子上的账不在吞吐上** ——
   ARM 那个数只是勉强实时，一旦要同时干别的（录音、写文件、跑界面）就顶不住；
   核是**确定性的 0.280 µs**（硬件那一段不随负载变），这才是上硬件的理由。

---- C. 结果对不对（两边精度不同，不能逐位比）----
   输入有效值 0.10706 ｜ CPU 输出 0.10659（1.00 倍）
   CPU 峰值 0.28627 ｜ 核峰值 0.28625
   两边都该是「整体变轻、不削顶」。
