# PL 直连 600 秒长跑 × 2（E3 2026-10-29 / T9 2026-10-31）

稳定性验收里**PL 直连线自己**的两条 600 秒记录。和 `soak600_20261023.md` 不是同一条线：
那份测的是块模式 `fir.bit`（PS 在环里逐块搬样本），这份测的是 `fir_pl.bit`（样本不过 PS）。
两种架构分别记账、不互相归属。

## 结论

**两趟都过。** I2S 溢出与欠载、FIFO 溢出、跳变计数（`POP_CNT`）全程零增长；
板上 XADC 温度 51.7 → 50.9 ℃，内存占用不变。

判据是**“不挂”**（600 秒里服务与网页一直活着、计数不涨），不是“不卡”。
“卡不卡”由 `latency_retest_20261023.md` 和验配页面的延迟读数负责，两件事分开看。

## 两趟

| 趟 | 日期 | 时长 | I2S overrun | I2S underrun | RX FIFO | 结论 |
|---|---|---|---|---|---|---|
| **E3** | 2026-10-29 | **606 s** | **54944 → 54944**（零增长） | 全 0 | 水位稳定 | 过 |
| **T9** | 2026-10-31 | 600 s 档 | 零增长 | 全 0 | 稳定 | 过 |

两处读法，别当成故障：

1. **overrun 的绝对数不小，判据是“不增长”。** 计数器从上电起累计，54944 是这一趟的
   起点读数，终点还是 54944 —— 跑满 600 秒一个新溢出都没有，这才是判据。
2. **T9 只有结论级记录。** 逐秒的时间序列在交付整理时没留下来，只剩“600 秒零增长”
   这一级结论（见下面的「数据出处」）。需要逐项数字时按「复现」重跑一趟即可。

## 判据（`board/probes/soak_pl_600.py` 结尾那组检查，跑完逐条打 PASS/FAIL）

| # | 检查 | 两趟的结果 |
|---|---|---|
| 1 | `age` 最大 < 1 s（live 没卡死） | PASS |
| 2 | 全程无 `stale`、无 `error` | PASS |
| 3 | `running` 全程为真（跳过启动头两拍） | PASS |
| 4 | **采集 overrun 长跑期间不增长**（`ovf[-1] == ovf[1]`） | E3 **54944 → 54944**；T9 零增长 |
| 5 | **播放 underrun 全程为 0** | 全 0 |
| 6 | `ramp_busy` 最终回到 0 | PASS |
| 7 | 输入有起伏（`max > 0`）且未恒满（`min < 30000`） | PASS |
| 8 | 温度末值 − 首值 < 10 ℃ | 51.7 → 50.9 ℃ |
| 9 | 内存末值 > 首值 − 40 MB（无泄漏） | 无泄漏 |
| 10 | 采样过程无异常 | PASS |

另有一条 **INFO（不算判据）**：RX FIFO 水位 `min~max / 4096`，按 48 字/ms 折成采集缓冲毫秒数。
水位稳定指的是这条读数没有单向爬升 —— 起跑阶跃不算异常。

## 复现

```bash
# 板上通路先开着（网页 / curl 点一次 start），然后主机侧：
python board/probes/soak_pl_600.py --secs 600 --json soak_pl.json
```

`--no-start` 表示不动 `/api/start`（通路已经在跑时用）；`--secs 60` 是冒烟档。
脚本每 2 秒采一次 `/api/status` 与 `/api/health`，结束打五条判据。跑之前确认只有自己在用板子 ——
探针的 `Overlay()` 会和守护进程拉起的 live 抢 PL。
