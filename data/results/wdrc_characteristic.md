# WDRC 板上特性曲线

对应验收项：压缩器输入-输出特性。2026-10-23 在出货版 `v25_env_indep` 上实测。

板上 `fir.bit` md5 `5aa079f29e8d66c21d1d34f1302c3695`，与仓库 `board/overlay/fir.bit` 一致。
原始输出两份：`wdrc_curve_run_20261023.txt`（控制台全文）、`wdrc_curve_20261023.json`
（逐档数据，画图用）。

复现：

```bash
cd /home/xilinx/jupyter_notebooks
echo xilinx | sudo -S env XILINX_XRT=/usr \
    /usr/local/share/pynq-venv/bin/python3 -u wdrc_curve.py
```

全部用合成信号，不接麦克风，跑多少遍都是同一串比特。

## 结论

1. **压缩曲线与设计一致**：出厂设置（阈 0.100、压缩比 0.70）在 −6 dBFS 处压 1.6~2.1 dB，
   最狠设置（0.010 / 0.30）压 8.0~8.5 dB，同一设置下四个频段之间相差不超过 0.6 dB。
2. **`wdrc()` 在时间常数趋零时严格退化成无记忆的 `drc()`**，实测差 0.001 dB。
   这是代数恒等式（`env == |x|` 时两式相等），板上对上了就说明包络这条通路没写错。
3. **真实时间常数下，输出比静态曲线算出来的轻 0.2~1.6 dB**。原因是包络追不到瞬时峰值。
   压得越重差得越多，四个频段方向一致。
4. **Q1.15 的步进存不下慢时间常数**：写 500 ms 实际是 683 ms，写 200 ms 实际是 228 ms。
5. **`wdrc()` 有固有失真**，压缩越重越大：−6 dBFS 下，无记忆 4.1%、出货设置 24.5%、
   最狠设置 45.0%。
6. **「压缩比」是幅度上的比例，不是 dB 上的**：参数写 0.30，实测 dB 斜率是 0.85~0.95。
   不要把 0.30 当成 dB 上的比例来解释。

## A. 静态传输曲线

13 档单音阶梯，峰值电平 −6 → −54 dBFS（每档 4 dB），每档 1.6 秒、取后 0.6 秒稳态。
四个频点各跑一遍，每个频点只落在一个频段里（段边界 500 / 1000 / 2000 Hz）。

每组阈值/压缩比都跑三条包络设置：

- 无记忆（attack = release = 0）—— 核里走 `drc()` 分支，是解析基准
- 包络极限（0.001 ms）—— `env` 几乎等于 `|x|`
- 真实时间常数

### 判据 1：时间常数趋零时，WDRC 就是无记忆压缩

`env == |x|` 时

    |x| − (|x| − thr)(1 − ratio)  ==  thr + (|x| − thr) · ratio

两式代数上恒等。实测四组配置的最大偏差：**0.0010 dB**（多数档位 0.0000 dB）。

这条对上了，就说明 `env` 的更新、`gr` 的算法、阈值的定点定标都是对的。
它是整节唯一要求"必须相等"的判据。

### 判据 2：阈值以下原样通过

参考用**直通输出**，不用原始输入。低电平时峰值只有几十个 LSB，输入量化
和滤波器系数量化本身就能吃掉 0.1 dB，拿原始输入当参考会把这笔账算到压缩器头上。

判据也用 LSB 绝对差而不是 dB：−54 dBFS 时峰值只有 65 个 LSB，差 1 个 LSB 就是 0.133 dB。
实测最大差 **1.00 个 LSB**，来自非直通路径比直通多一次的
`(drc_t)band[i] * g[i]` floor。

### 判据 3：输出随输入单调。四组配置、四个频点全部通过。

### 压缩量（相对直通，−6 dBFS 处，dB）

| 设置 | 阈 | 压缩比 | 250 Hz | 700 Hz | 1400 Hz | 4000 Hz |
|---|---|---|---|---|---|---|
| 出厂 .100/.70 | −20.0 dBFS | 0.70 | 1.9 | 1.6 | 2.1 | 2.1 |
| thr.030 r.50 起5/停100 | −30.5 dBFS | 0.50 | 4.4 | 4.2 | 4.8 | 4.8 |
| thr.030 r.50 起20/停200 | −30.5 dBFS | 0.50 | 4.2 | 3.9 | 4.6 | 4.5 |
| 最狠 .010/.30 | −40.0 dBFS | 0.30 | 8.3 | 8.0 | 8.5 | 8.4 |

### 阈值以上的斜率不是 0.70 / 0.50 / 0.30

`drc()` 是**幅度**上的仿射变换 `thr + (|x| − thr) · ratio`，不是 dB 上的。
换算成 dB 斜率是

    d(out_dB) / d(in_dB)  =  (|x| / out) · ratio

输入越大，`|x| / out → 1 / ratio`，dB 斜率就越接近 1。实测量到的斜率
（−6 → −10 dBFS 这一段，四个频段）：

| 设置 | 参数 ratio | 实测 dB 斜率 |
|---|---|---|
| 出厂 .100/.70 | 0.70 | 0.90 |
| thr.030 r.50 | 0.50 | 0.88~0.95 |
| 最狠 .010/.30 | 0.30 | 0.85~0.95 |

所以"压缩比 0.30"**不是**"输入涨 10 dB 输出涨 3 dB"。它指的是幅度，
而且只在阈值附近才接近 0.30。引用这个参数时不要当成 dB 上的比例。

（斜率按压缩量小的那几档更接近 ratio：`ratio` 是拐点处的切线值，
信号越大越偏离。要写"压扁了多少"，直接给上表的 −6 dBFS 压缩量。）

### 包络滞后造成的轻压

真实时间常数下，输出峰值比无记忆曲线**高**（压得更轻）。−6 dBFS 处：

| 设置 | 250 Hz | 700 Hz | 1400 Hz | 4000 Hz |
|---|---|---|---|---|
| 出厂 .100/.70 | +0.26 | +0.22 | +0.29 | +0.31 |
| thr.030 r.50 起5/停100 | +0.65 | +0.60 | +0.67 | +0.73 |
| thr.030 r.50 起20/停200 | +0.87 | +0.81 | +0.90 | +1.05 |
| 最狠 .010/.30 | +1.48 | +1.42 | +1.51 | +1.63 |

原因是包络是滞后的一阶平滑，稳态下停在瞬时峰值**下面**一点。波峰那一刻
`env < |x|`，减掉的 `gr` 就比静态曲线预测的小。压得越重、时间常数越慢，
差得越多。

这不是实现错误，是峰值检波加一阶平滑的必然结果。结论按这一条写，
不要写成"静态曲线与实测一致"。

## B. 阶跃响应

−20 dBFS → −10 dBFS → −20 dBFS，两段静音各 2.5 秒（release 500 ms 要 4~5 倍
时间常数才落回基线），响段 1.2 秒。

压缩量 `gr` 从输出反推：`gr = 输入峰值 − 输出峰值`，输入峰值取**直通**那一路。
`gr = (env − thr)(1 − ratio)` 对 `env` 是线性的，所以 63% 点直接对应时间常数。

### ① 直流阶跃：验寄存器写对了没有

`|x|` 恒定 → `diff` 的符号恒定 → 包络是严格一阶，63% 点就是时间常数。

| 写的 | Q1.15 实际能表示 | 量到 |
|---|---|---|
| 起 5 ms | 5.0 ms | 5.48 ms |
| 起 20 ms | 20.1 ms | 20.51 ms |
| 起 50 ms | 48.8 ms | 49.09 ms |
| 停 100 ms | 97.5 ms | 96.91 ms |
| 停 200 ms | 227.5 ms | 224.91 ms |
| 停 500 ms | **682.7 ms** | 634.56 ms |

三档攻击误差都在 10% 以内，释放 500 ms 那档差 7%（最慢那档的段只有 2.5 秒，
基线还没完全落回，偏早是预期内的）。

**表里第二列是要单独说的**：48 kHz 下 Q1.15 的平滑步进 `step = 1 − exp(−1/(τ·fs))`，
`step = 1` 时 τ 已经是 683 ms，再慢就表示不了。写 500 ms 得到的是 683 ms，
写 200 ms 得到的是 228 ms（+14%）。界面上如果要让用户输毫秒，
超过约 150 ms 之后实际值和输入值就对不上了。

### ② 正弦阶跃：量实际的有效响应时间

4 kHz 单音。这一节不是判据，是测量结果。倍数一律**相对直流阶跃同一设置的可表示值**
（5.01 / 20.07 / 48.75 ms 和 97.51 / 227.55 / 682.66 ms），这样比较不受 Q1.15 量化干扰。

| 写的 | 量到攻击 | 对写值 | 量到释放 | 对写值 |
|---|---|---|---|---|
| 5 / 100 ms | 10.71 ms | +114% | 77.00 ms | −23% |
| 20 / 200 ms | 35.92 ms | +80% | 184.13 ms | −8% |
| 50 / 500 ms | 88.11 ms | +76% | 545.18 ms | +9% |

换成相对可表示值：攻击 2.14 / 1.79 / 1.81 倍，释放 0.79 / 0.81 / 0.80 倍。
释放那一栏的 "+9%" 是错觉——写 500 ms 实际只能表示 683 ms，和 683 比仍是 0.80 倍。

两个方向都偏离，机制是同一个：包络只有在 `|x| > env` 时才往上追，而那一段
集中在波形靠近峰值的地方。

- **攻击慢一倍**：`env` 越接近峰值，每周期里 `|x| > env` 的时间越短，
  能追的时间越少。主机上直接从 `env` 抽出来量过：写 5/20/50 ms 分别是
  9.81 / 34.56 / 86.33 ms，和板上从输出反推的 10.71 / 35.92 / 88.11 一致。
- **释放快 20%**：远离峰值的那段时间 `|x|` 远小于 `env`，包络按 `rel` 往零走；
  快到零时才被波峰托住。所以"到最终渐近值的 63%"这个点比单指数模型更早到。

**结论：单音信号没有唯一的时间常数。** 如果要给"攻击/释放时间"这个数，
用直流阶跃那组（那是寄存器真正写进去的值），并把正弦下的偏一栏单列。

## C. 失真

`wdrc()` 减的是**瞬时幅度**（`a2 = a − gr`，再钳到 0），不是乘系数。
所以压缩一重，波形低幅的部分会被削成一段死区。700 Hz 单音，稳态窗口算 2~10 次谐波。

| 峰值电平 | 无记忆 .030/.50 | thr.030 r.50 | 最狠 .010/.30 |
|---|---|---|---|
| −40 dBFS | 0.041% | 0.041% | 0.041% |
| −30 dBFS | 0.010% | 0.010% | 18.233% |
| −20 dBFS | 7.222% | 13.764% | 28.220% |
| −12 dBFS | 4.816% | 18.987% | 38.329% |
| −6 dBFS | 4.144% | 24.510% | 45.032% |

读法三条：

- **阈值以下失真为零**（−40 dBFS 的 0.041% 是测量底噪，不是失真）。
- **无记忆那组在 −20 dBFS 有 7.2%，不是 bug**。`drc()` 本身就是折线整形器，
  阈值 0.030 = −30.5 dBFS，−20 dBFS 正好落在拐点附近，压的是波峰那一小段。
- **WDRC 的失真随压缩量单调上升**，−6 dBFS 下 45.0% 对无记忆的 4.1%。
  死区占峰值比例（理论值）和 THD 同步上升：3% → 47% 对应 0.01% → 24.5%
  （thr.030 那组），48% → 69% 对应 18.2% → 45.0%（最狠那组）。

这是算法形式的固有代价，不是定点引起的（同一套公式在 float 下预演，THD 一样）。
**上面整张表是模型域、段增益 1.0 的结论。** 板上演示默认是段增益 +22 dB，会把信号抬到门限
以上持续压缩：2026-10-31 板上实测同一音源 THD+N 9.13%（只开限幅 7.7%、深压 37.7%，
关压缩 0.07% 等于输入底噪），见 `thdn_localization_20261031.md`。所以「默认设置下听不到这个
失真」只对模型域的单位增益成立，板上的默认工况一直在压，不能照搬这句话。

## 已知限制

- 只测了四个单音频点，没有测多音互调。
- 增益 `band_gain` 全程是 1.0（默认值），没测非单位增益下的压缩曲线。
- 时间常数的段长按最慢的 500 ms 配的；再慢的时间常数（比如 2 s）用这套段长会量不准。
- Q1.15 步进快端也有限制：`step` 最大 32767/32768，对应 τ ≈ 0.002 ms（2 µs）。
  A 节用的"包络极限"写 0.001 ms 已经顶到这个上限，实际 τ 是 0.002 ms，
  所以那个判据成立的前提是"包络带宽 80 kHz ≫ 信号带宽"，不是真的无限快。
