==============================================================================
  ==== 结论 ====
==============================================================================

1. **只降 boost 不够。** fix_boost0_dv21 就是"只写 R5/R7=0x08"那个状态,三遍里
   一遍 65491。注意 cap_probe6 的 gain_0dB 是**同一个寄存器状态**,那边三遍全静
   (154/107/165)—— 同一个状态两次跑结论相反,正是 probe6 结论里说的"环路增益
   刚刚超过 1"的双稳态。**所以这个状态不能当修法用**,哪怕它有一半时候是好的。

2. **最干净的是 boost 0 dB + 输入 +27 dB(R5/R7=0x08, R8/R9=0xD3),三遍全静。**
   +30/+33 各有一遍抬到 ~1100-1200,+35.25 三遍都在 ~1000 —— 都还没到满幅,
   但明显离开安静区,说明这几档更靠近阈值。取 +27 留余量。

3. **两级都得写。** 光写 R5/R7 是"看起来治了",实际三遍里还会翻。

4. 灵敏度账:原来 PYNQ 默认 +41 dB(boost +20 叠输入 +21),现在 +27 dB,
   掉了 14 dB;离满幅自激那一档(+41)有 14 dB 余量。说话够不够用**必须戴耳机听一遍**,
   这是下一步。

5. 有一个**没解释的**现象:+35.25 dB 那一档比 +33 dB 还高 5 倍,而不是更低
   (如果只是"增益越大环路越容易自激",应该单调)。三遍都在 ~1000 且不冲满,
   所以不是自激,更像一个电平被压住的极限环。**没有继续追**——只要 +27 dB 这档
   三遍都稳,修法就够用;这条记下来,万一以后灵敏度不够要往上抬时先回来看它。

==============================================================================
  ==== 修法(已落到 board/scripts/fir_live.py) ====
==============================================================================

    lib.stream_reg_write(0x0B, 0x08, IIC)   # R5 左:PGA boost +20 -> 0 dB
    lib.stream_reg_write(0x0D, 0x08, IIC)   # R7 右
    lib.stream_reg_write(0x0E, 0xD3, IIC)   # R8 左:差分输入 +21 -> +27 dB
    lib.stream_reg_write(0x0F, 0xD3, IIC)   # R9 右

写这四行的前提是板上那份 .so **已经重编过**(见上面第一步),否则调用即崩。
