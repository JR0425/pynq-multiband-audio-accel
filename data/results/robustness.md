# 鲁棒性测试表

对应验收项：异常输入下的行为。2026-10-23 在出货版 `v25_env_indep` 上实测。

板上 `fir.bit` md5 `5aa079f29e8d66c21d1d34f1302c3695`。
原始输出 `robustness_run_20261023.txt`，逐项数据 `robustness_20261023.json`。

复现：

```bash
cd /home/xilinx/jupyter_notebooks
echo xilinx | sudo -S env XILINX_XRT=/usr \
    /usr/local/share/pynq-venv/bin/python3 -u robustness.py
```

**这节要回答的问题**：把输入推到极端、把参数拧到 16 位的两端、
把块长切到 1，核会不会崩、卡死、或者把数绕回去。
不回答"精度够不够"（那是第 3 项的事），也不回答"长时间稳不稳"（那是 10/26 的 600 秒）。

## 结论

1. **十种极端输入下，直通路径逐位正确**（48 万采样，0 个错），
   包括满幅方波、−32768 直流、Nyquist、满幅白噪声、单点脉冲。
   压缩路径全部跑完且有输出，两种纯直流输入输出符号不翻。
2. **输出级带饱和，不会绕回。** 直流从 0 扫到 32767，输出单调升到 23920；
   每段增益从 0 扫到 +42 dB，峰值单调升到满量程后停住，没有出现"正数变负数"。
3. **块长 1 ~ 8192 逐位一致**，包括每块只有 1 个采样、一共 4096 块这种切法。
   超过 8192 被驱动拒绝（`ValueError`），不会让核去越界搬内存。
4. **参数越界不崩，但结果没有意义。** 负压缩比在无记忆路径下**会把波形反相**
   （39% 的采样符号相反），在 WDRC 路径下会把输出压死；负阈值会把过零点抬到
   −0.3（满量程的 30%）。界面上这三类值都到不了，只有直接写寄存器才碰得到。
5. **状态是对的**：同一输入两次 reset 逐位相同；不 reset 接着跑结果确实变了
   （延迟线在跨块传递）；反复 reset 200 次不挂、末次与首次逐位相同。
6. **一个界面与硬件对不上的地方**：网页的 release 滑杆能拖到 1000 ms，
   但核里 Q1.15 最慢只表示到 683 ms（第 3 项测的），拖过约 683 ms 之后数值不再变。

## A. 输入边界

每个用例 1 秒（48000 采样），跑两遍：一遍直通、一遍默认压缩。

判据两条：直通输出必须**逐位等于输入延后 96 拍**；压缩输出必须**非零且符号对**
（纯直流输入不许翻号）。

| 输入 | 直通逐位 | 压缩后峰值 | 说明 |
|---|---|---|---|
| 全零 | ✅ 0 错 | 0 | 输出整段为 0 |
| 单点脉冲 +32767 | ✅ 0 错 | 24741 | 冲激响应 189 个非零采样（≈193 抽头） |
| 满幅方波 ±32767 @1 kHz | ✅ 0 错 | 26869 | 最坏的带内能量分布 |
| 0 dBFS 正弦 @1 kHz | ✅ 0 错 | 26152 | |
| +32767 直流 | ✅ 0 错 | 26784 | 符号不翻 |
| −32768 直流 | ✅ 0 错 | 26786 | 16 位最负值，符号不翻 |
| 正弦 +0.25 直流偏置 | ✅ 0 错 | 14983 | 检查直流分量不会被压缩器放大 |
| Nyquist +20000/−20000（隔点交替） | ✅ 0 错 | 15233 | 最高频，滤波器阻带 |
| 1 Hz 正弦 | ✅ 0 错 | 14984 | 比 release 时间常数还慢 |
| 满幅白噪声 | ✅ 0 错 | 26823 | |

**这里只验性质，不验数值。** 极端输入下没有独立参考可以逐位对压缩输出，
硬定一个逐位判据等于拿实现证明实现。逐位那一条放在直通路径上 ——
它是唯一有解析答案的（延迟 96 拍的输入本身）。

## B. 满幅扫描：查绕回

输出级是 `(data_t)acc`，`data_t` 是 `ap_fixed<16,1,AP_TRN,AP_SAT>`，
按定义会饱和到 ±满量程，不会像整数强转那样绕回。这一节是把这个性质**量出来**。

### B1 直流电平 0 → 32767（默认参数：阈 0.100、压缩比 0.70）

| 输入 | 输出 |
|---|---|
| 0 | 0 |
| 1000 | 999 |
| 2000 | 1999 |
| 4000 | 3783 |
| 8000 | 6583 |
| 12000 | 9383 |
| 16000 | 12183 |
| 20000 | 14983 |
| 24000 | 17783 |
| 28000 | 20583 |
| 32000 | 23383 |
| 32767 | 23920 |

单调不减，满幅输入输出仍是正数（23920）。若发生绕回，32767 附近会突然跳成负数。

### B2 每段增益 0 → 32767（0.5 正弦）

| 增益（Q7.8） | 分贝 | 输出峰值 |
|---|---|---|
| 0 | −∞ | 0 |
| 128 | −6.0 | 8119 |
| 256 | 0.0 | 14318 |
| 512 | +6.0 | 26153 |
| 1024 | +12.0 | 32768（饱和） |
| 2048 ~ 32767 | +18 ~ +42 | 32768（饱和） |

单调不减，到满量程后停住。**−6 dBFS 的信号，每段增益到 +12 dB 就顶满了** ——
这不是 bug，输出就这么大；再往上加只会在输出级削顶。

### B3 负增益

增益 −1.0 与 +1.0 的输出峰值是 14319 / 14318（差 1 个 LSB，来自 Q2.22 截断）。

## C. 块长

同一段 4096 采样、同一组参数（阈 0.030、压缩比 0.50、起停 5/100 ms），
按不同块长切开跑，结果与"一整块 8192"逐位比较。

| 块长 | 块数 | 与整块比 |
|---|---|---|
| 1 | 4096 | ✅ 0 错 |
| 2 | 2048 | ✅ 0 错 |
| 17 | 241 | ✅ 0 错 |
| 64 | 64 | ✅ 0 错 |
| 157 | 27 | ✅ 0 错 |
| 1024 | 4 | ✅ 0 错 |
| 8192 | 1 | ✅ 0 错 |

块长 1 是最狠的一条：每一块只有一个采样，延迟线和包络必须完全靠寄存器跨块保持。
逐位相同说明"分块处理"这件事在驱动层之外没有引入任何状态错误。

超过 8192（`m_axi` 声明的深度）时 `run()` 抛 `ValueError`，不会把越界的长度写进核。

## D. 参数边界

输入是 0.5 的正弦（1000 Hz）。

| 用例 | 结果 | 说明 |
|---|---|---|
| D1 阈 0 / 压缩比 0 | ✅ 末段峰值 0 | 上式退化成 `y = 0 + (a−0)·0 = 0`，全压成静音 |
| D2 阈 32767 / 比 32767 | ✅ 与直通差 1 LSB | 永不触发，等于直通（差的那个 LSB 是 Q2.22 截断） |
| D3 阈 0 / 比 32767 | ✅ 与直通差 1 LSB | 压缩比 0.99997，几乎不动 |
| D4a 压缩比 −32768（无记忆） | ✅ 有界，**39% 采样反相** | `y = 2·thr − a`，输出被翻转 |
| D4b 压缩比 −32768（WDRC） | ✅ 有界，末段被压死 | `gr = 2(env−thr)`，衰减量翻倍 |
| D5 阈值 −32768 | ✅ 有界（饱和到满量程） | `y = 0.7a − 0.3`，过零点被抬到 −0.3 |
| D6 起停 0.001 ms（最快） | ✅ 与无记忆差 0.0000 dB | 包络一步追上，退化成无记忆 |
| D7 起停 1e9 ms（最慢） | ✅ 不崩 | 实际步进饱和到 1（683 ms） |
| D8 四段参数全不同 | ✅ 不崩 | 阈 0/983/16384/32767，比 16384/9830/32767/0 |
| D9 四段增益 0/1/−1/max | ✅ 不崩 | |

**D4/D5 的意义不是"能跑"，而是圈出参数的有效范围。** 压缩比必须落在 [0, 1]，
阈值必须是非负；超出之后核照样跑完、输出照样有界，但波形已经是坏的。
网页那边已经夹住了（`ratio ∈ [0, 0.95]`、`thr_db ∈ [−60, 0]`），
所以这三类值只有直接摸寄存器才会出现。

D6 那条顺带把第 3 项的恒等式在极端参数下又验了一遍：0.0000 dB。

## E. 状态

| 用例 | 结果 |
|---|---|
| E1 同一输入、两次都 reset | ✅ 逐位相同 |
| E2 不 reset 接着跑 | ✅ 结果确实变了（4800 个采样里 168 个不同） |
| E3 反复 reset 200 次（每次 256 采样） | ✅ 不挂，末次与首次逐位相同，用时 11.6 秒 |

E2 用的是默认参数（起停时间 0 → 无记忆分支，核里没有包络状态），
所以这 168 个差异全部来自**延迟线**跨块传递，约等于 96 拍群延迟加上滤波器拖尾。
**包络的跨块保持由 C 组证明**：C 组开着起停时间、把块切到 1 个采样，
仍然与整块逐位相同 —— 包络若有一块没接上，那里立刻就会出现差异。

E3 的 11.6 秒主要是 Python 每次调用重新申请 DMA 缓冲的开销（约 58 ms/次），
不是核的处理时间；单次核调用约 1.3 ms（4096 次调用 5.5 秒）。
实时路径是一次分配反复用，不受这个影响。

## 发现的问题

**网页的 release 上限和硬件对不上。** `fir_webui.py` 把 `release_ms` 夹在 [0, 1000]，
但核里 Q1.15 的平滑步进最慢只到 683 ms（`step = 1`）。拖动滑杆超过约 683 ms 之后，
声音不再变化。

**已于 10-23 当天改掉**：界面滑杆上限 `page.html` 的 `max` 改成 680，
服务端 `_apply_tune` 的夹取范围改成 [0, 680]，笔记本界面 `w5_tuning_ui.ipynb`
的滑杆上限和「很慢」预设（原 20 / 1000）也一起改到 680。验证过
`release_ms = 1000` 的请求写进去读回来是 680，浏览器里拖到底显示 680 ms。

同一段代码里 `attack_ms` 夹在 [0, 200]，而核的最快约 0.002 ms，不存在这个问题。

## 已知限制

- 只跑了合成信号；真实语音的长时间压力测试见 `soak600_20261023.md`（2026-10-23 补做，600 秒 × 2 趟）。
- 没有测温度、供电波动下的行为。
- 边界用例都是"单次跑完"，不构成对板子死机问题的证据 —— 那是另一条线
  （见 `board_hang_evidence_20261017.md`）。
- D 组的越界参数只在直接写寄存器时可达；界面上到不了，所以这些不是用户能触发的故障。
