# 深度压缩下的长稳（2026-11-02）

11-02 那趟 605 秒长跑用的是演示音源，压缩器全程空闲（进出核峰值恒定）。判据全 PASS 只能说明通路与调度稳定，不能说明压缩器持续工作时也稳。本文记录让压缩器全程工作的两趟：先跑 300 秒，再跑满 600 秒。

## 配置

- 音源：`tone1001_full.wav`（1 kHz 满幅单音，循环播放）
- 参数：增益 +24 dB，门限 −40 dBFS，压缩比 0.5（即 2:1），attack 5 ms，release 100 ms，MPO −6 dBFS
- 探针：`board/probes/soak_pl_600.py --secs 600 --no-start`
- 原始数据：`soak_pl_deep_20261102.json`（300 秒、150 点）、`soak_pl_deep600_20261102.json`（600 秒、300 点）

## 压缩器确实在工作

| 观察量 | 600 秒那趟 | 说明 |
|---|---|---|
| 进核峰值 | 803（全程恒定） | 满幅音源经板载播放 −32 dB 衰减后的固定电平 |
| 出核峰值 | 7211—7225，中位 7224 | 不再是空闲时的恒定值 |
| 有效增益 | 7224 / 803 = **19.08 dB** | 设定 +24 dB，压掉约 **4.9 dB** |
| 二段包络 | −14.4 dBFS | 比门限 −40 dBFS 高 25.6 dB |
| 压缩比读数 | 2.0 | 与设定 0.5（2:1）一致 |

只记 `gr0`（第一段）时读数为 0 是正常的：1 kHz 单音落在第二段，第一段没有信号。

## 判据结果（600 秒，300 点）

脚本逐条打印的 12 条检查全 PASS，另有一条 FIFO 水位 INFO：

- 存活：`age` 最大 0.20 s
- 采集 overrun 0 → 0，播放 underrun 恒 0，RX FIFO 溢出与跳变 0（水位 0—1 / 4096）
- `ramp_busy` 最终归零，无 stale、无 error
- 温度 54.0—55.5 ℃（首 54.4 → 末 54.8）
- 内存 311—315 MB（无单调增长）

300 秒那趟的读数在同一区间（出核峰值 7214—7241，温度 53.0—55.1 ℃），两趟互不冲突。

## 完整记录里的一次源侧毛刺

300 个采样点里有一个点（t = 327.5 s）出核峰值为 **10055**，其余点都在 7211—7242。同一时刻所有计数器仍是零，进核峰值仍是 803。

查 `/tmp/live.log`，整趟只有一条：

```
PLAYLATE 0.021 pos=16220160
```

播放线程这次迟到 21 ms（写位置 16220160 采样 ÷ 48.828 kHz = 332.2 s），波表环里被重复读了一截，音源出现一次相位跳变。滤波器对这个跳变有瞬态，压缩器的包络按 5 ms attack 来不及跟上，于是那一个 16 ms 计量窗口的输出峰值高出约 2.9 dB。这是**音源侧**的事件：

- 进核峰值不变（803），说明进核的数字样点仍在满幅正弦范围内；
- out/overrun/underrun/FIFO 计数全部零；
- 300 秒那趟没有出现（最大 7241）。

它不进判据（判据看的是计数不增长，不是峰值恒定），但如实记在这里。

## 边界

- 600 秒，不是更长；结论是「压缩器连续工作时，600 秒内无溢出、无欠载、无泄漏」，不外推。
- 单音不是语音，测的是调度与计数，不是听感，也不覆盖包络快速起伏下的行为。
- 与 605 秒那趟分工不同：那趟证明长时间通路的稳定性，这两趟补上「压缩器确实在动」。
