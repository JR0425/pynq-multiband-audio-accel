# 干声并联能不能救深压档的失真（2026-11-02，离线整数模型）

## 为什么做

板上深压档（+24 dB / −40 dBFS / k=0.5）THD+N **37.24%**，机制是 `fir_drc4.v` 的减法式压缩
`y = sign(a)·max(0, |a| − gr)` 在零交叉附近留了一段死区。改成乘法式增益要动 DSP（剩 3 个）
和乘法槽（剩 6 槽），当前时序 slack 已经是 **−0.090 ns**，动不起。

另一条路是干声并联：把干净的干声和压缩后的湿声按比例相加。这里有个岔口——干声取在段增益的
前面还是后面，差别很大，所以两组都跑：

| 组 | 干声 | 硬件代价 |
|---|---|---|
| 甲 | `dry = x[i−96]`，取 `fir_mb_fe` 的段和（增益之前） | 现成的，不改 RTL |
| 乙 | `dry = g_lin · x[i−96]`（增益之后） | 多一个乘法器 |

湿路带 +24 dB 段增益，出核峰值 7225；甲组的干声峰值只有 803，差约 19 dB。如果只跑乙组，
m=0.5 时干声和湿声差不多响，看起来方法很好用——但那是加了乘法器之后才有的效果。

## 方法

模型：`sim/model/ref_model_wdrc.py`（逐位对齐 HLS 核）。扫描脚本 `sim/model/mix_sweep.py`。

1. **快路自检**：3 个低通改成 numpy int64 卷积，DRC 仍逐点。在 512 点随机噪声和 512 点单音上
   和原 `process()` 逐点比对，**1024/1024 全部相同**。原函数没改，逐位自测照旧。
2. **激励**：1 kHz 整数周期单音，f = 21 × 48828.125 / 1024 = 1001.36 Hz，峰值 803 计数
   （对齐板上入核电平），48828 点（1 秒）。
3. **混合**：`y = (1−m)·dry + m·wet`。延迟 96 拍是为了对齐湿路的群延迟（3 级 193 抽头 FIR），
   不对齐就是梳状滤波。`bsum = br0+br1+br2+br3` 的四个分支相加正好还原成延迟后的输入
   （`fir_mb_fe.v:375`），所以甲组不用改 RTL 就能拿到。
4. **测量**：直接用 `board/probes/thdn.py` 的 `thdn()`，最后 3 帧 1024 点取中位。峰和 rms 也取
   这 3072 点；取整段会把启动瞬态算进去（包络还没建立，那一下的峰值是线性满幅）。
5. **参数换算**：`fir_pl_live.py` 的 `db_to_gain` / `dbfs_to_thr` / `ratio_to_reg` / `ms_to_coef`。
6. **表头两项**：「相对线性」= 输出 rms 相对"只放大、不压缩"掉了多少 dB，就是这一档实际压掉了
   多少；「拉到湿声电平 +dB」= 把这一条 mix 提到纯湿声的 rms 需要补多少。THD+N 和电平无关，
   补不补都一样，补一下是为了看峰值会不会顶满量程。

## 判读

### 甲：能不花代价直接做的，但没有用

1. **THD 几乎没动**。m=0.5 时 37.17% → 32.75%，只掉了 4.4 个百分点。原因是干声比湿声低
   19 dB，`(1−m)·dry` 在 m=0.5 时只占约 1.6% 的能量，湿声里的死区还在那儿。要掉到 16.78%
   得把 m 压到 0.1，那时输出等于一份没放大、也没压缩的干声。

2. **还会白白丢电平**。m=0.5 时输出 rms 2470，比纯湿声低 5.0 dB，比"只放大不压缩"低 11.2 dB。
   补回湿声电平要 +5 dB 的增益，THD+N 不变（这个指标和电平无关），所以补了也是 32.75%。

3. **不会顶满量程**。等响后峰值 7140，离 32767 很远。所以这条路安全，只是没收益。

### 乙：有用，但要再加一个乘法器

1. **THD 掉得干脆**。m=0.5 从 37.17% 到 11.84%，降到三分之一。

2. **不花响度**。所有 mix 拉到湿声电平要的都是负增益（m=0.5 时 −3.6 dB），等响后峰值 6608，
   离满量程也远。THD+N 与电平无关，这条只说明不用额外留余量。

3. **代价是压缩量，大致一比一**。相对线性从 −6.2 dB 掉到 −2.7 dB，m=0.5 只保留 43% 的压缩；
   波峰因数从 4.3 dB 回到 3.5 dB，动态也一起回来了。深压本来就是为了在小音量下抬可懂度，
   把压缩让出去等于目的没达成。

4. **比单纯少压一点划算，但只划算 25%**。按"每保留 1 dB 压缩换多少失真"算：m=1 是 6.0 %/dB，
   m=0.5 是 4.4 %/dB，m=0.3 是 4.1 %/dB。没有量级差别。

5. **要到能听的程度得让掉大部分压缩**。THD 低于 4% 需要 m ≤ 0.2，这时相对线性只剩 −1.0 dB，
   等于关了压缩器。

### 两组的差别

同样 m=0.5，甲组 32.75%、乙组 11.84%。差这么多不是方法本身的问题，是干声取错了地方：
乙组的干声跟着 +24 dB 段增益一起放大，才和湿声接得上。两条路在 −20 dBFS 档也是这个规律
（甲 8.62% / 乙 4.25%）。

所以：

- 甲组**不改 RTL 就能做**（`bsum` 是现成的），但压不下来失真，不值得做。
- 乙组**要再加一个乘法器**，有效，但换来的仍是"拿压缩换失真"。

## 结论

只做甲组等于白做：不花硬件，也不解决问题。乙组在模型上成立（不削顶、不用加增益），但它本质是
**拿压缩换失真**，m=0.5 时用 57% 的压缩量换掉 2/3 的 THD。要真救 37% 这个数，还是得改乘法式
增益；并联最多算个"客户不要那么狠的压缩"时的折中档。

从硬件看乙组也不便宜：多一条 96×16 bit 的延迟线（一个 BRAM18 都用不到十分之一）、一个乘法器
和一个加法器，而 `fir_drc4` 的路径 slack 已经是 −0.090 ns。除非 DRC 本身要重写，否则不建议
为并联单独动 RTL。
