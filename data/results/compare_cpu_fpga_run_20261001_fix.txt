========================================================================
同一块板子上：ARM 核跑 vs PL 里的核跑
========================================================================
输入：144000 个采样（3.0 秒 @ 48000 Hz），11 根谱线 100 Hz~4 kHz + 底噪
算法：相减式 4 段 / 193 抽头 / 边界 [500, 1000, 2000] / 阈值 0.1 / 压缩比 0.7

---- A. CPU（Zynq 里的 ARM，float64 + scipy 的 C 实现）----
   跑 3 次取最快：
     3 低通 + 相减（和核同一个算法，**这个才是要用的**）：0.881 秒，单采样 6.116 µs
     4 段各自滤波（旧形状，乘加 4/3 倍，仅作对照）：1.041 秒，单采样 7.232 µs  → 比上面慢 18%
   实时倍率 3.41x（预算 20.8 µs/采样）

---- B. PL 里的核（Q1.15 定点，AXI4-Master 直接读写 DDR）----
   核地址 0x43c10000
   跑 3 次取最快：0.6490 秒（切了 18 块）
   单采样 4.507 µs   实时倍率 4.62x
   理论吞吐：450 拍 @ 100 MHz = 4.500 µs/采样（实测 4.507，差 0.2%）
   → 实测贴着理论值，说明 Python 写寄存器和 cache 维护的开销在这个规模下可以忽略。

========================================================================
加速比
========================================================================
   CPU   6.116 µs/采样   (  3.41x 实时)
   核    4.507 µs/采样   (  4.62x 实时)
   → 核比同一颗芯片上的 ARM 快 **1.4 倍**

   ⚠️ 引用这个数必须带上这三条，否则会虚高：
      1. 两边精度不同 —— CPU 是 float64，核是 Q1.15 定点 16 位。
         核做的是更粗的活，快的一部分是这一条换来的（定点设计的取舍，
         不是 FPGA 白得的便宜）。
      2. CPU 那边是 scipy 的 C 实现，属于「优化过的软件」，不是随便写的。
      3. 核的耗时含 Python 写寄存器 + cache 维护（上面那行证明它很小）。

   两个都够实时（预算 20.8 µs/采样）。**板子上的账不在吞吐上** ——
   ARM 那个数只是勉强实时，一旦要同时干别的（录音、写文件、跑界面）就顶不住；
   核是**确定性的 4.5 µs**，不随系统负载变。这才是上硬件的理由。
