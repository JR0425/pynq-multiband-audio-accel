# PYNQ-Z2 直连 Windows 笔记本:从零到打开 Jupyter 的避坑清单

> **场景**:一块刚拿到手的 PYNQ-Z2,用一根网线**直连 Windows 笔记本**(中间没有路由器、没有 Wi-Fi),
> 目标是笔记本浏览器能打开板子的 Jupyter。
> **2026-09-25 实测走通** — 环境:PYNQ-Z2 + PYNQ v2.7.0 镜像 + Windows 11。
>
> **适用性**:换任何一块「跑 Linux 的开发板 + 网线直连 PC」的场景,思路都通用。

---

## 一、最终能用的配置(先看结论)

| 项 | 值 |
|---|---|
| 板子 `eth0` | **纯静态** `192.168.2.99 / 255.255.255.0` |
| 笔记本网卡 | 静态 `192.168.2.1 / 255.255.255.0`,**网关与 DNS 留空/自动** |
| 访问 | `http://192.168.2.99:9090`,账号密码均为 `xilinx` |
| 备用 | `http://pynq.local:9090`(走 mDNS,效果相同) |
| ⚠️ 前提 | **PYNQ-Z2 没有 Wi-Fi 模块**,只有有线网口。别去连热点、别去找 Wi-Fi 密码 |

## 二、五个坑(症状 → 根因 → 处理)

### 坑 1:笔记本网卡地址是 `169.254.x.x`

- **症状**:`ipconfig` 里以太网地址是 `169.254.100.114/16`
- **根因**:`169.254.x.x` 是 **Windows 拿不到 DHCP 时的兜底地址(APIPA)**,
  **不是网卡坏了**。板子地址是写死的、它不发号 → 两边压根不在一个网段
- **处理**:给笔记本网卡设静态 `192.168.2.1`,网关与 DNS 留空

### 坑 2:在 IPv4 属性对话框里点了「确定」,但什么都没生效

- **症状**:IP 没上去,往往还会被描述成「DNS 也改不回自动」。
  `ipconfig` 复查仍是 `169.254`、`DHCP 已启用: 是`
  → **整个对话框的改动都没提交**,不是某一项的问题
- **根因**:**点「确定」时背后弹了 UAC 提权确认框,被漏点了** ——
  界面不报错,**改动静默丢弃**
  > ⚠️ **现象和根因完全无关**:被描述成「DNS 改不动」,
  > 但根因与 DNS 毫无关系。**别被字面用词带偏。**
- **排查三步**:① `ipconfig` 看实际值 ② `whoami /groups` 看是否在管理员组 ③ 注册表 `EnableLUA` 是否为 1
- **处理**:**改走命令行**,以管理员身份执行:
  ```
  netsh interface ipv4 set address 7 static 192.168.2.1 255.255.255.0
  netsh interface ipv4 set dnsservers 7 source=dhcp
  ```
  ⚠️ **用网卡 `ifIndex`(本例 = 7),不要用中文网卡名** ——
  中文名在 UTF-8 / GBK 之间必踩编码坑。
  ifIndex 可用 `Get-NetAdapter` 按 `InterfaceDescription` 过滤拿到

### 坑 3:电脑已是 `192.168.2.1`,但整个网段没一个设备应答

- **症状**:`ping 192.168.2.99` 返回「请求超时」/「无法访问目标主机」;
  并发扫 `1..254` 只有自己存活;ARP 表里目标地址是 `Incomplete`
- **根因**:板子**收到了但回不了** —— 它的 `eth0` 上没有 IPv4 地址
- **处理**:★ **别在主机端继续瞎试,直接串口进板子看**(见坑 4)

### 坑 4:★ 板子活着,但网络上找不到它 —— 用串口直连

- **认口**:Windows 的 COM 口列表里,板子调试口是 **FTDI USB Serial**
  > ⚠️ **别认错**:`COM3` / `COM4` 常常是**蓝牙虚拟口**,**只有 FTDI 那个是板子**
- **连接**:`115200` 8N1,**`DtrEnable` 与 `RtsEnable` 都要 `true`**
- **进 shell**:**PYNQ 镜像自带自动登录** —— 写一个回车就掉出 `xilinx@pynq:~$`,
  **不用输账号密码**
- **sudo 密码是 `xilinx`**:`echo xilinx | sudo -S <命令>`
- **为什么值得记**:比在主机端扫网段、猜 IP、试端口**快一个数量级**

### 坑 5:★ 真凶 —— `dhclient` 反复重配 `eth0`,把静态地址冲掉

- **症状**:
  - `ifconfig eth0` 里**只有 IPv6 link-local、没有 IPv4**,却 `RX packets 832`(收得到、回不了)
  - `ifup eth0:1` 说 `already configured`,但 `ifconfig` 里根本没这个地址
- **根因**:出厂配置是 `eth0 = dhcp` + `eth0:1 = static`,
  但 **`dhclient` 无限重试 DHCP,每次重配都把 `eth0:1` 的静态别名冲掉**
  → **一句日志就能看出来**:`journalctl -b | grep -i eth0`
  (本例中板子曾拿到过 `192.168.137.245` —— 那是 **Windows ICS 的网段**,
  证明它一直在等一个并不存在的 DHCP 服务器)
- **处理**:停掉 dhclient,把 `/etc/network/interfaces.d/eth0` 改成**纯静态**:
  ```
  auto eth0
  iface eth0 inet static
  address 192.168.2.99
  netmask 255.255.255.0
  ```
- ⚠️ **代价**:板子以后**插路由器不会自动拿 IP**。这是换取稳定直连的取舍

## 三、验收(必须做,否则「能用」只是推测)

> **只看能不能 ping 通不算数** —— 那可能还是上一轮手工设出来的残留。
> **必须重新上电,再验一遍。**

| 查什么 | 在哪查 | 命令 | 通过标准 |
|---|---|---|---|
| 外部可达 | 笔记本 | `ping 192.168.2.99` | **0% 丢失** |
| 服务在线 | 笔记本 | `curl -o /dev/null -w "%{http_code}" http://192.168.2.99:9090/` | **`302`** |
| **确属冷启动** | 板子(串口) | `uptime` | **数值很小**(如 `up 2 min`) |
| 地址自动恢复 | 板子 | `ifconfig eth0` | 有 `192.168.2.99` |
| 无残留进程 | 板子 | `pgrep -a dhclient` | **输出为空** |
| 配置未被改 | 板子 | `cat /etc/network/interfaces.d/eth0` | 4 行,与写入一致 |

**`uptime` 那条最省事 —— 一个数字就证明了「这确实是一次新启动」,
配置是开机时自己读的,而不是上一轮手工设的。**

## 四、⚠️ 改配置文件时的通用铁律

> **凡是「改配置」的命令,下一条必须跟一条 `cat` 把内容读回来。**

**反面案例(实测踩到)** —— 本意是把密码喂给 sudo:

```bash
printf '...' | echo xilinx | sudo -S tee /etc/network/interfaces.d/eth0
```

但 **`echo` 不转发 stdin** —— 它把 `xilinx` 这七个字母**直接写进了配置文件**,
把一份好的网络配置**覆盖成了一个单词**。
靠**下一步 `cat` 回读**才发现:预期 4 行,实际只有 `xilinx` 一行。

**正确写法**:让密码和内容**分处两地**,不要抢同一个 stdin:

```bash
echo xilinx | sudo -S bash -c 'echo "auto eth0" > /tmp/x ; echo "..." >> /tmp/x'
```

> **管道 + 重定向 + sudo 密码,三件事同时出现时,出错率极高。**
> **不能假设它写对了 —— 必须读回来。**

## 五、日常自检

`skill/checkers/check_board_connection.bat` —— 双击即用,会打印:
① 笔记本网卡是否已是 `192.168.2.1` ② ping 板子的结果 ③ 打不开时该怎么办。

**排查心法**:卡住时先问自己「**这是环境问题还是理解问题**」——
实测下来 **90% 是环境问题**(网卡没设、UAC 没点、DHCP 在捣乱),
不是操作者不懂原理。
