## 3. 流水深度（DRC 单段）

| 级 | 做什么 |
|---|---|
| 0 | band → Q2.22（>10 饱和） |
| 1 | × 增益（Q7.8） |
| 2 | 取绝对值 + 记符号 |
| 3 | `diff = |a| − env`、选 atk/rel **（2026-10-28 新增的一级）** |
| 4 | `prod = diff × step`（DSP） |
| 5 | `env += prod >> 22`，饱和、钳零 |
| 6 | `ex = env − thr` |
| 7 | `gr = ex × (1−ratio) >> 22` |
| 8 | 饱和到 24 位 |
| 9 | `a2 = |a| − gr`，贴回符号 → y |

输入到输出 10 拍。硬件里相邻采样隔 2083 拍（48 kHz @100 MHz），
所以包络反馈（第 5 级写、第 3 级读）有足够时间落定；仿真里激励间隔给 5 拍即可。

## 4. 双耳 DRC4×2：怎么塞进去的（2026-10-29）

批 2 定版时 DSP 已经 209/220，一套 fir_drc4 实测 **20 个**（每段 5 个：增益 1、
包络增量 2、压缩曲线 2），直接例化两份 = 229，超过 220。

真正的原因不是"乘法次数多"，而是 **25×24 的乘法一个要占 2 个 DSP48**：
DSP48E1 的 B 口只有 18 位，24 位的操作数被拆成两半各乘一次。

做法：**手动拆**，把低 6 位从 DSP 里拿出来用 LUT 乘。

```
step = step_hi·64 + step_lo          step_hi = step >>> 6 (18 位，进 DSP)
                                     step_lo = step[5:0]  (6 位，进 LUT)
prod = (diff · step_hi) << 6 + diff · step_lo
```

这是整数分解，**逐位精确**，没有精度损失（不是近似）。压缩曲线那个乘法同理。
收益：一套 DRC4 从 20 个 DSP 降到 **12 个**，整机 189 + 24 = **213/220**。

| 版本 | DSP | 说明 |
|---|---|---|
| 单耳（批 2 定版） | 209 | 20 个在 DRC |
| 双耳（2026-10-29） | 213 | 24 个在 DRC（12×2），LUT +1.6k |

代价是 LUT：一套 DRC4 从 2317 涨到 4090，两份 7719（整机 LUT 预计 19k / 53k）。
FF 也从 910/套涨到 1369/套（拆分后的部分积要打拍）。

> 走过的弯路：先试过"时分复用"（一个采样占两拍，左右交替跑同一套流水，
> 靠 tag 选 bank 参数和包络状态）。DSP 确实不涨，但 tag 的相位在
> "注入拍 / 各流水级 / 输出"三处的下标差一拍，现象是两耳音量差 1.75 倍、
> 包络一个快一个慢，调了三轮仍有 1 LSB 偏差。**同一个模块例化两次 + 拆乘法**
> 从根上没有这类问题，而且两份实例都是被 HLS 逐位验过的那个模块。

## 5. 报数字前的口径（踩过两次）

- 乘法次数要数**每个采样**的，不是每段每帧。四段并行 ≠ 四倍时钟。
- 采样率 48 kHz、时钟 100 MHz，一个采样有 2083 拍可用 —— 谈"实时"要先说这个，
  否则"FPGA 快 2000 倍"这种说法站不住（那只是时钟余量，不是吞吐）。
- 和 HLS/CPU 对比时，把"PS 在环"与"PS 不在环"分开讲：PL 直连的卖点是
  **延迟确定 + PS 占用近零**，不是"算得快多少倍"。
