## 2. 硬性要求（用户原话，违反即打回）

1. **沿用原上位机的视觉风格**：深色底（`#0f1214` 系）、细边框卡片、等宽字体显示数字、
   琥珀色 `#e0a33c` 作强调色、蓝色 `#5b8dd6` 表示负值。不要换主题、不要圆角卡片堆阴影、
   不要 Material/浅色。
2. **所有功能一屏显示完，不许上下滑。** 1600×900 和 1366×768 两个尺寸都要满足
   （浏览器视口高度大约 805 / 660）。
3. **波形、频谱没有数据，先占位**。框子要有，但**只能占矮条**（≈150 px），
   里面写清楚"暂无抓取缓冲（RTL `scope_*` 未实现）"，**不许画假波形骗人**。
   —— 上一版把两个空框拉成半屏，右列控件被挤到重叠，用户原话"乱改"。
4. **四段增益必须两组：左耳 + 右耳**。左右各 4 条滑杆，能各自拖。
   现有版本有个"跟随左耳"勾选，可以保留也可以去掉，但两组滑杆必须在。
5. **不许改后端**（`fir_pl_webui.py` / `fir_pl_live.py`）。接口不够用就写进文档提出来，
   不要自己动 python。
6. **单文件、零外部依赖**：不能引 CDN、不能引 npm 包、不能要构建步骤。
   板子不联网，页面就一个 `.html`。字体用系统 `Consolas/等宽` + `-apple-system,Segoe UI`。
7. **不许编数据**：所有数字必须来自 `/api/status`、`/api/health`，读不到就显示 `—`，
   不要用随机数冒充。

## 3. 接口契约（后端已实现，照这个写）

Base：`http://<board>:8080`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 返回 `pl.html`（你的成品）。`/page.html` 是旧版，可忽略 |
| GET | `/api/status` | 实时状态，**每秒轮询一次** |
| GET | `/api/tune` | 当前参数，返回 `{ok:true, tune:{...}}` |
| POST | `/api/tune` | 写参数，body 就是 tune 对象，返回 `{ok:true, tune:{...}}`（**已钳制后的值**） |
| POST | `/api/start` | 通路开（写 run=1），返回 `{ok, backend_alive}` |
| POST | `/api/stop` | 通路关（写 run=0） |
| GET | `/api/health` | 板子健康：温度/内存/运行时长/位流 |
| GET | `/api/scope` | **永远 `ok:false`** —— 没有波形缓冲，不要用它 |

### 3.1 `GET /api/status` 返回（节选真实报文）

```json
{
  "t": 1776016813.74, "ok": true, "running": true, "mode": "pl",
  "gain_db": [17.0, -5.5, 0.0, 4.0],
  "gain_applied_db": [17.0, -5.5, 0.0, 4.0],
  "ramp_busy": 0,
  "bypass": false,
  "attack_ms": [5.0, 5.0, 5.0, 5.0],
  "release_ms": [97.5, 97.5, 97.5, 97.5],
  "peak_in": 1, "peak_out": 8,
  "peak_in_db": -90.3, "peak_out_db": -72.2,
  "env":    [0.0002, 0, 0, 0],
  "env_db": [-74.0, null, null, null],
  "gr":     [0, 0, 0, 0],
  "gr_db":  [null, null, null, null],
  "env_r": [...], "env_r_db": [...], "gr_r": [...], "gr_r_db": [...],
  "dual": false,
  "rt": 1.0, "lat_ms": 2.3, "uptime_s": 123.4,
  "i2s_stat0": 1, "i2s_stat1": 0, "error": null,
  "age": 0.21, "stale": false, "n": 0, "pid": 1580,
  "status": { ...同一个对象... },
  "proc": {"running": false, "starting": false, "stopping": false, "log": ""}
}
```

**必须知道的几条：**

- **字段同时有扁平和外层 `status` 两份**（历史原因）。新页面**直接用扁平字段**就行。
- `stale` 或 `age > 3` = 后端进程不在，页面必须显示"与板子失去联系"并禁用控制。
- `running` 才是"通路开没开"。`proc.running` 在 PL 档**恒 false**，别拿它判断。
- `peak_in/peak_out` 是 **16 位整数幅度**（0~32767）。
  换算 dBFS：`20*log10(peak/32768)`，`peak=0` 时显示 `—`。
  **不要重复除 32768**（旧版就这么错，电平永远 -114 dBFS）。
- `env_db / gr_db` 可能是 `null`（该段没有信号），显示 `—` 不要显示 `-inf`。
- `gr_db` 是**负数**（压掉多少 dB），例如 `-12.0`。
- `bypass: true` = 压缩被跳过（增益仍生效）。

### 3.2 `GET/POST /api/tune`

```json
{
  "gain_db":     [30.0, 30.0, 30.0, 30.0],
  "thr_db":      [-20.0, -20.0, -20.0, -20.0],
  "ratio":       [0.7, 0.7, 0.7, 0.7],
  "attack_ms":   [5.0, 5.0, 5.0, 5.0],
  "release_ms":  [100.0, 100.0, 100.0, 100.0],
  "bypass":      false,
  "b1": { "gain_db": [0, 6, 12, 18], "thr_db": [...], "ratio": [...],
          "attack_ms": [...], "release_ms": [...] }
}
```

| 字段 | 范围 | 含义 |
|---|---|---|
| `gain_db` | **−24 ~ +42** | 左耳四段增益（dB）。UI 标尺可按 ±24 画，但后端允许到 42 |
| `thr_db` | −60 ~ 0 | 压缩阈值（dBFS） |
| `ratio` | **0 ~ 0.95** | ⚠ **不是压缩比 R，是"压掉多少"= 1−1/R**。R=2 → 0.5；R=4 → 0.75 |
| `attack_ms` | 0 ~ 50 | 启动时间 |
| `release_ms` | 0 ~ 500 | 释放时间 |
| `bypass` | bool | 跳过压缩 |
| `b1` | 同上 | **右耳**处方。不带 `b1` = 两只耳朵一样（后端镜像 bank0） |

**ratio 换算**（页面显示"2.0 : 1"时写 0.5）：

```js
const toWire = R => 1 - 1 / R;          // 2 → 0.5
const toRatio = q => 1 / (1 - q);       // 0.5 → 2
```

**写入策略：** 拖动时每 120 ms 合并发一次（防抖），松手（`change`）立刻发一次。
只发变化的字段也可以，后端会给缺的字段填默认。

### 3.3 `GET /api/health`

```json
{"ok": true, "mode": "pl", "ver": "pl-webui 2026-10-28",
 "bit": {"path": "...", "exists": true, "mb": 2.1},
 "status_age_s": 0.21, "run": true,
 "temp_c": 45.2, "mem_avail_mb": 780, "uptime_s": 3600,
 "load": ["0.10","0.08","0.05"], "guard": null}
```

`temp_c / mem_avail_mb / uptime_s` 在 PC 上跑会是 `null`（读不到 `/sys`），
显示 `—` 是对的，**不要当成错误**。

## 4. 页面必须呈现的信息（少一条就算没做完）

| 区块 | 内容 | 数据来源 |
|---|---|---|
| 顶栏 | 标题、来源、运行徽标（未运行/运行中/失联/出错）、已处理时长、延迟、实时率 | `status.running / stale / rt / lat_ms / uptime_s` |
| 频响曲线 | 四段阶梯（20 Hz–20 kHz 对数横轴），**纵轴范围跟着最大增益自适应** | `tune.gain_db` |
| 电平 | 进 / 出 两条 + 出/进差值（dB） | `peak_in_db / peak_out_db`（或自己算） |
| 观察量 | 四段 ENV、四段 GR（dB，负数）；双耳时右耳也要 | `env_db / gr_db / env_r_db / gr_r_db` |
| 四段增益 | 左耳 4 条、右耳 4 条，实时数值 + 拖拽 | `tune.gain_db / tune.b1.gain_db` |
| 压缩 | 阈值 / 压缩比 / 启动 / 释放 + 直通 | `tune.thr_db / ratio / attack_ms / release_ms / bypass` |
| 系统健康 | 过核用时、CPU 温度、可用内存、运行时长、死机防护、位流 | `/api/health` |
| 波形、频谱 | **占位**，写明未实现 | 无 |
| 控制 | 接通路 / 静音（要能真的停）、失联时禁用 | `POST /api/start /stop` |

**关键交互：**
- "静音/停止"按钮必须**始终可点**（只要通路是开的）。上一版因为字段读错，
  按钮永远是灰的，用户说"想断开都断开不了"。
- 拖动滑杆要跟手，不要每次拖都整页 re-render。
- 断线（`stale`）时：显示"与板子失去联系，重试中…"，控件变灰，但**不要清空**最后已知数值。

## 10. 上一版踩过的坑（别再踩）

1. **两套布局规则同时存在**（`.scope-col` + 新 flex）→ 浏览器按顺序挑，改一处另一处还在压。
   重写就干净重写，别在旧文件上打补丁。
2. `peak_in` 已经除过一次 32768 → 再除一次，电平永远 -114 dBFS（已修，别再犯）。
3. `proc.running` 恒 false → 用它判断"运行中"会导致按钮永远灰、停不下来。
   用 `status.running`。
4. `/api/tune` 返回**包了一层** `{ok, tune}`。不认这层会拿不到参数，页面初始化
   会把默认值（0 dB）写回去，演示一上来就听不见。
5. `ratio` 是"压掉多少"不是"压缩比"，直接显示会变成 "0.7 : 1"，看着像坏的。
6. 页面如果 5 秒不刷新 `/api/status`，用户会以为卡死；轮询固定 1 s。
7. 板子 8080 可能被老的 `fir-webui.service` 占着 —— 起不来时先 `systemctl stop fir-webui`。

## 12. 附：板上怎么重启这套东西

```bash
# 板子 192.168.2.99 (xilinx/xilinx)
cd /home/xilinx/dma_exp
ps -ef | grep -E '[f]ir_pl_(live|webui)'      # 有旧的就 pkill
sudo sh pl_webui_up.sh                        # 先 live 后 webui，顺序不能反
curl -s localhost:8080/api/tune | head -c 200 # 必须是 {"ok":true,"tune":...}
```

overlay 只能被一个进程持有，所以 `fir_pl_live.py` 必须先在、`fir_pl_webui.py` 只读写
`/dev/shm` 下的三个文件：

```
/dev/shm/fir_tune.json    页面写 → live 读
/dev/shm/fir_status.json  live 写 → 页面读
/dev/shm/fir_pl_run.txt   页面写 1/0 → live 开关通路
```
