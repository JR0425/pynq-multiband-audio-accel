> 制定:2026-10-27 ｜ 状态:**定稿待评审**,RTL 与 `fir_pl_live.py` 都照这份写

---

## 0. 一句话

**这份表是两条线之间唯一的契约。** 任何一边想改地址、位定义、单位、默认值,
先在本文改、再改代码 —— 不许单边改。

三条硬约束:

1. **默认值必须与 v25 的出厂参数逐位一致**,否则"RTL 与出货核逐位对拍"这条
   验收判据失去基准(见 §5)。
2. **`CTRL` 的 bit0/1/2/8 不许挪**(现有探针 `pl_direct_probe.py` 按这几位写的),
   新功能只往上加位。
3. **页面接口字段不动**(`/api/tune` 的 `gain_db`/`thr_db`/`ratio`/`attack_ms`/
   `release_ms`/`bypass`,以及 `/api/status`、`/api/scope`、`/api/health`),
   换算全部在后端做,见 §7。

## 1. 总线与访问约定

| 项 | 值 |
|---|---|
| 总线 | AXI4-Lite 从机,32 位数据,4 字节对齐 |
| 时钟 | 100 MHz(与 `FCLK_CLK0` 同域) |
| 地址跨度 | 0x00000 – 0x27FFF(160 KB),基地址按 Vivado Address Editor 分配 |
| 字节序 | 小端 |
| 写只读地址 | 忽略,不报错、不响应 SLVERR |
| 读未定义地址 | 返回 0 |
| 保留位 | 写 0,读回 0;不得依赖其值 |

**为什么不做成 AXI-Stream 或 BRAM 直挂**:参数是低频、单点的读写(页面 150 ms 一次),
AXI-Lite 足够;只有波形缓冲和播放缓冲两块大内存走 `axi_bram_ctrl`。

## 3. 寄存器详表

### 3.1 标识与控制

| 偏移 | 名称 | 属性 | 位 / 编码 | 默认 | 说明 |
|---|---|---|---|---|---|
| `0x000` | `ID` | RO | `[31:16]`=0x504C("PL") `[15:0]`=版本号 | `0x504C0002` | 后端加载后**先读这一格**确认挂对了;版本变了说明表变了 |
| `0x004` | `CTRL` | RW | `[0]` run | 0 | 1 = 往外放音。0 = 内部照跑但不出声(`i2s_duplex` 语义,同现有位) |
| | | | `[1]` drc_en | 0 | 0 = 只过前端(= v25 的 bypass 通路,已验 0 LSB);1 = 整条压缩路径 |
| | | | `[2]` flush | 0 | 1 = 清前端延迟线 + 两侧 FIFO + 包络状态。**自清**:写 1 后 RTL 用 16 拍做完再回 0。切音源、切旁路后建议 flush |
| | | | `[3]` mpo_en | 0 | 1 = 开最大输出限幅(B6) |
| | | | `[4]` tone_en | 0 | 1 = 测试音注入(B4 测听闭环) |
| | | | `[5]` src | 0 | 0 = codec ADC(麦克风);1 = 播放缓冲(D1 曲目模式) |
| | | | `[8]` clr_stat | 0 | **兼容位**,与 `0x070 CLR_STAT` 等价。写 1 清 `STAT0/1/2`、`MPO_CNT`、`SMP_CNT` |
| | | | `[31:6]` | 0 | 保留 |
| `0x070` | `CLR_STAT` | WO | `[0]` | 0 | 写 1 清全部计数器。与 `CTRL[8]` 是同一件事,新代码用这一格 |

**`CTRL[2]` 是自清的**,别指望读回 1;要确认清完了读 `STAT1` 的 FIFO 占用是否归零。

### 3.2 状态与计数

| 偏移 | 名称 | 属性 | 位 | 说明 |
|---|---|---|---|---|
| `0x008` | `STAT0` | RO | `[15:0]` und_cnt | 播放断流次数(每帧数"LRCLK 来了手里凑不齐一对")。**正常恒 0** |
| | | | `[31:16]` ovf_cnt | 接收溢出次数(上一对还没走完又收到新帧)。**正常恒 0** |
| `0x00C` | `STAT1` | RO | `[15:0]` tx_lvl | 播放 FIFO 当前占用(字) |
| | | | `[31:16]` cap_lvl | 接收 FIFO 当前占用(字) |
| `0x010` | `STAT2` | RO | `[15:0]` oovf_cnt | 输出 FIFO 溢出次数。**正常恒 0** |
| | | | `[31:16]` tx_peak | 起跑以来见过的最大播放水位 |
| `0x014` | `SMP_CNT` | RO | 32 位 | 前端已处理采样数。48 kHz 下 32 位约 24.8 小时回绕,复位清零 |
| `0x018` | `FRM_CNT` | RO | 32 位 | 已输出帧数(LRCLK 周期数),用于算实时倍率 |
| `0x01C` | `PLY_RD` | RO | 32 位 | 播放缓冲当前读指针(以字为单位,模 16384) |
| `0x020` | `PLY_UND` | RO | 32 位 | 播放欠载次数(缓冲空了但还要取数) |

> **水位类寄存器量的是"积压多少",不是"有没有在流"。** 跑得越干净水位越像 0 ——
> 判"通不通"要看 `STAT0` 的两个计数**不涨**,不要看水位(10-25 已经在这上面错判过一次)。

**"3 拍/采样"不在这里读。** 它是设计值(前端 195 乘法器 × 3 组系数轮转),
不是运行时观测量。要验就验 `SMP_CNT` 在 1 秒里涨 48828 ± 1 且 `STAT0` 不涨。

### 3.3 电平、限幅、音源、抓取

| 偏移 | 名称 | 属性 | 域 / 位 | 默认 | 说明 |
|---|---|---|---|---|---|
| `0x02C` | `LVL_IN_LO` | RO | `[31:0]` | 0 | 输入均方累加低 32 位 |
| `0x030` | `LVL_IN_HI` | RO | `[15:0]` | 0 | 输入均方累加高 16 位(合并成 48 位) |
| `0x034` | `LVL_OUT_LO` | RO | `[31:0]` | 0 | 输出均方累加低 32 位 |
| `0x038` | `LVL_OUT_HI` | RO | `[15:0]` | 0 | 输出均方累加高 16 位 |

| `0x040` | `PEAK_IN` | RO | `[15:0]` 有符号 | 0 | 输入窗内绝对值峰值(int16 域) |

| `0x060` | `EAR_CTL` | RW | `[0]` indep | 0 | 0 = 左右耳用同一套参数(bank0);1 = 左耳用 bank0、右耳用 bank1 |
| | | | `[2:1]` out_mode | 0 | 0=双声道都出 1=只出左 2=只出右 |

**测试音注入点**:前端**输入端求和**(饱和加),所以它照样过四段增益和压缩。
这样"测听 → 该段电平 → 判断听没听到"这条闭环才成立,而且麦克风不参与、永不啸叫。

### 3.4 参数组 bank0(左耳)/ bank1(右耳)

两组的**内部布局完全相同**,基址分别是 `0x100` 和 `0x200`。右耳默认值 = 左耳(镜像)。

| 相对偏移 | 名称 | 属性 | 域 | 默认 | 说明 |
|---|---|---|---|---|---|
| `+0x00` | `GAIN[0..3]` | RW | Q7.8 有符号 | `256` ×4 | 四段验配增益。1.0 = 256,步进 1/256 = 0.034 dB,量程 ±128(±42 dB) |
| `+0x10` | `THR[0..3]` | RW | Q2.22 无符号 | `419456` ×4 | 压缩阈值(线性幅度),419456 = 0.1 = −20 dBFS |
| `+0x20` | `RATIO[0..3]` | RW | Q2.22 无符号 | `2936064` ×4 | **压掉多少**(1 − 1/压缩比),2936064 = 0.7 ⇒ 3.33 : 1 |
| `+0x30` | `ATK[0..3]` | RW | Q2.22 | `0` ×4 | attack 平滑步进。**0 = 不启用,走无记忆压缩**(见 §6) |
| `+0x40` | `REL[0..3]` | RW | Q2.22 | `0` ×4 | release 平滑步进,**0 = 不启用** |
| `+0x50` | `ENV[0..3]` | RO | Q2.22 | 0 | 当前包络值(线性幅度) |
| `+0x60` | `GR[0..3]` | RO | Q2.22 有符号 | 0 | 当前衰减量(≥0 表示压掉了多少幅度) |
| `+0x70` | `RAMP_DIV` | RW | `[15:0]` | 0 | 增益斜坡步长:`step=(目标-当前)>>>N`,指数收敛、时间常数 2^N 个采样(48 kHz 下 N=5 ≈ 0.7 ms,N=6 ≈ 1.3 ms);**0 = 一步到位(无斜坡,拖滑块会咔)**。网页后端默认写 5。2026-10-28 板上实测口径 |
| `+0x74` | `RAMP_BUSY` | RO | `[0]` | 0 | 1 = 当前增益还在追目标。页面用来显示"已生效" |

**数组的地址是连续递增的**:`GAIN[0]=0x100`、`GAIN[1]=0x104`、`GAIN[2]=0x108`、
`GAIN[3]=0x10C`;其余同理(每组 4 个 × 4 字节 = 16 字节)。

## 4. 数值域与换算(后端照抄这几个函数)

**所有换算都在 PS 侧做,RTL 里没有 `exp` / `log` / 除法。**

> ⚠️ **先算 Q1.15、再左移 7 位,不要直接在 Q2.22 域取整。**
> v25 的驱动传的是 Q1.15(如 `thr=3277`),核里再 `<<7` 变成 Q2.22(`419456`)。
> 先在 Q2.22 域直接 `round(2^22 * 0.1)` 会得到 `419430`,差 26 LSB ——
> 听不出来,但**逐位对拍会挂**。下面这几个函数就是照驱动的顺序写的。

```python
import math

GAIN_UNITY = 256          # Q7.8
FS = 48000

def db_to_gain(db):                       # 页面 gain_db -> GAIN[]
    return max(-32768, min(32767, int(round(GAIN_UNITY * 10 ** (db / 20.0)))))

def dbfs_to_thr(db):                      # 页面 thr_db -> THR[]
    q15 = int(round(32768 * 10 ** (db / 20.0)))         # 先 Q1.15,和 v25 一样
    q15 = max(0, min(32767, q15))
    return q15 << 7                                     # 再 <<7 成 Q2.22

def ratio_to_q22(r):                      # 页面 ratio(1..10) -> RATIO[]
    q = max(0.0, min(0.95, 1.0 - 1.0 / max(1.0, r)))    # q = 压掉多少
    q15 = int(round(q * 32768.0))
    return q15 << 7

def ms_to_coef22(ms):                     # 页面 attack_ms/release_ms -> ATK[]/REL[]
    if ms is None or ms <= 0:
        return 0                          # 0 = 不启用,与 v25 语义一致
    step15 = int(round((1.0 - math.exp(-1.0 / (ms * 1e-3 * FS))) * 32768.0))
    step15 = max(1, min(32767, step15))
    return step15 << 7                    # Q1.15 -> Q2.22

def level_dbfs(acc48, win):               # LVL_*_HI:LO -> dBFS
    if acc48 <= 0:
        return -120.0
    rms = math.sqrt(acc48 / float(win))
    return max(-120.0, 20.0 * math.log10(max(rms, 1e-9) / 32768.0))

def gr_db(env, gr):                       # ENV/GR -> 当前衰减量(dB,负值)
    if env <= 0:
        return 0.0
    lin = max(1, env - gr) / float(env)
    return 20.0 * math.log10(lin)
```

**自检样例**(拿这几组数对一遍,对不上就是换算写错了):

| 调用 | 期望 |
|---|---|
| `db_to_gain(0)` / `db_to_gain(0.5)` / `db_to_gain(24)` | `256` / `271` / `4057` |
| `dbfs_to_thr(-20)` / `dbfs_to_thr(-10)` | `419456` / `1326336` |
| `ratio_to_q22(2)` / `ratio_to_q22(10)` / `ratio_to_q22(3.3334)` | `2097152` / `3774848` / `2936064` |
| `ms_to_coef22(5)` / `ms_to_coef22(100)` / `ms_to_coef22(0)` | `17408` / `896` / `0` |

`419456` / `2936064` / `17408` / `896` 这四个数与现在 `fir_drc4.v` 里的编译期参数
**逐位相同** —— 这不是巧合,是 §5 的基准要求。

## 5. 默认值表(= v25 出厂参数,逐位对拍的唯一基准)

| 寄存器 | 默认值 | 对应 v25 的 | 来源 |
|---|---|---|---|
| `GAIN[0..3]` | 256 | `band_gain = 1.0` | `fir_core.py: DEF_GAIN` |
| `THR[0..3]` | 419456 | `thr = 3277 (Q1.15)` | `fir_core.py: DEF_THR` |
| `RATIO[0..3]` | 2936064 | `ratio = 22938 (Q1.15)` | `fir_core.py: DEF_RATIO` |
| `ATK[0..3]` | **0** | `drc_attack = 0`(不启用) | `fir_core.py: DEF_ATTACK` |
| `REL[0..3]` | **0** | `drc_release = 0`(不启用) | `fir_core.py: DEF_RELEASE` |
| `CTRL` | 0(drc_en=0) | `bypass = True` | — |
| 其余 | 见 §3 各表的"默认"列 | — | — |

> ⚠️ **这里有个要 RTL 补的东西**:现在 `fir_drc4.v` 的 attack/release 是**编译期**
> `atk=17408 / rel=896`(5 ms / 100 ms),**没有"不启用"这条路径**;而 v25 的默认
> 是 **0 / 0(无记忆压缩)**。所以 `ATK=REL=0` 时必须退化到无记忆的 `drc()`,
> 否则"默认配置下 RTL ≡ v25"这条判据根本不成立(PROGRESS 10-25 第 ⑦ 条
> 就是因为这个没能比 DRC 通路)。
>
> 这条不写进 RTL,逐位对拍就只能比 bypass 通路 —— 报告 §3.4.3 那张表也就只能
> 讲一半。**列入 A 线必做项,估 0.5 天。**

## 6. 时序与生效规则

| 规则 | 说明 |
|---|---|
| 参数生效时刻 | 下一个采样边界(≤ 21 µs @48 kHz) |
| `GAIN` | **走斜坡**,每 `RAMP_DIV+1` 拍走 1 LSB,过程中不出咔哒;`RAMP_BUSY` 为 1 表示还在追 |
| `THR`/`RATIO`/`ATK`/`REL` | 立即生效,切换瞬间可能有轻微的包络跳变(和现在 16 ms 版一样,不做斜坡) |
| `ATK=0` 或 `REL=0` | 该段退回**无记忆压缩**,与 v25 相同;**0 与"极小值"不等价**,别用 1 代替 |
| 切 `CTRL[1]`(旁路) | 立即生效会有一声轻跳;演示时先拖到 0 dB 再切,或直接 flush |
| 切 `CTRL[5]`(音源) | **必须先 flush**:两个源的相位/延迟不同,不 flush 会有半秒的错位 |
| `flush` | 16 拍内完成,期间 `STAT1` 归零;`STAT0` 的计数**不清** |
| 读 `LVL_*` | 累加器在每窗结束时锁存一次,窗内读到的是上一窗的值(不要在同一窗里连读两次比较) |
| 写 `CLR_STAT` | 计数清零是同步的,写完立即读可能还看到旧值,隔 1 ms 再读 |

## 7. 与页面接口的映射(不改前端)

`page.html` 只认这 7 个接口,后端负责翻译:

| 接口 | 来源 |
|---|---|
| `POST /api/tune` | 字段 → 寄存器,见下表 |
| `GET /api/status` | 见下表 |
| `GET /api/scope` | 读 `0x10000`/`0x14000` 两块,按现有二进制头写 `/dev/shm/fir_scope.bin` |
| `GET /api/health` | 温度/内存/位流 md5 走 PS;`过核用时` 可省或写设计值 |
| `POST /api/start` / `stop` | 加载 overlay + 起 `fir_pl_live.py` 子进程 / 杀进程 + `CTRL[0]=0` |

|---|---|---|
