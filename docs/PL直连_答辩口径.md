# PL 直连 · 答辩口径（2026-10-29）

> 每一句能说的话，后面都跟"凭什么"和"被问到怎么答"。没证据的不要先说。
> 数字全部来自仓库里的报告文件，路径都写了，问起来能当场打开。

## 1. 一句话定位（开场用）

一条**全硬件**的四段动态范围压缩通路：I2S 进、I2S 出，PS（ARM）不碰音频样本，
只负责写参数。48 kHz 采样下一个样本有 2083 个时钟周期可用，PL 里用掉 10 级流水。

- 凭什么：`docs/PL直连_资源与时序.md` §3（逐级流水）+ §5（2083 拍的来历）。
- 被问"PS 到底干什么"：只写寄存器（网页 → json → `fir_pl_live.py` → MMIO），
  音频数据一个字节都不过 PS。

## 2. 三个能当场演示的能力

| 能力 | 怎么说 | 证据 |
|---|---|---|
| 四段补偿 | 四段各自的增益/阈值/压缩比/起停时间，全部运行期可改，拖滑杆就有反应 | 寄存器表 §3.4；`pl_regs_check.py` 的四段写读 |
| 真 WDRC | 不是"限幅器"：每段一套包络 + attack/release（5 ms / 100 ms 默认），和 HLS 的 `wdrc()` **逐位相同** | `tb_drc_chan` 模式 A：1200 采样 0 失配；另有 7 组参数扫描 |
| 双耳两套处方 | 单麦 → 左右各一套完整的 DRC（不是共用一套状态），左字/右字分别送两个声道 | `docs/PL直连_资源与时序.md` §4；`pl_dual_probe.py` 三条判据 |

## 4. 被追问时的三道防线

**问：怎么证明 RTL 是对的？**

三层，从弱到强：

1. 与 HLS 的整数模型逐位对拍（`tb_drc_chan`：模式 A 0 失配、模式 B ±1 LSB、
   模式 C 直通逐位等于输入）；
2. 与"改动前的 RTL"逐位对拍（`tb_drc_gain`：3000 采样 0 失配）——
   用来证明重构/优化没改变数值（拆乘法那次就是靠它）；
3. 板上读寄存器（`pl_regs_check.py`）+ 读数随参数动（`pl_drc_ply_probe.py`）。

**问：双耳是不是"一套压缩器两边共用"？**

不是。`fir_pl_direct` 里是两个 `fir_drc4` 实例（`u_drc_l` / `u_drc_r`），
参数来自两组独立寄存器（bank0/bank1），包络状态各一份。
代价是 DSP 从 209 涨到 213 —— 能装下的原因是一套 DRC 从 20 个 DSP 降到了 12 个
（25×24 的乘法手动拆成 18 位走 DSP + 6 位走 LUT，整数分解，逐位精确）。

**问：为什么不用时分复用省资源？**

试过，写在 `docs/PL直连_资源与时序.md` §4 的最后一段。结论：tag 的相位在
"注入/各级/输出"三处要对齐，调了三轮仍有 1 LSB 偏差，风险大于收益。
两份实例 + 拆乘法从根上没有相位问题，而且两份都是被 HLS 验过的同一个模块。

## 5. 明确不要说的话

- **不要**说"网页上能分别调两只耳朵的所有参数"：现在只有**增益**能分开调，
  右耳的门限/压缩比/时间常数要写 json（`tune["b1"]`）。
- **不要**说"有波形/频谱显示"：抓取缓冲还没做，`/api/scope` 明确返回 `ok:false`。
- **不要**说"有 MPO 限幅"：寄存器位留了，RTL 没做。
- **不要**说"测过 THD+N"：`tools/quality_metrics.py` 算的是**整数模型**的
  THD+N，不是模拟端（DAC/耳机/ADC 都不在里面）。要提就带上这句限定。
- **不要**说"延迟 100 ns"：10 级流水是逻辑延迟，整机延迟还包括 I2S 帧同步和
  FIFO 水位（"听不出延迟"这个说法是安全的，"延迟 100 ns"不是）。
- **不要**用"双耳"指"两个耳机听同一个信号"：本项目里双耳 = 两套处方。

## 6. 演示流程（3 分钟）

1. 网页打开 → 四段增益拖到 +30 dB → 说话听得见（`pl_demo_check.py` 已写好默认值）。
2. 拖阈值/压缩比 → 面板上 `ENV`/`GR` 跟着动（这是 PL 里的真信号）。
3. 打开"双耳" → 右耳四条滑杆给一个高频抬升的处方 → 左耳平坦、右耳明亮。
4. A/B 对照（bypass）→ 说明"补偿前 vs 补偿后"。
5. 收尾：`pl_demo_check.py --restore` 或直接把 tune 写回默认（+30 dB / −20 dBFS / 0.7）。

## 7. 一页纸的"我们踩过的坑"（用来回答"难点在哪"）

| 坑 | 现象 | 根因 |
|---|---|---|
| 参数包错位 | 四段增益只有两段是活的 | 128 位参数包被 slice 成 64 位当四个 16 位用 |
| 拼接拖成无符号 | 包络一步顶到饱和值 | `{a,b} >>> n` 里 `>>>` 变成逻辑右移 |
| 参数寄存器化后时序崩 | WNS −1.612 ns / 529 个失败端点 | 减法+选择+乘法挤在一拍，拆成两级解决 |
| 一条 tb 1000 点全对但其实错了 | 换响的音源才暴露 | 音源包络没超过门限，压缩器没工作 |
| 两个构建循环同时跑 | 每轮都报不同的 tcl 读不到 | 互相当成残留进程杀掉，看着像 license 随机失败 |
