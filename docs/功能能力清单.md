# 功能能力清单（做统一上位机之前必须先看这张表）

> 2026-10-29 晚。用途：**先确认"功能能不能用"，再统一做界面。**
> 界面只负责把这里标"能用"的东西摆出来；标"缺"的，界面做得再漂亮也是假的。

---

## 1. 结论先说

- **能用的 8 项**：通路开关、四段增益（左/右）、压缩四参数、压缩直通、
  电平/ENV/GR 观察量、频响曲线、系统健康、双耳独立处方。
- **缺的 3 项**：**测听配增益**、**波形/频谱**、**录音回放**。
- 这三项**都不是前端能补的**，全卡在后端/RTL：
  - 测听：RTL 里的测试音是**写死 440 Hz 方波**，寄存器 `0x58 TONE_SEL` /
    `0x5C TONE_AMP` 在 `fir_pl_regs.v` 里留了口，但 `fir_pl_direct.v`
    **一个端口都没接**。要按 250/750/1500/3000 Hz 逐段放音，必须改 RTL + 重编位流。
  - 波形/频谱：RTL 没有抓取缓冲（`scope_*` 是桩），`/api/scope` 只能说 `ok:false`。
  - 录音：`/api/rec` 直接 501，PL 档没有落盘通路。

所以顺序应该是：**补后端能力 → 功能逐条验收 → 接口冻结 → 统一做界面**。
现在抠版面是白抠，功能一加窗口就得重排。

## 3. 要补的三件事（按性价比排）

### 3.1 测听配增益（优先级最高，因为它是"卖点"）

**现状**：`ctrl[3]=1` 只能放一路 **440 Hz 方波、幅度 ±8000 写死**。
`fir_pl_regs.v` 已经把 `tone_sel[1:0]` / `tone_amp[15:0]` 引出来了（`0x58` / `0x5C`），
但 `fir_pl_direct.v` 没有这两个端口。

**要改**：
1. RTL：`fir_pl_direct.v` 增加 `input [1:0] tone_sel`、`input [15:0] tone_amp`，
   相位增量按 `tone_sel` 查表（250 / 750 / 1500 / 3000 Hz，四段中心频率），
   幅度换成 `tone_amp`，输出仍由 `ctrl[3]` 开关。
2. 顶层把 `fir_pl_regs` 的 `tone_sel/tone_amp` 接到 direct。
3. 重编位流（1 轮约 40–60 分钟，含 retry）。
4. 后端 `POST /api/hearing/tone {band, amp_db}`：写 `0x58` / `0x5C`，置 `ctrl[3]`；
   `POST /api/hearing/end` 清 `ctrl[3]`。
5. 前端：**模态弹层**（不能塞进一屏布局，会把别的挤掉）。

**验收判据**：四个频段各放一次，耳机里听得到、频率明显不同；
把 `gain_db` 全设 0 与全设 +20，测听结果不同（说明走的是同一条增益链路）。

### 3.2 波形 / 频谱（中等，答辩加分）

RTL 加一块环形缓冲（比如 4096 点 × 16 bit，抓 `fe_dout` 和 `out_q`），
加 `snapshot` 触发位 + 读地址，后端 `/api/scope` 一次读回来给页面画。
估算 1–2 天（含 BRAM 例化、时序、探针验证）。**不加就只能画占位。**

### 3.3 录音（低，除非要交音频文件）

PL 档没有落盘，要么加 DMA S2MM，要么把 PL 输出再接回 PS 用 `audio` 库录。
半天到一天。

## 4. 统一做界面的前置条件（建议写死）

在做界面之前，下面三条必须冻结，否则界面会反复改：

1. **功能冻结**：上面 15 项里，哪些进演示版定下来（建议 1–9 全要，10 争取，11 有时间就做，12 不做）。
2. **接口冻结**：`/api/status` 的字段名、单位、`null` 语义不再变。
   （现在 `ratio` 是 1−1/R、`peak` 是 16 位幅度、`proc.running` 在 PL 档恒 false，
   这三条最容易让写界面的人踩坑，已经写进 `页面重构_交接.md`。）
3. **一屏尺寸冻结**：演示机分辨率定下来（1600×900 还是 1920×1080）。
   现在按 1600×900 / 1366×768 两档做过验收。

## 5. 现在能做的"功能验收"（不写界面也能跑）

按这个顺序逐条跑，每条记 PASS/FAIL：

```bash
# ① 寄存器与双耳隔离（不含音频）
python tools/board_debug/pl_regs_check.py

# ② 压缩器随参数动（读 ENV/GR）
python tools/board_debug/pl_drc_ply_probe.py

# ③ 双耳两套处方各算各的
python tools/board_debug/pl_dual_probe.py

# ④ 网页接口契约（不需要板子）
python board/scripts/fir_pl_webui.py --selftest

# ⑤ 页面版面（不需要板子）
python tools/webui_accept.py
```

听感三件（必须人耳）：
- `gain_db` 全 0 → +30，说话明显变大、不破音
- 拖某一段增益，声音不咔（斜坡 ≈6 ms）
- 左右耳参数设成不同，耳机里能听出差别

## 6. 一句话给做界面的人

**现在做界面只需要覆盖 1–9 项**，把 10–12 留成"禁用 + 说明"的占位；
等 RTL 把测听和抓取缓冲补上，再按同一套接口加窗口 —— 那时候不用重排版面，
因为它们都是**模态弹层**，不占一屏。
