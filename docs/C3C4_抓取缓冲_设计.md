## 1. 要解决什么

现在页面上的波形、频谱是**占位框**，因为 RTL 里根本没有采样缓冲。
`/api/scope` 只能回 `ok:false`。这同时卡住三件事：

| 卡住的项 | 需要什么 |
|---|---|
| 波形显示 | 一段进核/出核的时域样本 |
| 频谱显示 | 同上，前端做 FFT |
| A2 延迟可视化 | 同上，互相关求 in→out 的样点差 |
| C6 THD+N | 同上，对出核样本做 FFT 后算谐波比 |

所以 C3/C4 是这一组的总闸。

## 2. 方案：一块双口 BRAM + PS 侧直读

### 2.1 硬件

```
        ┌──────────── fir_pl_direct ────────────┐
din ───▶│ fe_dout ──┬─▶ [写口 A]  cap_bram      │
        │           │     4096 × 32             │
out ───▶│ out_q  ───┘     {out[15:0], in[15:0]} │
        │                                        │
        │  snap_en(ctrl[6]) 冻结写地址           │
        └────────────────┬───────────────────────┘
                         │ 口 B
                  ┌──────▼───────┐
                  │ axi_bram_ctrl │  0x43C60000
                  └──────┬───────┘
                         │ AXI4-Lite（PS 读 16 KB）
```

- 一块 **4096 × 32 位** 的 BRAM：低 16 位放"进核"，高 16 位放"出核"，
  同一个地址就是同一时刻的两个样本 —— **天然对齐，不用再找相位**。
- 写地址每采样 +1，回绕。4096 点 @ 48.8 kHz ≈ **84 ms** 的环形历史。
- `ctrl[6]` 叫 `snap`：置 1 时把当前写指针锁进 `snap_ptr`，之后写继续（不影响通路）。
  PS 从 `snap_ptr − 4096` 开始读，拿到的就是"触发前 84 ms"的一段。
- 为什么不做触发（比如"超过阈值才开始抓"）：演示场景下"回看最近 84 ms"够用，
  而且不需要人配合。

**资源**：1 块 RAMB36（或 2 块 RAMB18）。当前 8 块 RAMB36 / 220 DSP / 17.6k LUT，
加这一块完全不紧张。**时序上也不该有影响** —— 全是 BRAM 端口，不新增组合路径
（当前 WNS +0.124 ns 很薄，这一点很重要）。

### 2.2 RTL 改动清单

| 文件 | 改什么 |
|---|---|
| `src/rtl/fir_pl_direct.v` | 加端口 `output [11:0] cap_addr`、`output [31:0] cap_din`、`output cap_we`、`output [11:0] snap_ptr`；内部加写指针与 snap 锁存 |
| `board/overlay/build_audio_pl.tcl` | 加 `cap_bram`（blk_mem_gen 或 BRAM Controller 直连）+ `axi_bram_ctrl`，地址 `0x43C60000`，range 16K |
| `src/rtl/fir_pl_regs.v` | 加 `0x78 SNAP`（RW，写 1 触发）、`0x7C SNAP_PTR`（RO） |

写口逻辑（约 15 行）：

```verilog
reg [11:0] wr_ptr;
reg [11:0] snap_ptr_r;
always @(posedge clk) if (out_vld) wr_ptr <= wr_ptr + 1'b1;
always @(posedge clk or negedge rst_n)
  if (!rst_n) snap_ptr_r <= 12'd0;
  else if (ctrl[6]) snap_ptr_r <= wr_ptr;      // 打一拍，PS 读到的就是冻结瞬间
assign cap_addr = wr_ptr;
assign cap_din  = {mpo_r, mpo_l};               // 出核（限幅后）在高位，进核低位
assign cap_we   = out_vld;
```

> 注意：`fe_dout` 是**进核**的样本，`mpo_l` 是**出核**（限幅后）。要放在同一拍对齐 ——
> `out_vld` 那一拍两者都在，直接打包即可。

### 2.3 后端

```python
# fir_pl_live.py
def read_scope(regs, bram):
    ptr = regs.rd(0x7C) & 0xFFF
    n = 4096
    buf = []
    for i in range(n):
        w = bram.read((ptr + i) & 0xFFF) << 2      # 32 位 → 字节地址
        buf.append(w)
    return {
        "fs": 48828,
        "in":  [((w & 0xFFFF) ^ 0x8000) - 0x8000 for w in buf],
        "out": [((w >> 16) ^ 0x8000) - 0x8000 for w in buf],
    }
```

`/api/scope` 返回这个结构（现在是 `ok:false`）。读 4096 个 32 位 ≈ 几毫秒，不影响实时。

### 2.4 前端

- 波形：把 `in`/`out` 两条线画出来，横轴 84 ms。**这就能看见"进核/出核"的差别**。
- 频谱：对 4096 点做 FFT（前端纯 JS，4096 点用 radix-2 大约 2 ms，1 秒刷一次没问题）。
  或者降采样到 1024 点再 FFT 也够看。
- A2 延迟：对 `in`/`out` 做互相关，峰值位置 = 延迟样点数，乘 1/48828 = 秒。
  **这才是真正的端到端延迟**，比现在 status 里那个 `lat_ms: 2.3`（估算值）可信。

## 3. 验收

| 项 | 判据 |
|---|---|
| 波形有数据 | `/api/scope` 的 `in`/`out` 长度 4096，且不全 0 |
| 两路确实不同 | 增益 +36 dB 时 `out` 的峰值 ≈ `in` 的 63 倍（±10%） |
| 延迟 | 互相关峰值在 100~200 样点之间（≈2~4 ms），和 `lat_ms` 对得上 |
| 不卡通路 | 抓 10 次，`i2s_stat0` 的 ovf/und 不增长 |
| 帧率 | 页面 1 s 刷一次，CPU 占用 < 30% |

## 4. C6 THD+N（依赖 C3）

拿到 `out` 的 4096 点之后：加窗 → FFT → 找基频（测听时是纯音，直接知道是 250/750/1500/3000）
→ 谐波功率和 / 总功率。

演示口径：**"1 kHz 纯音，THD+N = x.x%"**，要跟 `tools/quality_metrics.py` 的模型值对得上
（模型侧现在只有块模式的数据，PL 侧要重跑）。

单元：注意 PL 是 16 位定点、24 位 I2S 左移 8 位，算 THD 前要先还原成同一标度。

## 5. 为什么值得做

- 波形/频谱是**答辩时最直观的东西**，评委看一眼就知道"这是真的在跑"。
- 延迟数字现在站不住：实测 RX FIFO 常驻 3960/4096 ≈ **83 ms** 的采集积压，
  而 status 里写的是 `lat_ms = 2.3`。有抓取缓冲之后才能把真实数字拿出来，
  否则被人追问会露馅。
- THD+N 是"音质"这一栏唯一能给的硬指标。
